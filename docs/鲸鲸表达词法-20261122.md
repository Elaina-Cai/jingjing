# 鲸鲸的表达词法：理解、情绪、意图怎么落到词上

这份文档回答一个反复出现的问题：**最终说出口的那句话，用什么词才能让人听出「我理解了什么、
我是什么情绪、我想做什么」**。它不讨论架构，只处理用词。

## 一、真实样本

2026-11-22 16:06，主人发来一张身份证背面照片（点名、必须回）。她说过：

> 这张是身份证背面。可你怎么把证件照直接发聊天里了？姓名、住址、号码全在上面，
> 赶紧撤回，别留在聊天记录里。

为什么这条好，可以把四件事拆开看：

| 要素 | 对应的词 | 作用 |
|---|---|---|
| 理解 | 「这张是身份证背面」 | 指认她看到了什么，不是复述内容 |
| 态度 / 情绪 | 「可你怎么把证件照直接发聊天里了？」 | 用反问表达不赞成，没有指责人格 |
| 意图 / 动作 | 「赶紧撤回，别留在聊天记录里」 | 具体、可执行、有先后 |
| 优先级 | why：「比追问他要做什么更要紧」 | 说清为什么先做这件事而不是别的 |

四拍里没有任何一个词是「情绪标签」（紧张、担心、焦虑），但读的人能听出紧张。

## 二、四类词各自怎么选

1. **指认**用「这是什么」，不用「你说了什么」。
   - 好：「这张是身份证背面」「你刚才那句是在问我能不能帮」
   - 差：复述对方原话，或把敏感信息再念一遍（身份证号、住址、电话）。
2. **态度 / 情绪**用句式和语气承载，少用形容词。
   - 好：「可你怎么就……」「这我有点在意」「你这么说我心里咯噔一下」
   - 差：「我感到很担心」「我的情绪是焦虑」。这是标签，不是说话。
3. **意图**用下一步的动作，不用打算。
   - 好：「我先问清楚再动手」「这个我现在就去查」「这拍我先收住」
   - 差：「我打算稍后可能去看看」。
4. **优先级**只在需要时才说，用一句「比……更要紧」「先……再……」。
   - 好：「比追问他要做什么更要紧」
   - 差：把三件事并列说一遍，让对方自己排。

## 三、反例

- 只报事实：「图片包含身份证信息。」——像 OCR 回执。
- 只表态：「这样不好哦。」——没有指出不好在哪、要做什么。
- 机械三段式：「我理解你觉得……我感到……我打算……」。系统提示里已经明确禁止，因为它读起来像
  模板，不像人。
- 复述敏感内容：为了显得「看懂了」把号码念一遍，恰恰是把风险扩大。

## 四、代码里对应什么

- `evaluate_experience` 的四个字段：`meaning`（理解）、`feeling_text`（情绪，只写自己）、
  `tendency`（意图，自然语言）、`next_move`（这一拍的方向：reply/clarify/act/wait/comfort）。
- `say` 的 `why` 字段承载优先级：为什么先说这句、而不是别的。16:06 那条就写在这里。
- 提示层的约束写在 `loop/brain.py::_decision_guidance`：「称呼、语气、回答重点、要不要追问、
  这一步动手还是先等，都按我对眼前这件事的理解、此刻的情绪和我真正想达成的来定」，
  并明确「不机械报成固定标签或三段式」。

## 五、当前的缺口

16:06 那条推理里，她明确想过评价：「要用 evaluate_experience……有情绪：有点紧张/担心他把
证件照往外发。**先 say 吧。**」——然后 `say` 结束这一拍，评价没有落下。

也就是说：**用词这一层已经能做到，落库这一层还没有**。要让「理解/情绪/意图」留下来并在
以后被修订，需要先决定：允许说完再记一笔，还是让 say 自己带上这四个字段。
在这之前，`cognitive_events` 里几乎没有评价记录，「随新经历修正」只发生在当拍的推理里，
不落在任何可追溯的地方。
