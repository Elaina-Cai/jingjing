# 动作队列（最小版）设计

> 状态：**设计完成，未实施** · 记录日期 2026-10-28 · 相关：`docs/多平台适配-为什么现在不做.md`、`docs/world-db.md`

## 0. 一句话

队列不是为了"排队"，是为了让**策略层 / 物理层 / 进程层**的三种丢话共用一个账，
并让"她说过什么"能被她自己看见。

---

## 1. 为什么需要（三层丢话，一层的补丁管不了另一层）

| 层 | 症状（2026-10-28 实测） | 只有什么能救 |
|---|---|---|
| 策略层 | 去重闸把"续讲"当重复拦掉（3 条） | 不该重试，只需**入队前**判 |
| 物理层 | 焦点被抢 / OCR 读错 / 打字没进框（「冒了」13ms、「耶什么」66ms、清框 3 次） | 需要**重试**，且必须串行（两个动作同时抢键鼠 = 73s） |
| 进程层 | 引擎重启/崩溃，话在内存里蒸发 | 需要**持久化** |

补充证据：回执 271 条里 14 条 `unconfirmed`；`unconfirmed` 仍被 `touch_said()` 记成"说过"，
于是她会以为"我已经回了"（P5「起床」那次就是这么静默的）。

---

## 2. 设计原则

1. **单线**：全进程只有一个线程去点微信（`desk`）。
2. **两段提交**：先落盘 `pending`，再用 CAS 抢成 `sending`，发完才 `settle`。
3. **持久化**：队列在 `data/world.db`，进程崩了不丢。
4. **可见**：面板必须能看见 pending/sending/failed/expired，否则等于没有队列。
5. **可回退**：一个环境变量回到直发。
6. **不做**：多平台、修订/替换（`rev`）、recheck、跨进程队列。

---

## 3. 数据结构（`db/world_db.py`）

```sql
create table if not exists outbound_queue (
  id          integer primary key autoincrement,
  idem_key    text not null unique,              -- group_id|seq，幂等
  group_id    text not null,                     -- 一拍 ＝ 一个事务（全成全败）
  seq         integer not null,                  -- 组内第几条
  platform    text not null default 'wechat',    -- 预留：只有 needs_desk 的通道才入队
  chat_id     text not null,                     -- 入队前必须已解析成真 id（群名会改）
  text        text not null,
  state       text not null default 'pending',   -- pending|sending|sent|failed|expired
  attempts    integer not null default 0,
  next_at     real not null default 0,           -- 下次可尝试的时间（退避）
  not_after   real not null,                     -- TTL 到点作废
  owner       text not null default '',          -- 谁在发（pid:thread），用于崩溃回收
  started_at  real not null default 0,
  ack         text not null default '',
  why         text not null default '',
  created_at  real not null
);
create index if not exists ix_q_state on outbound_queue(state, next_at);
```

方法（5 个）：

```
enqueue(group_id, chat_id, texts, *, platform="wechat", ttl_s=600) -> list[int]
claim_next(now=None, platform="wechat") -> dict | None      # CAS: where state='pending' and next_at<=now
settle(qid, *, ok, ack="", why="", backoff_s=0) -> None     # sent / failed(+next_at) 
reap_stale(stale_s=120) -> int                              # sending 超时 → pending, attempts+1
queue_stats() -> dict                                       # 各状态计数 + 最近 10 条
```

## 4. 状态机与竞态

```
        enqueue
           │
        ┌──▼──────┐   claim(CAS)   ┌─────────┐  ok   ┌──────┐
        │ pending │──────────────►│ sending │──────►│ sent │
        └──┬──────┘               └────┬────┘       └──────┘
           │ now>not_after            │ fail（可重试且 attempts<3）
      ┌────▼────┐                     ▼
      │ expired │◄──────────────  ┌────────┐
      └─────────┘   now>not_after │ failed │──► next_at 后退避，回 pending
                                 └────────┘
```

- **CAS 抢锁**：`update ... set state='sending', owner=?, started_at=? where id=? and state='pending'`，命中 0 行 = 别人抢走了。
- **崩溃回收**：`reap_stale()` 把 `sending` 超过 120 秒的重置为 `pending`，`attempts+1`（最多回收 1 次，防死循环）。
- **TTL**：`expired` 不重试，但**留账**（面板可见"这条没发出去"）。
- **退避**：`(15, 60, 180)` 秒；`attempts>=3` 直接 `failed`。

---

## 5. 两条路径

```
say()  ──判闸（白名单 / 去重 / 主动目标）──► enqueue() ──► 立刻尝试发一次（快路径）
                                                          │失败
                                                          ▼
                                              worker 线程按 next_at 重试
```

**为什么要快路径**：保持现在的时延（她说完就走，不排队等）。worker 只处理失败。

## 9. 实施顺序（不要一次全上）

1. `world_db` 表 + 方法 → 编译、跑一次 `enqueue/claim/settle` 自测（不改行为）
2. `panel` 队列块（先能看见）
3. `desk.py` + `ports.say` 双路 → 开关默认 **0**
4. 打开开关 → 观测 1 小时（重点：pending 中位等待、有没有重复发送）
5. 稳定 24 小时后，删直发分支

---

## 10. 验收标准（可测）

1. 同一条 `idem_key` 入队两次 → 只有 1 行（唯一索引）
2. 并发 `claim_next()` 10 次 → 同一 id 只被 1 个拿到
3. 杀进程后重启 → `reap_stale()` 把 `sending` 回到 `pending`，且不重复发送（`attempts>=2` 时直接 failed）
4. 一条消息失败 3 次 → `failed`，面板可见，账本有一行 `say_failed`
5. `YINYUE_QUEUE_ENABLED=0` → 行为与今天完全一致

## 11. 待拍板（2 项）

1. **TTL**：单一 600 秒（建议）／按语义分档（回应 60s、主动 10min、群通知 30min）
2. **顺序**：全局 FIFO／**每个会话各自 FIFO**（建议）——说给 A 的话不该被 B 的积压堵住
