### C7 加固 ✅ 2026-10-31（`loop/ledger.py:165` + `loop/brain.py:239`；锁 `tests/test_said_since_c7.py` 6 条）

先说清一件事：C7 从来不是"没做"——它在 `loop/brain.py:239-245`，标题「这一拍我已经说过」，取数走 `ledger.said_since(tick_since, exclude=focus)`，`tick_since` 由 `loop/run.py:253` 每拍开一次。之前两次审计都说"没做"，是因为：① 全仓搜的是"已经说过"而不是"这一拍我已经说过"；② 它只在**同一拍里前面的窗口已经发过话**时才出现，而那两拍恰好 0 条 say，所以生产 prompt 里一次都没现身。`docs/提示词形状改造施工.md:74` 的十段清单里本来就列着它。

那天顺手拆掉它三处不该有的限制：

- **60 字截断**：原来 `str(d.get("text") or d.get("why") or "")[:60]`，长句会被截成半句——"她说过什么"读成另一句话，比不给她看更糟。现在整句。
- **`limit: int = 4`**：同一拍说了 5 句就漏。现在默认 `None` = 不限；显式传 `limit=2` 仍然有效（保留测试）。
- **`exclude=focus` 不同域**：台账里的 `target` 是 chat_id（`loop/brain.py` 的 say 回执），而 `focus` 往往是窗口名（"Elaina"），只排除一个会漏——本窗自己刚说的话会被当成"别的窗口已经说过"塞回来。现在签名多一个 `exclude_chat: str = ""`，`brain.py:240` 传 `exclude_chat=chat_id`，两个都排。

验收：`tests/test_said_since_c7.py` 6 条（240 字原样、8 句不砍、`limit` 仍可显式用、按名字+chat_id 双排、只认 `say/sent`、`brain.run_loop` 源码里有 `exclude_chat=chat_id`）；探针 `scripts/probe_c7.py` 造假台账复核：V1 user @857 / V2 user @542，本窗那句已消失，长句完整。

> **2026-10-31 深夜修订（微信群并回微信一栏）**：这一版面板原本有「微信 / 微信群 / QQ」三栏 21 个开关，但运行时只有 `wechat` / `qq` 两个平台，群聊靠 `chat_id` 区分（微信 `…@chatroom`、QQ `group:…`）。`wechat_group` 从没被传进 `channel.rules()`，于是群里「要 @ 对方 / 不发语音 / 停 1.5 秒」三条全是死配置。现在：`channel.rules(platform, chat_id)` 按 `chat_id` 判群（`is_group`），群的固有规矩写在 `_GROUP_RULES`，面板只剩 14 个可改字段，群那三条以说明行显示（不给开关）。`loop/run.py::_window_ids()` 负责把窗口名换成 `(platform, chat_id)`，cells 空或 `platform` 为空时按 `chat_id` 形态兜底。

## 5. 怎么证明"LLM 真的看到了"

不接受口头保证，只认三样东西：

1. `data/prompt/<tick>/request.json`：脱敏后的真实请求。人工核对清单：
   - `messages[0]` 是 system，含 A1…E1；
   - 日级段紧随其后；
   - 最后一条 user 以分界线开头，紧接着是待回原文；
   - 原文行里没有 `（…）` 注释。
2. `data/prompt/<tick>/parts.json`：key → 字符数，能与 `audit()` 对上。
3. `scripts/prompt_diff.py <tickA> <tickB>`：任意两次可比。
