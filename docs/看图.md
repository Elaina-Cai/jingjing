# 看图：从「只是个空框」到「看得见」

2026-10-27 修。用户问：她最新那条还是说「你那两张图我这边只看到是图，看不清里面写的什么」。

## 一句话结论

不是视觉模型不会看图，是**图晚到时没人去问模型**。

## 三层，各管一段

| 层 | 位置 | 什么时候跑 | 结果写到哪 |
|---|---|---|---|
| ① 入库即描述 | `core/ingestion/media_store.py:_prefetch_description` | 图片在**入库那一刻**就已经落盘 | `message_media.description` |
| ② 读字（OCR） | `loop/vision.py:image_text` → `data/loop/image_text.json` | 视界渲染时，没有描述就 OCR | 只进 prompt，不落库 |
| ③ 视界渲染 | `loop/snapshot.py:_text_of` | 每一拍 | `[图片: 描述]` / `[图片]「OCR」` / `[图片]` |

## 坏在哪

1. **晚到的图（微信几秒后才写文件）走的是另一条路**：`resolve_pending` →
   `backfill_media_from_account`，那条路只补 `mime/size/md5/local_path`，
   **从来不问描述** → `description` 一直是 NULL。10-24 之后 1231 张 image 里只有 686 张有描述，且都停在 10-24。
2. 剩下只有 OCR。而 OCR 读的是截图上的界面字（"首页 推荐 关注"），
   再加上视界里 `[:CELL_CHARS + 16]` 的截断，她拿到的就是**半句噪声**。
3. 补描述时还踩到一个坑：思考型模型（deepseek-flash）把推理写满 `max_tokens`，
   `text` 为空 → `_clean_brief` 从 reasoning 里取到了**任务书原文**
   （"目标：用一句话（30字以内）概括…"），差点把任务书当图的内容写进库。

## 改了什么

- `core/ingestion/media_store.py` 新增 `describe_missing_media(engine, limit=6)`：
  只挑「resolved + 有 local_path + 没有 description」的图，问一次视觉模型，写回该行。
- `scheduler/main.py`：`backfill_media_from_account(...)` 之后顺手 `describe_missing_media(limit=4)`。
- `core/conversation/media.py`：视觉调用 `max_tokens` 600→1200；`_clean_brief` 增加"复述任务"过滤（`目标 / 用户想要 / 30字以内 / 禁止项 / 要求 / 注意 / 步骤 …`），并改成**取最后一行结论**（思考稿的结论在末尾）。
- `loop/snapshot.py`：`[图片]「OCR」` 的截断从 `CELL_CHARS+16` 放宽到 `CELL_CHARS+120`；描述若像任务书（含"30字以内/禁止项/目标："）一律不采信、退回 OCR；`quote_image` 也走图片分支。

## 实测

`describe_missing_media(engine, limit=4)` → `{'rows': 4, 'described': 4, 'failed': 0}`，两张关键图现在写的是：

- `手机短视频界面显示两张百元人民币，下方有"全屏观看"和卡券图标。`
- `米白编织物上四个红色脚印状血迹，配文"@你咋这样""#拼豆挑战"。`

视界里渲染成 `[图片: …]`，不再是 `[图片]`。

## 还没做的

- 库里的历史图（10-24 之前那批有描述，10-24 之后缺的）只能按批补：调度器每轮最多 4 张，72 小时窗口。要一次性补齐可跑 `describe_missing_media(limit=N)`。
- 引用里的图（`[引用 P6: [图片]]`）目前只显示 `[图片]`，没接描述。

## 2026-10-27 补：唤醒行也带描述 + 历史图批量补

- 描述来自 `media_descriptions(db)`（同一库 `message_media.description`，按文件名小写对齐），`_descs()` 做 **30 秒缓存**，每拍最多查一次库；

### 2026-10-27 补二：引用里的图也带描述

`loop/ports.py` 新增 `_quote_text()`：`[引用 P6: [图片]]` → `[引用 P6: [图片: 两张百元人民币平铺着…]]`。

关键发现：微信把**被引用那张图的 `media_path` 存在引用行自己身上**，
所以不用去库里找原消息，直接拿这一行的 `media_path` 换描述即可；
`_SELECT` 里顺手补了 `coalesce(quote_reply_id,'') as quote_id`（以后要回溯原消息也有 id 了）。

实测（`sense_sync`，48 小时窗口）：

```
2026-10-27 00:01:47 [引用 P6: [图片: 两张百元人民币平铺着，印有"100"字样，周围有社交软件点赞图标。]] / 拼这个不是很有意思吗
2026-10-26 18:58:46 [引用 P6: [图片: 手机课表界面显示第16周，列有大学物理、大学体育等课程。]] / 创新创业不去？
```

补二落地时的两个坑：

1. **只改 `ports.py` 不够**：视界走的是 `loop/snapshot.py:_text_of` 自己的渲染，要在
   `_text_of` 里也调 `_with_quoted_image()`，否则「这一拍为什么醒」里有描述、她眼里还是 `[图片]`。
2. **描述会把正文挤掉**：`CELL_CHARS=200` 是整行预算，一条 100 字的描述能吃掉一半，
   让她看不到对方真正问的那句（`/ 这个图里是什么` 被截没了）。所以引用里的描述只留 **40 字**。

## 2026-10-27 追加：摘要 + OCR 一起给（`[图片: 摘要｜原文：…]`）

**为什么**：摘要说得清"画面是什么"，但常常丢掉里面的硬信息 —— 车牌、门牌、金额、课表时间、编号。
她以前要么只拿到摘要（读到"打车界面"却不知道车牌），要么只拿到 OCR（满屏界面噪声）。

**怎么拼**：`loop/snapshot.py:_text_of()` 在"有摘要"的分支里再调一次 `vision.image_text()`
（有缓存，`data/loop/image_text.json`），经 `_ocr_gist()` 过滤后拼成：

```
[图片: 打车界面显示司机正赶来，车牌粤KD37998·白，一口价2.5元。｜原文：799米2分钟 G325 粤KD37998·白 比亚迪e2]
```

`_ocr_gist()` 的规则（宁缺毋滥）：
- 只留含 **三连数字** 或 `时:分` 的片段：`9516`、`粤KD37998`、`10:45`、`139%`；
- 长度 < 4 且不含 `: / % / ¥` 的孤立小数字丢掉（`211`、`140` 这种）；
- 纯英文字母缩写丢掉（`INEW`）；
- 界面噪声词（首页 / 推荐 / 关注 / 点赞 / 全屏观看 …）丢掉；
- 最多四段、合计 40 字。

**配额**：`vision.MAX_NEW_PER_BUILD = 3`，每拍最多新读 3 张、其余走缓存；读不到就退回只有摘要。

**引用里的图只留 40 字**：`CELL_CHARS = 200` 是整行预算，摘要太大会把对方真正问的那句挤掉
（实例：`[引用 Elaina: [图片: 一张动漫风格的插图…]] / 这个图里是什么`）。
`snapshot._with_quoted_image()` 与 `ports._quote_text()` 两处都按 40 字截。

**已经被污染的描述**：早期把"任务书"（`目标：用一句话（30字以内）概括…`）写进了库，
`_BAD_DESC` 里命中即不采信、退回 OCR；库里 3 条（id 2909 / 3701 / 3705）已清空重问。
