# 目标与蓝图

> 这份文档只回答三件事：**为什么做**、**做到什么算成**、**现在离它有多远**。
> 它不写实现细节（那是 `docs/decisions/`），也不列代码清单（那是自动生成的 `docs/现状地图.md`）。
> 落地路线见 `docs/重构总纲.md`；索引见 `docs/README.md`。
>
> 三条维护纪律：
> 1. **全项目只有这份文档允许写「目标状态」**；`docs/decisions/` 只写「现在是什么」。
> 2. 每个目标必须带**可测口径**。测不了就写 `未测`，不许用形容词代替数字。
> 3. 每条结论都要能指回代码或文档（`路径:行号` / `文档 §节`）。指不回去的，删掉。

## 0. 一句话

鲸鲸是一个常驻微信群与私聊的 AI 陪伴体：**看见当下这一屏对话，记得住人和事，像人一样决定「接不接、对谁说、说什么」，说出去的每句话都能追回原文，判不出来就不说。**

三个否定，划清边界（都有本项目实测依据，不是口味）：

| 它不是 | 依据 |
|---|---|
| **不是客服**（默认回答） | 50 条人工盲标里 **38 条「不该接」、12 条「该接」**（`docs/decisions/受话标注集_50条.md`）。默认动作是沉默，不是回答。 |
| **不是知识库**（默认检索） | 检索是一个**动作**（`search_memory`），不是一层索引；查不到就弃权，不拿「最像的」顶替（`docs/decisions/记忆立方体.md`）。 |
| **不是分类器**（默认归类） | 「写时归类」路线已判停：题型通道 place 净负、num/term 未过门；`gap` 分类字段已在契约 v0.6 撤回（`docs/decisions/判投记_契约.md` §变更记录）。 |

## 1. 服务对象与场景

| 场景 | 谁在说话 | 她要做的 | 她不该做的 |
|---|---|---|---|
| **主群**（多人、快节奏） | 几十号人，同一时刻多条 | 判断这一句是不是冲她、要不要接、接谁的话；接的时候通常不 `@` | 逐条回应；把群当问答频道；抢在别人正互相说话时插话 |
| **私聊**（一对一、慢） | 主人 | 连续、不重复问、记住上次说的事 | 把群里的语气搬过来；把「没查到」说成「我记得」 |
| **被点名**（`@` / 引用 / 拍一拍） | 任意人 | 必须回，但仍要判断回什么、要不要 `@` | 只因为被叫到就把知道的全倒出来 |

`@` 的习惯是**反直觉**的：受话标注里主人的原话是「不是每次都要 @ 人的……只有专门涉及某个人的时候才会 @ 那个人」。所以「缺 `@` 就按唤醒者补」是反的，正确方向是**没有依据就不补**（开关 `ADDRESSEE_FACT_ONLY`，`core/speech/outbound.py`）。

| # | 目标（行为） | 可测口径 | 现状 | 依据 / 锚点 |
|---|---|---|---|---|
| **G1** | **该沉默时沉默** | 在「未点名、无义务」的回合里开口的比例；对照集用 50 条标注中「不该接」的 38 条 | 未测 | `受话标注集_50条.md`；开口/沉默判定在 `判投记.md` §5 五问 |
| **G2** | **对谁说对** | `target` 命中率（对 50 条标注的「该回谁」） | 未测 | `判投记_契约.md` §输出字段；`docs/现状地图.md` §8（`inferred_target` 无实现） |
| **G3** | **每句可追溯** | `basis` 指回原文的比例 ≥ **90%** | 未测 | `判投记_契约.md` §量具；留痕条是骨架：表 / 迁移 / 写入点都在，生产 0 行（`docs/重构进度.md:59` 板 8 是现口径） |
| **G4** | **不编造** | 无据断言率 = **0**；弃权率落在 **5%–15%** | 部分（有设计、无读数） | `判投记.md` §6 弃权；`判投记_契约.md` §量具 |

| **G6** | **可重建** | 同一个窗口后缀重放两次，渲染结果**逐字节一致** | 已实现 | `世界窗口.md`；`core/context/chat_window.py:30-33`（40 条 / 7 天 / 3600 字） |
| **G7** | **只追加** | 账本旧行不可改；撤回/编辑/删除都是**追加事件**；全仓只有一处能写账本 | 已实现（有测试守卫） | `账本·事件流.md`；写入口 `core/terminal/event_store_db.py:607`；守卫 `tests/test_event_chain_links.py:969` |
| **G8** | **跨天一致** | 同一人/同一事，在 24h 与 7d 两个时点问，回答不矛盾（人工对照集，n≥20） | 未测 | `自我立方体.md` v0.6（事件清单 + 可核对事实）；`记忆立方体.md` |
| **G9** | **反应有记忆痕迹** | 同一触发重复 3 次后，行为（开口/语气/称呼）出现可测变化 | 未测 | `自我立方体.md` §4.6.2（读数算法）；`态度层_存储与读取.md` |

**为什么要这九条而不是别的**：G1–G4 决定「像不像人」，G5 决定「会不会失控」，G6–G7 决定「出错能不能查」，G8–G9 决定「她是不是真的记得」。少任何一组，另外两组都会退化成玩具或灾难。

## 3. 三条不可让渡（红线）

| # | 红线 | 为什么是红线 | 代码锚点 |
|---|---|---|---|
| **R1** | **唯一真相**：账本 append-only，全仓只有一处能写 | 只要有两处能写，历史就不再可信；不可信的历史不能当证据，只能当日志 | `core/terminal/event_store_db.py:607`；守卫 `tests/test_event_chain_links.py:969`（唯一允许 `insert(TerminalEvent)` 的文件） |
| **R2** | **唯一模型点**：每回合只有「判」用模型 | 多一个模型点就多一个不可测变量；本项目的量具全挂在判的产物上 | `core/routing/turn_pipeline.py:755`（回合入口）；`判投记.md` |
| **R3** | **唯一对外口**：出口只执行、不改写；重复发送率 = 0 | 出口一旦会改写，就没人能回答「这句话是模型说的还是模板说的」 | `出口.md`；旧路径 `core/speech/rhythm.py:146`（多气泡拆分器）；真正的收口点 `core/speech/outbound.py:1831` `send_text`（5 个调用点见 `出口.md` §5.5） |

三条红线的共同点：**它们保护的不是性能，是「能不能查出错」**。本项目没有编译器和测试当裁判（这是它和 Claude Code 类工具的根本差别），所以只能靠「唯一入口 + 可回指 + 硬预算」替代裁判。

## 4. 蓝图：一个循环 · 三面读 · 一写 · 一出 · 一留痕

```
【写】唯一写入口，append-only，失败也留痕
外部世界（微信 / QQ / 网页 / 文件） ──① 落屏──▶ 账本 · 事件流（唯一真相）

【读】三种视图，全部从账本派生，全部只读、不写回
账本 ──后缀 40 条 / 3600 字──▶ 世界窗口（纯函数，可重建，不持久化）
账本 ──按词 / 意思翻（是动作）──▶ 记忆立方体（原文投影 · 索引 · 常驻 · 候选）
账本 ──人设版本 / 事件 / 事实──▶ 自我立方体（铭牌 · 态度 · 情绪）

【判】全项目唯一有模型的地方
世界窗口 + 记忆（按需）+ 自我 ──读──▶ 判 / 投 / 记
  判 ──▶ decision（respond / ask / silent / abstain）+ deliver + basis
  投 ──▶ 出口（只执行、不改写）──▶ 软件 · 适配器 ──▶ 平台 ──回执──▶ 账本
  记 ──▶ 留痕（判决行每回合一行）+ 写回（事件 / 事实，每回合 ≤1）+ 未结事
  用 ──▶ 工具包（≤2 次；「失败」与「没查到」必须分开）
```

### 4.1 一次回合的九步

| # | 谁做 | 做什么 | 产物 | 失败会怎样 |
|---|---|---|---|---|
| 1 | 感知层 | 把平台回调变成事件行（归一格式、算幂等键、失败留痕） | 账本新行 | 该条丢失但留下 `event_gap`/失败行，不静默 |
| 2 | 世界窗口 | 取账本后缀（40 条 / 7 天 / 3600 字顶格）渲染成「这一屏」 | 只读文本 | 渲染失败退化为纯文本，不阻塞 |
| 3 | 判 | 读三面（世界 / 记忆按需 / 自我） | — | 任一面缺，按「缺读数」处理，不猜 |
| 4 | 判 | 需要外部信息时调工具（工具调用即「缺口声明」） | 工具结果（≤2 次） | 失败要区分「没查到」与「查不到」，不许混 |
| 5 | 判 | 一次调用产出：`decision`（respond/ask/silent/abstain）+ `deliver` + `basis`（+ 条件字段 `reading`/`open_loop`/`memory`） | 结构体 | 缺 `basis` 或 `deliver` 与 `decision` 不一致 ⇒ 视为未完成，不投递 |
| 6 | 出口 | 校验（kind 已注册、target 存在、限流、dry-run 白名单）→ 调 adapter → 收 `client_msg_id` | 回执 | 失败回原因；只 `blocked/partial/retryable` 回给判，重试 ≤1 |
| 7 | 适配器 | 一次投递 = 一次平台调用；拿不到回执 = `sent_unconfirmed` | 平台侧结果 | 不回退成「重发」，只标记未确认 |
| 8 | 判 | 记：写回（`self_event`/`self_fact`，每回合 ≤1）+ 未结事（自然语言 + 到期） | 账本旁注 | 写回失败不影响已投递的内容 |
| 9 | 判 | 留痕：判决行**每回合一行**；完整留痕只在她开口/动手的回合写 | `turn_trace`（设计中） | 缺留痕 ⇒ 该回合不可复查，但不阻断 |

### 4.2 六条数据不变量

| 不变量 | 含义 | 锚点 |
|---|---|---|
| **I1 只追加** | 账本没有 UPDATE/DELETE 语义；修订 = 追加 | `账本·事件流.md`；`event_store_db.py:607` |
| **I2 可定位** | 每一行都能回到原文与位置（含附件正文的字符偏移） | `感知层.md` §字段表；`世界窗口.md` |
| **I3 可重建** | 窗口是账本后缀的**纯函数**，不持久化 | `世界窗口.md`；`core/context/chat_window.py:30-33` |
| **I4 有界** | 每回合模型 ≤2、工具 ≤2、记忆 ≤400 token、重试 ≤1 | `判投记_契约.md`；`记忆立方体.md` §11 |
| **I5 可弃权** | 判不出来就弃权（5%–15%），弃权不是失败 | `判投记.md` §6 |
| **I6 不双写** | 判不直接写账本，只产「事件/事实」，由代码校验后追加 | `自我立方体.md` §4.6.3；`判投记_契约.md` §记 |

## 6. 演进阶段（E0–E4）与退出判据

> 阶段划分的标准是**「哪一个读数现在没有」**，不是「哪个模块先写」。每一阶段的退出判据都必须能在仓库里跑出来。

| 阶段 | 只做一件事 | 退出判据（可测） | 主要风险 |
|---|---|---|---|
| **E0 观测** | 把三个读数打出来（shadow，不改行为）：开口率、弃权率、`basis` 指回率 | 连续 7 天，每天这三个数都有值（≥1 条/天）；口径写进 `docs/decisions/` | 读数口径本身错，后面全白做 |
| **E1 判的三必填落地** | `decision/deliver/basis` 写入 `turn_trace`；判决行每回合一行、完整留痕只在她开口/动手时写 | 人工抽 50 条：`basis` 指回原文 ≥ **90%**；弃权率落在 **5%–15%**；沉默回合留痕 = **0 行** | 留痕变成「为了交差而写」的噪声 |
| **E2 出口契约** | `deliver → Receipt`，加 `client_msg_id` 幂等与 dry-run 记账 | 重复发送 **0**；无回执率 **0**（每条都有 `client_msg_id` 或明确 `sent_unconfirmed`） | 平台回执不可靠导致「不敢发」 |
| **E3 跨天一致** | 记忆原文板 + 自我事件清单可读；候选转正三扇门 | 对照集 n≥20：24h 与 7d 两次问法不矛盾的比例 ≥ **80%** | 事件清单膨胀，读数变成流水账 |
| **E4 人味** | 风格样本 + 改写点清单（只在她开口的回合） | 盲评 n≥50：判「像人」≥ **60%**，且信息量不低于基线 | 为了像人而丢掉信息（已有实测：硬形态约束会连信息一起砍） |

**阶段之间的硬约束**：E1 没出数之前不许做 E4（否则改的是风格，量的是噪声）；E2 没达成之前不许开任何新的对外 `kind`（否则重复发送无法归因）。

## 7. 明确不做（每条都带理由与证据）

| 不做 | 理由 | 证据 |
|---|---|---|
| **知识图谱 / 本体** | 没有真值可校准；关系边料量极小，「真关系题全对」是因为原文里就有答案 | `docs/decisions/记忆立方体.md`；关系/实体类判读记录 |
| **写时分类标签** | 归类错误不可逆，且会被下游当事实用 | 2026-09-22 群聊事故（「看个牛，影不影响」被当主人事实） |
| **数值化情绪（valence 打分 + 半衰期）** | 没有真值；上限 + 日限 + 衰减 ⇒ 数学上不可能有长期情绪 | `自我立方体.md` v0.6 §4.6（三条根本问题） |
| **`gap` / 任务类型 / 缺口类别字段** | 换一个没见过的命令就要改代码，等于把开放世界塞进闭集 | `判投记_契约.md` v0.6 变更记录（已撤回） |
| **模型改写出稿、润色、复读替换** | 出口只执行不改写；改写会让「这句话是谁说的」无法回答 | `出口.md`；「嗯，这个我刚说过啦」事故 |
| **每回合强制四段输出** | 沉默回合也产四段 = 逼模型编造；已改为三必填 + 三条件 | `判投记_契约.md` §2 |
| **把全量上下文塞进 prompt** | 窗口 3600 字顶格是设计选择（7 天原文 3% 存活率是实测代价，不是 bug） | `core/context/chat_window.py:30-33`；`世界窗口.md` |
| **每回合新增 LLM 调用** | 成本与延迟不可控，且会让量具失去单一模型点 | `判投记_契约.md` §有界 |
