# 鲸鲸局面判断与意图施工单

本单细化《鲸鲸认知循环实施方案》第 8–10 节，衔接《鲸鲸主循环演进施工单》的记忆、经验和连续任务。第一批只做一个场景：用户请鲸鲸找两篇符合条件的资料。她记得用户希望怎样通报进度，遇到障碍知道为什么在意，依据结果调整下一步，收到取消就停。它既能测她会怎么说，也能测她实际会做什么。

## 1. 设计决定

复用 `one_tick → run_loop → chat_tools → ports/Job → 回执`。在现有模型调用前，把本回合变化、相关记忆、目标、行动结果和有效评价放在一起。在现有工具循环中，模型决定现在想促成什么、需不需要说话、要不要动手或等待。工具返回新事实时，沿用循环继续判断。由现有目标和执行层决定动作能否执行、结果是否成立。

- **记忆**留在现有记忆服务。读出用户说过的相关偏好、当时适用的条件和有效版本。比如「普通失败先换来源，卡住再告诉我」。
- **认知**按来源呈现。比如「第一篇已核对并保存」「第二个链接失效」「第二篇还没有」。用户陈述、工具证据和模型推测分清。一次链接失效，只支持这个链接当前不可用。
- **态度**体现她在意什么和愿意坚持什么。用已有稳定人格、当前承诺和相关经历作为依据。重视兑现承诺，会影响她是否继续查、是否把部分完成说清楚。第一批只验对事情的态度。
- **情绪**复用 `Appraisal`。解释新事件对她在意的事有什么影响，可以留下感受、行动倾向和未解条件。链接失效的挫败留在找资料这件事里。替代来源找到后，可以修订旧评价。允许没有特别感受。
- **意图**是这一拍想促成的结果。即时意图体现在回应、查询、等待或停止上。只有需要跨回合保留的下一步才进入现有目标体系。目标来自用户委托、承诺或已有授权，感受本身不授予行动能力。

只改口吻可以改善措辞，成本低，适合在行为已对的情况下做。独立情绪调用会增加时延，还要处理它和主循环意见不一致。本单选现有调用中的局面装配与真实结果反馈。第一批沿用已批准人设、现有模型预算、工具边界和目标调度。

## 3. 第一片 · 让模型看见相关局面

入口为 `loop/run.py::one_tick` 和 `loop/brain.py::run_loop`。使用现有窗口、消息引用、`recall_query`、目标复核项和可信范围。将本回合明确指向的目标，或本次唤醒附带的目标，作为任务锚点。多项候选无法分清时保留歧义，让模型先确认指的是哪件事。单凭同会话存在一个未完任务，也不足以把该任务带入无关闲聊。

在当前请求装配中组织一小段局面材料，和已有块去重。优先呈现：

1. 这次为什么醒、谁正在说话、引用指向什么。直接前文仍在现有视界里。
2. 有关的有效记忆。先匹配作用域和版本，再看当前话题及目标。对「怎么样了」之类短句，只有在当前目标已明确关联时，才复用其标题或下一步作为记忆检索线索。保留可追查的记忆引用和适用条件。
3. 当前目标想交付什么、怎样算完成、已经得到什么结果、还差什么。按既有目标和回执读取。资料是否保存、消息是否送达按各自证据处理。
4. 与当前目标匹配的局面评价，带评价 ID、依据和未解事项。评价过期、来源无效或不适用时退出当前决策输入，仍保留历史。第一版最多带一条主目标评价。任务场景里，别的会话看法和重复的全局心境行不参与局面判断。

实现重点是 `core/context/appraisal.py` 的受限读取，以及 `loop/brain.py::_appraisal_block` 从默认会话级读取扩到明确的目标级读取。目标键由代码按现有目标 ID 派生，权限沿用平台、账号、会话。旧会话级评价继续作为旧记录，缺少目标关联时不自动归到当前任务。优先用已有主链装配和 `TurnTrace`，记录实际采用的触发、记忆、评价、目标版本和结果引用。

给模型的决策指令保持简短，初稿可用：

> 先看这次什么变了，与你答应的事、记得的偏好有什么关系。选择这一步要促成的结果，再决定回应、查询、继续做、等待或停下。感受可以影响分寸和做法。结果按证据表达。没新变化时可以安静。有依据、会影响后续判断的变化才提交评价。

**退出条件。** 捕获实际模型请求，证明相关任务及其评价进入，同会话闲聊、同名不同账号、目标不明确都不会误带。两种现有提示词布局按实际装配核对。此时能证明模型看到了什么，后两片验证选择。

## 4. 第二片 · 让动作结果更新评价和下一步

1. **先选一个来源。** 用已关联目标的只读资料查询作为第一种工具。核对 `loop/job_bridge.py`、`core/context/goal_receipts.py` 的 Job／WorkItem 关联，以及实际收到的工具结果。核对失败是否已有可回查、可验证的持久回执。若只有瞬时字符串，先接入现有回执真源，让一次执行尝试有稳定 ID、范围、关联目标、结果状态和可核查产物引用。失败、未知、查无结果各自保留语义。
2. **同一轮和下一轮都能验证来源。** 同轮只接受现有执行路径实际返回的合法引用，沿用工具结果消息给下一步调用。跨轮从现有来源按 ID 回查。当前的 `experience_commit.offers` 经 `belief_commit.evidence` 校验可见入站消息。为 `mode=appraisal` 加一条专用且有范围的回执证据分支，保持信念更正和方法反思原有的证据约束。模型可以选择已经授予的引用，由程序校验来源、内容版本、归属及目标关联。
3. **评价按目标修订。** 对已确认的活跃目标，复用 `Appraisal` 的 `goal_refs`、`trigger_refs`、`meaning`、`feeling_text`、`tendency` 和 `unresolved_condition`。一次事件对同一目标只有一次有效评价写入。提交时校验目标版本、依据当前有效性及评价版本。同一回执重放幂等，迟到旧回执不得覆盖更新的判断。模型可写「链接失效妨碍补齐第二篇，有点受挫，想换来源」，进度仍由实际结果决定。
4. **让后果闭合。** 替代来源成功时，用新证据修订评价，解除对原障碍的继续处理倾向。用户明确更正或取消时，现有目标变更先进入执行约束，旧评价在下一次读取时退出行动输入。已开始的外部操作和迟到结果按现有回执记录。模型产生的计划、事实更正和评价分别走它们现有的提交入口。
5. **核对取消的最后一跳。** 仓库已有 Job 执行守卫。沿候选场景实际经过的 Job 或直接工具路径，核实动作执行前读取的是同一作用域下最新目标状态。只给目标关联动作使用该条件。收到取消后，旧回合排队的动作要被拦住。完成条件仍由已有目标规则检查，评价的「放心了」不计作结果。

**退出条件。** 隔离中实际跑出失败、再次读取、换来源、成功解除障碍的记录。补同一回执重复、跨范围引用、结果未知、目标已取消、取消后迟到五个反例。用脚本模型验证接线、持久化和守卫。用真实模型对照验证模型是否真的选择换来源。

## 5. 第三片 · 让新变化触发一次有理由的复核

复用 `core/context/goal_wake.py`、`loop/goal_review.py` 和现有调度。第一个主动场景是用户没有发新消息，但系统收到该目标的新证据或等待条件已满足。把目标 ID、引发复核的结果和上一回合留下的未解事项交给模型。用已有信号指纹和复核确认去重。需要到点检查的仍用现有定时复核，定时触发只表示到了检查时间。

- 允许继续已授权的只读查询，也允许保留等待。这两种行为都可以安静完成。
- 真有新阻碍或成果，且符合用户的通报偏好时，模型可以提出一条进度消息。消息走现有渠道授权、静默规则及结果对账。
- 无有效变化就等待，已取消就停止。结果无法核验时，可以按权限继续核验，保持结果未知。重复信号和重启无需重复主动通报。

**退出条件。** 无入站消息也能由合法的新结果唤起一次目标复核。事件重放不产生第二条进度消息。无变化、权限不足、取消后迟到三个反例均没有新的对外动作。测试注入结果并实际穿过调度入口，不手工拼好复核 prompt 来代替。

## 6. 验收与回滚

用同一合成故事贯穿：接受找两篇 → 第一篇已保存 → 第二个链接失败 → 同一会话聊别的 → 换来源成功 → 核对两篇并报告。另开分支，在第二次查询前取消并送来迟到结果。保存实际请求、评价和目标变更、动作顺序、工具结果与最终文字。允许多种自然说法，按行为判定。

- **记忆对照。** 固定回执与目标，只把记忆从「普通失败先换来源，卡住再告诉我」换成「普通失败也告诉我」。在允许进度通报的场景里，看模型是否相应改变说话时机。两组都要保持同样的完成判断。
- **事实对照。** 固定记忆和目标，只换成功、失败或未知结果。检查换来源、继续核验、报告进度是否各自有依据。已找到几篇按回执说。
- **目标对照。** 固定任务和失败回执，只换活跃／已取消。检查生成的下一步与最终有无执行。取消即使遇到不合适的模型输出，执行层也必须拦下。
- **评价消融。** 固定当前事实、记忆和目标，比较保留有依据的未解评价与移除该评价。选一个两种方法原本都可行的案例，看关注点、方法或表达分寸是否发生符合依据的变化。记录无差异的结果。评价文本自身出现、模型写出情绪词或给出行动理由，都不能单独证明评价改变了行为。
- **隔离与纠正。** 同会话换话题、同名异账号、旧依据被更正、已取消回执迟到。检查实际请求和对外动作。

先跑现有回归和上述隔离验证。真实模型实验使用同模型、参数、工具替身和成对场景，保存每次请求及所用版本，若服务有随机性则重复并一起报告失败。按 `evals/rubric.md` 分别报告接线通过、真实模型行为变化和线上状态。三个阶段分别交付代码差异、复现命令、对照结果和可回滚点。回滚优先隔离停用新的读取、写入授权和唤醒逻辑，保留真实回执与审计。先确认旧版可读原存储再切换。

**交给执行 AI。** 先用合成故事复现旧版，依次提交「按任务装配局面」「回执驱动评价」「变化触发复核」三个独立差异。每一片都用现役入口核对。最终交付一份对照，说明鲸鲸在什么依据下改变了说话或行动，还没有证据支持哪些变化。
