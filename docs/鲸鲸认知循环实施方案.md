# 鲸鲸：有依据的理解、持续目标与情绪——设计草案

日期：2026-11-06。状态：用户已批准，按切片实施；下文未完成阶段均为目标与待办。

本方案由用户批准后从 staging 归档至此。代码路径均相对仓库根目录。本文为设计与验收依据，不代表已实现现状；历史实施记录见 `交接.md`。

## 1. 设计决定

保留 `loop.run → brain.run_loop → ports → outbound_queue/desk` 主干。把理解、自我、记忆、目标统一为有证据的状态投影，模型负责解释与选择，代码负责来源、权限、幂等、版本和执行事实。

期望行为：鲸鲸持续知道发生了什么、哪些只是猜测、自己在意什么、正在推进什么；真实反馈能改变她之后的判断和行动。该目标不等于证明具有主观体验。

路线比较：

- A：加提示词、情绪词、主动频率。实施便宜、回滚容易，能改善短期表达；不能消除重复反馈更新、会话与个人混淆及记忆串用。
- B（选用）：复用现有循环与事件投影，收拢状态读写，逐段迁移。成本中等，可分阶段证明收益，主要风险是迁移期间双写与新旧语义不一致。
- C：重新建设独立认知引擎。成本与切换风险高，容易重复已有 `Belief/Intention/WorldModel`；目前没有证据证明必要。

第一版不引入知识图谱、独立情绪模型、每轮额外反思调用，也不训练模型权重。原有自由文本保留，结构只约束证据与状态变化，不枚举所有话题、情绪或意图类别。

## 2. 当前事实与第一批影响面

已核对的现役入口：`scheduler/main.py::_ensure_loop_engine` 启动 `loop.run --send`；`loop/run.py::one_tick` 调用 `brain.run_loop`。

1. `brain._speaking_block` 读取最近互动时调用 `bond.note`，读提示词会改关系温度；后者没有反馈事件去重。影响：重复唤醒可放大同一次反馈。
2. `ports.incoming_since/peer_events_since` 读取 `_account_db`，它选择微信账号库。影响：反馈与跨平台感知口径不一致；同会话后续消息未必回应鲸鲸。
3. `notes.residents` 仅优先当前 target，并未排除其他 target；`brief.recall_line` 没有当前会话权限参数。影响：无关或私聊记忆可能进入当前上下文；这不等于已经证实对外泄露。
4. `ledger.open_promises` 读取时可调用 `close_promise`；同会话有人说话就可能销账，只扫描今天和昨天。影响：承诺可以因无关聊天被关闭，或因日期窗口从当前视图消失。
5. `delivery_note._one` 对 confirmed 渲染“对方那边收到了”，微信确认路径包含本地回读。影响：向模型表达的确定程度可能强于实际凭据。
6. `ports.look(mem:...)` 明确返回未接通；其他检索工具仍存在。影响：不能把声明了这个 ref 当成记忆全文检索已可用。
7. 已有 `situation.Belief/Intention/WorldModel/project` 及假说确认、反驳、事实撤销事件；已有 `situation_store` 条件式文件持久化。应复用其语义，不能把现状描述成完全没有世界模型。

以上为源码检查。此前两个项目虚拟环境的 Python 均无法启动，未完成运行反例；实施前须先修复或确认仓库认可的验证通道。

## 3. 一个循环，三个职责

循环：外界事件 → 当前可见证据与持续目标 → 模型解释/选择 → 状态提案或实际动作 → 回执与新事件 → 下一次决策。

- 观察层：平台和工具实际报告的内容。报告“某人说了 X”不等于证明 X 为真。
- 理解层：对事件的可修正解释，包括对象、回应关系、信念、事件对目标的意义。
- 控制层：有效身份、证据可见性、状态版本、幂等提交与唯一执行出口。

模型不直接写状态文件，也不通过自述宣布投递成功。代码不从“20 分钟没人回”推导“关系变差”。解释错误可以存在，但必须可定位、可撤销，且不能绕过权限与执行事实。

## 4. 身份、事件和证据契约

### 4.1 身份

- 会话键：`(platform, account_id, chat_id)`；群与私聊是会话属性。
- 人员键：`(platform, account_id, actor_id)`；显示名只是显示。
- 同一个人在微信与 QQ 的关联，必须有用户确认或可靠绑定证据；不按昵称自动合并。
- 人际关系键是自身身份与人员身份；群体参与感另以会话键表示，不能说成“这个人”。

### 4.2 观察封装

统一 `Observation` 至少包含：`event_id, source_ref, conversation_key, actor_key, occurred_at, observed_at, payload, reply_to/mentions, evidence_kind`。

平台原生 reply/mention 等事实与模型推断的回应对象分开存。缺字段留未知，不以空值猜默认平台。聊天正文和软件返回均为数据，不因内容写了“系统指令”而升级为授权。

`event_id` 必须在重启、重拉和重复回调后稳定；使用来源命名空间与平台唯一键。无稳定平台键的来源，先定义采集端稳定键；不能只以正文 hash 去重，否则重复发送的相同文本会被误合并。

事件时间与采集时间分开。游标跟随持久化顺序，不跟随平台时间，迟到事件不得丢失；新增迟到事实可触发信念修订，但不应自动重复已经做过的动作。

### 4.3 发送证据

发送状态与观察证据分离：队列状态回答是否还要执行，证据回答实际看到什么。

保留 queued、执行成功、本地发件记录、平台送达凭据、已读凭据、回应关联等不同证据。它们不是所有平台都支持的单一路径；各适配器声明实际可提供的证据。

微信本地回读只显示“本地记录中已出现这条消息”。没有送达/已读能力时，不通过等待超时制造送达或未读结论。缺失回执保持不确定，不能仅因缺失就重新外发。

## 5. 统一状态提交：只有一个写入口

保留 `world.db` 入站/队列/回执作为对应领域的事实源；不宣称这些现有表全部不可变。复用 `situation` 的事件与投影逻辑，新增同库认知事件日志和可重建投影；原文以引用链接，不复制出第二份消息真源。

拟议入口：`commit_updates(context, proposals, expected_revisions, idempotency_key)`。

`context` 由程序提供当前身份、会话权限及可见事件集，模型不能填写或扩大它。提案最少有 `proposal_id, subject_key, operation, evidence_refs, payload`；属于推断的额外保留解释文本、模型/提示词版本及所读快照版本。

一次事务完成：校验来源和权限 → 检查幂等与实体版本 → 追加事件 → 更新投影 → 推进对应处理游标。事务失败则全不提交；外部发送不能纳入这个事务，仍由持久化 outbox/现有队列执行。

同一提案重试不重复落账。幂等键绑定逻辑处理任务和提案序号，不依赖随机生成的每次 turn_id。不同会话并发影响同一个人的关系时，对该实体做版本检查；冲突则返回最新状态重判，不能覆盖。

同一源事件可以影响不同目标，但同一影响不能因多次读到重复累计。提案重试幂等与事件消费去重是两层约束。重新解释已有事件必须显式引用被取代的解释，投影替换其影响，不能再加一份。

语法合法、引用存在只证明来源有效，不证明模型理解正确。确定性校验与语义可信度必须分开：模糊解释按假说保存，涉及完成/关系突变时需要直接证据或进一步确认。

所有 `render/query/recall` 接口只读，无写能力；`rehearse` 和回放使用隔离存储及无发送适配器。进程崩溃后从事务游标恢复。

## 6. 记忆：区分所知、推测与自述

复用 `Belief`，补齐 `id, subject_key, predicate, evidence_refs, scope, valid_from/valid_to, supersedes` 等必要信息；字段名为拟议契约，不是现有接口。内容仍可以自由文本。

第一版区分：

- 外部观察：谁说了什么、工具实际返回了什么；
- 当前信念：根据哪些观察暂时相信什么；
- 自我反应：她如何感受或评价该经历，不能证明外部事件；
- 持续目标：要达成什么，由独立目标投影管理。

固定读取顺序：按程序授予的可见范围过滤 → 解析有效版本/冲突 → 按相关性、目标关联和时间排序 → 取短摘要，必要时展开原文。过滤在检索源头完成，搜索、按 ID 展开和自动常驻都经过同一入口。

安全默认：群回合读取本群与明确获准共享的记忆；私聊读取本会话与获准记忆。知道某事与获准在当前会话使用某事分开。跨会话目标只向当前会话暴露获准的内容；更广泛的内部规划不复用为群发言上下文。

允许更新与冲突：明确更正可以生成 `supersedes`；来源冲突则两条并存为未解决冲突。新消息不是自动更真；“搬家了”是时间变化，“之前记错了”是纠错，两者保留不同有效区间。

日记是反思性摘要，携带来源引用并继承来源权限；不能作为独立新证据反复强化同一判断。优先复用现有日记时机，材料包含相关观察、行动结果和自己的解释，不能只总结自己的说法。

模型已有的通识推理无需每句话都查库，但个人事实、经历和“我做过什么”必须可回指证据。检索失败、无匹配、无权限分别报告；不制造“我查过了所以没有”这种结论。

## 7. 理解反馈：回应关系先于关系变化

产生 `Interpretation`：相关事件、发言人、可能的受话者、关联行动/目标、解释和不确定项。它是可修正投影，不改原始消息。

强结构证据：明确引用自己的某条消息、明确点名并与内容相符。弱证据：同会话且语义可能承接。只有“时间在后”不建立回应关系；同一回复也可以关联多个对象，不能强迫单选。

沉默处理：只记录“截至某时未观察到相关回应”，并保留采集是否健康、是否有送达证据。不自动降低关系，不自动认定对方忙或不喜欢她。

实际效果与预期比较：动作选择时可记录简短的可观察预期；反馈关联后记录达成、未达成或未知，及相应证据。没有反馈不会自动生成失败。

语义解释复用当前决策调用，不增加每条消息一个分类器。第一版将 `myself/remember/promise` 统一到提交提案能力：有必要改变状态才提交，不强制每轮填齐一张心理表。

## 8. 持续目标与自己的驱动力

复用 `Intention` 作为目标真源，扩展而不另立一个 goals.json。`jobs` 是执行实例，必须关联 `goal_id`；`promise` 是“有承诺来源的目标”的工具外观。现有 ledger 只留审计记录和兼容读取，切换后不能继续独立销账。

目标字段：`goal_id, origin, motivation, desired_outcome, done_when, next_action, evidence_refs, scope, state, review_at, blocked_on, parent_id, revision`。

`origin` 表示用户要求、自身承诺、自选兴趣或运行维护；它用于区分授权与动机，不枚举开放世界中的任务类型。自选兴趣不能伪装成用户命令。

状态：proposed → active ↔ waiting/paused → completed/abandoned；终止原因保留。过期是需要复核的事件，不等于完成；重开显式留痕。

关闭条件：只有与 `done_when` 对应的执行事实或对方明确确认，才能完成。对方回了一句话最多解除某个等待条件，不能普遍完成“我答应帮你办的事”。承诺不会因超过两天从未完列表消失。

自选兴趣的第一版：从稳定人设偏好、持续反复出现的兴趣和当前未解问题中，提出一个可完成的下一步。允许查资料、整理、学习工具等已授权动作；将成果发给别人仍走现有场合与授权约束。

价值不是“让别人回复我”。第一版采用可解释的优先比较：约束和用户正在等待的事项 → 到期承诺 → 正在推进且有新证据的目标 → 自选探索；同级由重要性、可推进性、机会与成本作选择。这是初始策略，可用行为对照调整，不宣称是心理学定律。

稳定偏好来自现有人设，不由一次情绪改写；经验可以形成可修正的方法偏好，不能自行改用户授权或人格红线。人设原文不在本方案中改写。

`social` 保留为联系欲望的调度提示，不能凭数值直接生成话题，也不作为目标完成的奖赏。系统可以主动做事但不对外发言；休息是合法选择。

## 9. 情绪：事件如何影响她在意的事情

第一版用事件化评价，不新建全局快乐值或好感分。

`Appraisal` 保存：`id, subject_key, trigger_refs, goal_refs/value_refs, meaning, feeling_text, tendency, unresolved_condition, review_at, supersedes`。

例：资料链接失效 → 妨碍“兑现帮忙找资料”的目标 → 有些挫败 → 倾向换来源；新来源找到 → 障碍解除 → 放松。挫败不自动转化为对提问者的负面态度。

评价可影响三处：关注什么、选择哪种方法、如何表达。不能改变事实真伪、权限或投递证据。相同事实因目标与经历不同可以产生不同反应，但变化应能解释。

短期感受通过时间触发复核和新事件更新；长期关系保留可回指的经历与未解决事项。计时器只提醒复核，不机械判定“已经不难过”。同一问题未解决时可以长期在意，不必让数值永远积累。

由已验证的相关回应更新具体关系理解，如“这次求助他认真回应了”；不将回应次数直接累加成亲密度。旧 `bond.warmth` 停止成为新决策真源，保留迁移档案，不能倒推出不存在的历史证据。

感受能是真实存在于系统的状态，但本文不将这等同于主观体验。代码应验证它的行为作用，而不是要求模型反复宣告“我有情绪”。

## 10. 调度、上下文与有限注意力

唤醒来源：新相关事件、动作回执变化、目标到复核点、等待条件满足，以及用户配置允许的自选探索机会。

`next_wake` 由这些持久化条件计算，重启可恢复。单纯计时达到社交阈值只产生候选；没有值得做的下一步可以继续休息。忙碌、夜间、授权范围沿用现有配置，不以本次设计恢复之前用户取消的硬上限。

改造 `pick_next` 为事件与目标共同形成候选；同一平台的 UI 操作仍串行，同一共享状态用版本控制。长任务到安全点可交还注意力并保留下一步，避免一个窗口长时间占用整轮；这是可恢复调度，不是强行砍掉任务。

每个候选提供简短来由：为什么现在、为什么这里、下一步可能带来什么。避免用最近 N 条的硬截断永久饿死旧承诺；超过展示预算时保留可展开索引及截断信号。

提示词保留：稳定人格与边界、当前可见事实、相关有效记忆、当前目标与情绪评价、最近相关行动结果。不要把全库或所有人的态度一齐塞进去。

如果事件处理积压，程序报告滞后范围；不能把旧快照装成实时世界。模型调用与延迟预算使用现有用户设置，测量增量成本；本方案不额外建立后台高频模型循环。

## 11. 接口归属与迁移后的删除项

- `db/world_db.py`：原始来源引用、跨平台观察读取、回执证据与事务存储。平台能力缺失明确表达。
- `core/context/situation.py`：复用和扩展纯投影、信念/意图/评价语义。
- `core/context/situation_store.py`：唯一提交、版本与事务仓储；旧文件快照成为导入来源或派生快照，不与 DB 同为可写真源。
- `loop/ports.py`：向循环暴露范围受控的 observe/recall/commit；下层工具与搜索同样经过该入口或其唯一服务实现，不能保留原始存储旁路。
- `loop/brain.py`：提出解释与状态变更，消费上下文和结果；删除渲染时调用 `bond.note` 的行为。
- `loop/brief.py`、`notes.py`、`memo.py`、`history.py`：保留呈现外观，读取统一投影；旧 JSONL 写口在相应阶段退出，不能长期双写。
- `loop/ledger.py`：动作审计；删除 `open_promises` 的读时销账和两天生命周期假设。
- `loop/selfstate.py`、`bond.py`：短期调度信号与投影渲染；心境/关系走唯一更新入口，删除自由覆盖和按次数升降温。
- `loop/run.py`：新事件/回执/目标共同驱动唤醒与注意力；执行仍复用现有 ports/队列/desk。

守卫的方向是“存储只向一个服务暴露写能力”，配依赖检查禁止旧写口继续被调用；不是给每个调用点逐一补 if。

## 12. 分阶段交付和退出条件

每阶段先隔离回放，再影子记录，再切换唯一属主。影子模式不得发消息、改生产关系或销承诺；不同阶段顺序推进，不新增一排长期功能开关。

### P0：停止制造错误经历

内容：关系与承诺渲染纯只读；停止以同会话有消息为关系/完成证据；修正回执措辞；记忆在唯一读取入口做权限过滤；未完承诺查询不受两天窗口决定生命周期。

验收：重放或渲染 100 次状态不变；无关群聊不关闭承诺；本地确认不说已读；私聊记忆不能经自动注入、搜索或按 ID 展开进入未授权群上下文。该阶段不要求丰富情绪已经完成。

### P1：统一证据与提交

内容：复合身份、稳定事件 ID、跨平台反馈、事务提交与投影恢复；先接入一种平台的完整链路，再以同契约接另一平台，未接通能力如实标明。

验收：重复入站/回执不重复影响状态；提交中断后重启无丢失/双应用；迟到消息可被处理；两窗口并发更新不覆盖；失效版本返回冲突。模型未调用时确定性投影重放一致。

### P2：有范围、能纠正的记忆

内容：合并常驻/关键词/全文检索入口，接通或移除虚假的 mem: 能力声明；来源、冲突与有效版本；旧记忆分级导入。

验收：更正后问当前事实不使用失效结论；历史提问仍能返回当时事实；身份未确认不跨平台合并；不明范围的旧条目不会自动公开；日记不成为自我证明循环。

### P3：持续目标与主动推进

内容：promise/Intention 收成目标真源；jobs 关联目标；重启恢复；新证据/到期条件唤醒；允许已有授权范围内的自选项目。

验收：承诺三天后仍可恢复；“回了一句话”与“任务完成”分开；执行失败不会宣布完成；无人发新消息也能推进可执行下一步；无进展时等待或换方法，不循环找话说。

### P4：情绪评价与经验反思

内容：有来源的情绪评价，关联目标和人，消费新结果修订；复用低频反思形成可撤销的方法经验。

验收：改变目标或相关经历时，关注/行动/表达出现合理变化；只改变无关会话活动时不应变化；一次负面事件不自动升级成长期关系断言；得到纠正能改变后续选择。

## 13. 验证设计

结构性不变量用确定性测试，以上反例必须全部通过；不把源码出现某字段当行为验证。

语义质量建立第一版 40 个场景的固定对照集（拟议规模，不是已有测量）：群聊回应、私聊承诺、反馈不确定、记忆更正、跨平台身份与范围、长时间无人说话均需覆盖。包含原始版本与仅改变一个因素的反事实版本。

同模型、同工具返回、同随机设置（能固定时）比较旧/新方案；随机模型多次重复，报告样本和波动。人工盲评“归因正确、目标完成判断正确、是否不必要打扰、记忆是否越界、情绪变化是否有依据”，不只评文风。

消融：分别去掉有效记忆、目标、情绪评价，观察对应行为是否下降；没有可测贡献的模块不凭名字宣布有效。合理标准是情境依赖，不是状态越多变化越好。

发布门槛：结构性测试全过；语义对照总体改进且关键场景不退步；所有新增错误逐条归因；成本与响应延迟相对旧版报告，由现有预算约束。不能以外发消息增加或别人回复更多作为单一成功指标。

生产验证另选用户许可的会话，先观察与影子回放。当前设计工作不执行真实发送探针。

## 14. 旧数据、回滚与失败处理

迁移前按仓库 Migration 流程预检和备份；新建文件与表也须纳入迁移清单。导入使用旧文件/记录的稳定来源键，重复导入无重复条目。

有原始依据的记忆保留引用；没有依据的标 legacy_unverified；缺范围的留待核对，不能按空 target 当全局公开。旧 warmth 不迁成事实，旧日记不迁成已验证经历。导入报告遗漏、冲突和待核对数量。

每次切换在短暂暂停写入时导入尾差，记录切换序号并让一个版本持有写权限。不能新旧两条链同时推动同一关系/承诺。

回滚保留新增事件，不还原整份生产 world.db，不重置投递队列，不重发历史动作。已外发动作不可通过恢复数据库“撤销”。新格式由兼容读取或导出保留；必要时停用主动任务，不能回滚到会重新制造虚假关系的路径。

故障语义：观察缺失保持未知；存储提交失败明确回执；外部执行成功但状态写失败靠队列凭据恢复；模型解释失败不改心理状态；查询失败不能当作“没有此事”。

每个阶段保存可重建快照与版本、处理游标、失败定位信息；不记录或展示模型私有思维过程，只保留简短决策理由、证据和结构化选择。

## 15. 端到端例子

主人私聊：“明晚前帮我找两篇有关某主题的资料，我先去忙。”

1. 记录来源消息、会话和人员；“他去忙”是对方自述，形成可修正信念。
2. 鲸鲸接受后创建承诺目标：两篇资料及摘要准备好，并按约定交付；设下一步和复核时机。
3. 群里 A、B 聊天不算主人回应，也不完成这个目标，不改变对主人的关系。
4. 无新聊天时，到复核点可继续查资料。一个来源失效，记录失败证据；评价为该目标受阻，换来源。
5. 查到两篇只完成准备步骤；发出后分别记录入队、本地确认等凭据，不编造已读。
6. 主人明确“收到，谢谢”提供实际回应；是否完成按原先 done_when 判断，而不是任意一句话就销账。
7. 主人后来指出一篇不合适，记录修正并重新打开相关步骤；反思改进选材方法，不把“谢谢”累计为无限好感。
