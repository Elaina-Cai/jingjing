## 没有做的事（以及为什么）
- **没有物理删除** `memory_projections` 的 17,824 行。它们作为只读档案留在 `data/yinyue_meta.db`，停写触发器（`legacy_projection_{insert,update,delete}_frozen`）继续在位。
- 原因一：撤销停写要求两个库都处于 rollback-journal 模式（`core/memory/legacy_write_freeze.py:193 legacy_rollback_requires_rollback_journals`），当前 `yinyue_meta.db`/`world.db` 都是 WAL，服务在线时无法安全切换。
- 原因二：删行会破坏审计可回放性，且这与「弃置」的语义并非同一件事——弃置只需要保证**永不导入**。

## 对「新」的影响（已核实）
- 新事实走 `cc.commit_updates` → `data/world.db` 的 `cognitive_state_scoped`，不经过 `memory_projections`；停写自 22:12 生效后，日志中 `memory_projection_retired` 事件 0 条、`legacy_projection_writes_frozen` 报错最后一条停在 22:16:08（均为切换前探针产物），说明运行路径没有再尝试写旧投影表。
