## 3. 边界：什么动，什么不动

| 允许动 | 为什么 | 纪律 |
|---|---|---|
| `core/context/`（世界窗口、自我读数、记忆读侧） | 三面只读要在这里落地 | 只加读接口，不改窗口的纯函数性质 |
| `core/terminal/`（留痕、账本旁注） | 留痕是账本的旁注，不是第二本账 | **不加第二个写入口**；只加表/列与 append |
| `core/speech/`（出口） | `deliver → Receipt` 要在这里 | 出口只执行、不改写；旧路径保留到 E2 验收后再摘 |
| `core/execution/`（平台适配器） | `capabilities()` 与六类错误码 | 一次投递 = 一次平台调用；失败不重发 |
| `agents/tools/`（契约族） | 工具要按 `observe/act/schedule` 收口 | 每回合 ≤6 个 schema、≤2 次调用 |

| 不动（或只做加法） | 理由 |
|---|---|
| `core/terminal/event_store_db.py` 的写入语义 | 唯一写入口已被 `tests/test_event_chain_links.py:969` 钉死，动它就是动 R1 |
| `db/migrations.py` 里已有迁移 | 迁移只允许**新增**；已发布的迁移改一行都算破坏历史 |
| `core/routing/turn_pipeline.py:755` 的入口签名 | 只允许加字段（如 `turn_id`），不允许改已有参数 |
| `configs/llm.toml` 的端点与模型选择 | 重构期不换模型，否则所有读数不可比 |

**三条红线（与《目标与蓝图》§3 同一套）**：一次只允许一处能写账本；迁移只增列；新开关默认 `off`/`shadow`。

| **I7** | extra 键必须先登记 | `scripts/audit_extra_contract.py` 扫到的每个 extra 键都必须在 `core/routing/turn_pipeline.py` 的 `EXTRA_CONTRACT` 里；不在即红（strict 档抛错会被 fail-closed 吞掉，于是静默放行） | 拒 |
| **I8** | 一个工具只许有一个效果等级 | `core/tools/builtin.py` 的 `all_specs()` 里每个 spec 的 `effects` 只允许一个等级；混挂即红（否则闸只能按最高档执行，读也被授权） | 拒 |

**为什么是这八条**：I1/I2 保护「真相只有一份」；I3/I4 保护「读是纯函数、可以空手」；I5 保护「说得出就要指得回」（我们没有测试当裁判，只能用 basis）；I6 保护「人设是人写的，不是她被骂两次就改了」；I7 保护「闸只认数得清的键」（未登记的 extra 键在 strict 档抛错会被 fail-closed 吞掉，于是静默放行）；I8 保护「读不被当成写」（一个工具混挂两个效果等级时，闸只能按最高档执行）。

## 7. 文档与图的变更协议

改任何一块，都按**图 → 文档 → 检查器 → 测试**这个顺序走，反着走必出事：

1. **先改图**（`output/3d/viewer_css.html` 的坐标/贴图/标签）。图是唯一命名来源。
2. **再改文档**：坐标只写在各文档 §1（图上位置）；改了坐标必须同步 `scripts/check_docs_consistency.py` 的期望值。
3. **重跑两个检查器**：`scripts/check_docs_consistency.py`（文档↔图）与 `scripts/check_3d_textures.py`（贴图↔文档↔CSS 比例）。任一红，停。
4. **补/改回归测试**：契约字段变了，`docs/decisions/判投记_契约.md` 与代码里的校验器必须同一次提交里一起变。

另外三条禁令：
- **禁止**只手改文档里的坐标（不改图）——这正是过去 4 处矛盾的来源。
- **禁止**在两份文档里各写一遍同一字段的定义；字段只在契约里定义，块文档只写「见契约 §X」。
- **禁止**把 `docs/` 里的东西当运行时输入——没有任何代码读它们（已实测 0 处），文档只是设计事实源。

## 8. 风险与退出条件

| 风险 | 触发信号 | 退出动作 |
|---|---|---|
| 读数长期为空，重构变成「自我感觉良好」 | E0 连续 3 天某个读数为 0 或缺失 | 停下，先把观测修通，不进 E1 |
| 出口幂等失效 | dry-run 出现任何一次重复发送 | 立即停 E2，回 `dry_run=1`，查 `client_msg_id` 生成 |
| 读数漂移（文档改完图没改 / 图改完文档没改） | 两个检查器任一红 | 停手，按 §7 顺序重做；不许「先提交再说」 |
| 契约与块文档再次分叉 | 同一字段在两处定义 | 合并到契约，块文档删掉复述 |
| 阶段拖期 | E2 超过 8 周仍未验收 | 砍范围（先只做微信一个平台、只做文本 `say`），不延期 |
| 读数被当成 KPI 刷 | 为了「弃权率 5–15%」而人为弃权 | 回到原始记录抽检，凡是 basis 为空的一律算未完成 |

**什么时候必须停下来问人**：① 要动 R1/R2/R3 任一红线；② 要改已发布的迁移；③ 要引入新的分类表/标签体系；④ 某条验收指标连续两周达不到且不知道原因。
