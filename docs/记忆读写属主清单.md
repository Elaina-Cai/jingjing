# 记忆读写属主清单（B 读路径盘点）

日期：2026-11-08。目的：把 personal / knowledge / diary 的现役读写属主写清楚，避免再出现第二个情绪/记忆真源。本清单描述**当前代码事实**，不是迁移方案；生产切换仍需单独窗口。

## 总原则

- 一个存储只有一个现役写入口；旧 JSONL 只读兼容，不再追加。
- 日记（diary）是自述材料，不是事实/承诺的证据；不能拿来给 belief 或完成判断作证。
- `knowledge_docs` 是全局 web 知识，不属于某个人，不参与个人记忆可见性。
- 个人长期记忆的规范写入口是 `core/memory/explicit_write.py::commit_explicit`（事件 + 投影同事务）；投影不能绕过它直接 `upsert`。
- 读路径必须带 scope/身份；不能只凭昵称或相同 chat_id 合并。

## 1. 个人记事本（notes.jsonl）

- 现役写：
  - `loop/notes.py::add`（新增一行，含 `note_id/revision/status/evidence_refs`）
  - `loop/notes.py::revise`（追加新 revision）
  - `loop/notes.py::revoke`（追加 revoked 墓碑）
- 现役读：
  - `loop/notes.py::_all_rows` / `all_rows` / `visible_rows` / `residents` / `diaries` / `note_block`
  - `loop/memo.py::resident`（只读门面）
  - `loop/history.py::_rows`（日记视图优先 `notes.diary_rows()`）
  - `console/collector.py::_notebook`（展示用，按 note_id/revision 折叠）
- 旧库只读：
  - `loop/notes.py::_legacy_rows` 读 `data/loop/self_history.jsonl` + `data/loop/memo.jsonl`
  - `loop/memo.py::_rows` 只读 `data/loop/memo.jsonl`
  - `loop/history.py` 仅在 notes 读取失败时回退 `self_history.jsonl`
- 不再写：`memo.jsonl`、`self_history.jsonl` 没有现役 writer。

## 2. 日记（diary）

- 现役写：`loop/history.py::maybe_write` → `loop/notes.py::add("diary", ...)`。
- 现役读：`loop/notes.py::diary_rows`、`loop/history.py::_rows/block`、`console/collector.py::_notebook`。
- 旧库：`self_history.jsonl` 只读兼容；不再双写。
- 约束：diary 不能作为 `believe/close/appraise` 的证据引用；只能作为自述上下文。

## 3. 人员备注（person_notes 表）

- 写：`core/context/person_notes.py::upsert_note`（名单同步事务内可传 `conn`）。
- 读：`core/context/person_notes.py` 的读取 API（按 person/scope）。
- 用途：逐人稳定备注/名单，不等同于 `notes.jsonl` 的个人记事，也不写 memory projection。

## 4. 全局知识（knowledge_docs 表）

- 写：`agents/tools/web.py`（web_search 结果入库、hash 去重、过期清理）。
- 读：`core/memory/providers.py`（全局 web 知识 provider）。
- 约束：不按 person/chat 做可见性；不能拿来冒充个人记忆或关系证据。

## 5. 规范个人长期记忆（terminal_events + memory_projections）

- 写：
  - `core/memory/service.py::MemoryService.remember` → `core/memory/explicit_write.py::commit_explicit`
  - `core/quality/corrections.py`（用户纠错）
  - `core/quality/consolidation.py`（consolidation）
  - `agents/tools/memory.py`（显式记忆工具）
- 读：
  - `core/terminal/memory_gateway.py::recall`（带 scope/身份/索引绑定）
  - `core/terminal/memory_runtime.py`
  - `db/repo_memory_projections.py`（底层仓储）
- 事件真源：`terminal_events`；投影由 `MemoryProjector.project_event` 生成，`source_event_ids` 必须指向真实事件。
- 约束：禁止在 `commit_explicit` 之外直接 `memory_projections.upsert`（迁移/回填脚本除外，且走显式迁移）。

## 6. 认知状态（cognitive_events）

- 写：`core/context/cognitive_commit.py::commit_updates`；操作集合 `observe/believe/revise/intend/close/appraise/reflect/retract`。
- 读：`cc.read_state`、`core/context/appraisal.py`、`core/context/reflection.py`、`core/context/goal_*`。
- 约束：appraisal/reflection 只写解释/方法经验，不改事实、权限或投递证据。

## 现役读路径的已知边界

- `loop` 的 prompt 仍从 `notes.jsonl` 读个人记事/常驻板；这些 notes 尚未投影进 `terminal_events/memory_projections`，所以“notes 与规范记忆”仍是两个存储，只是写入口已统一为 notes。
- `knowledge_docs` 与个人记忆分离，符合设计，不应合并。
- `console/collector.py` 是展示读口，允许同时读 notes + 旧 JSONL，但不能成为写入口。
- `loop/history.py` 的日记是自述上下文，不是证据。
