# 鲸鲸后续实施任务书（交给 DeepSeek）

日期：2026-11-08。这是后续施工顺序和验收要求；上位设计为《鲸鲸认知循环实施方案》。不代表以下功能已经实现。遇到本文路径或现状漂移，先核对 owning source，再决定改法。

## 一、先认清当前状态

整体方案未完成，也未生产切换。P0/P1 是部分实现；P2 已推进到旧库迁移与兼容写入收口；P3 有目标契约和时间复核回合，但尚未启用；P4 情绪评价及经验反思尚未系统实施。

已实现：完整平台/账号/会话隔离；认知日志、版本、幂等和投影恢复；目标关闭/补偿；复核候选及明确确认；Belief 纠错和时间变化；实际工具 valid_at 历史查询；旧库只读分级预检、v2 人工审核、隔离导入与验收；读取权绑定；隔离旧投影整表停写；旧作业退役；未迁移旧库的显式事件/投影原子写入。

最近一批还完成：后台纠错的稳定反馈身份、事件/投影/样本 learned 状态同事务；源变化 CAS；并发与响应丢失恢复；模型失败/取消/无效提案不消费；旧轨迹和引用材料在进入模型前限制会话及权限。真实 MetaRepositoryManager 的 WriteHandle 接线已修复，读走 read_engine，写走 write_engine/_write_session，不能自行绕过句柄。

最近验证：403 项相关组合通过（.test_tmp/feedback-consumption-complete.txt）；另有27项索引/权限隔离 dry、5项旧纠错场景通过。不要相加为全方案覆盖率。静态检查仍红：events 98、envread 2、json 5 基线外违规，py/flags/undef 等为零。旧 data_channels 三项历史红未重验。真实模型、真实平台、多进程全链恢复和影子验收不能据此算通过。

本轮没有生产部署、服务重启、真实发送、生产库迁移或持续目标。配置开关不应因接手自动打开。

## 二、每批施工纪律

1. 先读 AGENTS.md、docs/开发规矩.md、交接当前摘要、原方案 §17；再读本任务涉及的真实代码。历史流水中的下一步不优先于当前摘要。
2. 保留所有既有未提交工作，包括 DeepSeek/Codex 已完成内容。不执行 git reset/clean，不按整个目录覆盖。先查看当前差异，再用 Migration 预检、备份、修改；新文件也纳入清单。
3. 每批完成一个相关闭环，立即 py_compile，跑行为反例和必要回归，执行 scripts/check.py all。不得改 baseline 掩盖违规。不要把失败、跳过或未执行写成通过。
4. Python 通道先验证：.venv/Scripts/python.exe --version。本机沙箱曾拒绝启动其基础解释器；获准的沙箱外现有解释器可用。不要为此重装环境，也不要以管理员方式启动服务。不同宿主重新核实权限。
5. 隔离 YINYUE_COGNITIVE_DB、世界模型、META_DB_PATH、DATA_DIR、PLATFORMS_DIR 等，且须在配置模块首次导入前设置。旧测试可能有导入顺序守卫；不能删除守卫。测试只用临时库和无发送替身。
6. 进度仅用户明确要求时更新；更新时同步方案 §17 和交接当前摘要。保持摘要，不追加每轮流水。本任务书各项的完成也必须有代码和证据，不能预勾完成。
7. 不靠枚举调用点各加 if 收口。把判定放到唯一属主、删掉旁路，或在接口上表达不了错误操作。每批说明同类错误还有没有别的入口。

## 三、实施批次与依赖

以下是工作包，不是必须一包一轮。能在同一上下文安全完成相关包即可合并；发现根因或前提不成立，先收缩范围，保留未完成项。

### A：审计本批反馈消费及剩余状态写入口（优先）

入口：core/memory/feedback_commit.py、explicit_write.py、core/quality/corrections.py、db/repo_base.py、repo_memory_projections.py。

先复核已有实现，不重新发明消费表：反馈样本版本包含原始字段、状态变化不覆盖晚到提交；稳定事件身份绑定来源；learned 与事件/投影同事务；reviewed/skipped 也 CAS；恢复不调用模型、不复活已删除投影；模型调用期间停写不消费。真实受控句柄和原始 engine 都要覆盖。

重点剩余检查：跨进程竞争、并发模型调用成本、处理超时后的恢复、公平处理积压。当前并不承诺跨进程只调用一次模型；不要把内存限流当持久化租约。只有发现真实重复调用/饿死反例才设计必要的认领或持久化调度，不能无依据叠新队列。新状态必须有租约到期、崩溃恢复和来源变更保护。

梳理新建、撤销、记忆/关系/自述和旧 JSONL 写口。按“实体—真源—授权—版本—消费身份”识别独立真源，不只搜函数名。未迁移旧库可有显式兼容层，但不能与已迁移实体双写。撤销须有授权和依据，不能恢复模型直接 forget 或词面相似失效逻辑。

退出：选定实体的所有现役读写都可解释其唯一属主；失败、重复、并发、源变化、重启均有行为证据。仍未统一的实体明确列出。

### B：新建/撤销及其他记忆契约统一（依赖 A 的属主分析）

沿用 Belief、commit_updates 和程序授予的上下文，不让模型填 scope、预期版本或扩大证据集。补齐尚缺的新建/撤销提案与回执；先查现有操作是否已支持，不另立事实表。来源存在不等于语义为真，推测仍为推测。

personal/knowledge/日记等分别核对来源、可见范围、有效时间、冲突与替代语义。未知归属不能补成当前账号或公开；抓取时间不能当有效时间；日记和自身 MEMORY_WRITE 不能作为独立外部证据循环强化。尚无版本契约的旧库不能回答历史事实。保留人工核对报告，不自动批准或自动迁移敏感资料。

退出：当前纠错不复活错误，历史 time_change 可回到当时版本；不同来源矛盾并列；无授权的群搜索、自动常驻、按ID展开均取不到私聊材料；新旧接口不能绕过版本解析。

### C：完整迁移与回滚演练（依赖 A/B）

串起真实控制流：离线副本预检 → v2 默认暂缓模板 → 人工审核 → dry → 隔离导入 → 行/证据漂移验收 → 精确读取权绑定 → 停写尾差核对 → 旧作业退出 → 重启 → 纠错/历史查询 → 回滚演练。

当前 freeze 命令只允许隔离库、会冻结整张旧投影表；未迁记录保留只读，原始事件可继续入库。不要为了部署直接移除路径限制。先定义旧写者暂停、尾差边界和切换序号，再申请真实迁移窗口。必须证实切换时只有一个版本持有写权限。

回滚保留新增日志，不恢复整份生产 world.db，不重置队列，不重发历史动作。设计失败点：建闸中断、导入中断、提交成功响应丢失、绑定丢失、文件替换、目标漂移、迟到事件、人工同时修改。恢复后核对日志与当前投影，不按“没看到回执”重做外部动作。

退出：给出一条从旧数据到新读写、重启和回滚的可复现隔离命令链，以及每一步预期输出。cutover_ready 不能只改布尔值变绿，须对应已证明的门槛。

### D：P3 持续目标调度补齐（可在 B/C 的独立部分并行推进，但不另建目标真源）

入口：core/context/situation.py、situation_store.py、goal_wake.py；loop/goal_review.py、run.py、brain.py、ports.py；promise/Intention/jobs 关联处。

目标仍以 Intention 为真源，jobs 只是执行实例。核对 goal_id 真实关联，提列需单独迁移窗口。补等待条件满足、新证据、动作回执变化等唤醒来源；事件稳定身份与目标版本共同去重，读取不消费，真实复核/提交成功才消费。避免固定最近N项饿死旧承诺；长任务在安全点交还注意力并保留下一步。未获授权的自选兴趣不能伪装成用户要求。

验收：三天后承诺可恢复；无人新发消息也能推进已授权动作；回复一句话不算任务完成；失败不宣布完成；无进展会等待/换方法，不循环找话；夜间、忙碌、权限规则保持。先隔离，再核对配置和路径，不能自动打开生产唤醒。

### E：P1 身份、证据与一条平台完整链路

跨平台只按确认的身份/来源关联，不按昵称或相同 chat_id 合并。未知坐标明确未知。原生 reply/mention 与模型解释分开，来源文本不能提升成指令或授权。

选一种已有平台，串起观察入库、稳定ID、迟到事件、范围过滤、状态提案、事务提交、实际工具回执、反馈关联和恢复。另一平台复用同契约；没有能力就标未接通，不伪造兼容成功。

验收：重复入站/回执不重复影响；两窗口并发不覆盖；重启无丢失/双应用；迟到事实会被处理；旧版本返回冲突。身份关系被撤销后，旧索引和缓存授权不能继续读取。

### F：P0 真实异步、发送证据与静态欠账收尾

保留已有 desk 操作/账号/发送前游标/精确回执绑定；继续核对尚未统一的 GUI、ports 和媒体证据入口。不要恢复按时间窗/近似文本/默认账号猜成功的旧能力。

本地回读只能说明本地记录出现，不说已读/送达；没有回执保持未知，不重发。用受控异步适配器覆盖延迟入库、重复同文、人工并发、回调取消、发送后落账前崩溃等边界；物理发送后无证据的缺口不能补造成功。

处理静态检查实际 owning source，分清历史红与新增红；逐类清 events/envread/json 欠账，不能改 baseline 或统一吞异常。旧 data_channels 三项红须重新定位后才可宣称已修复。

退出：原方案 P0 反例与相关异步恢复测试通过；不能用同步 dry 代替真实异步验证。真实平台探针另需用户明确许可，仍不自动外发。

### G：P4 有来源的情绪评价与经验反思（当前尚未系统实施）

先盘点现有 selfstate/bond/appraisal/反思机制，复用现有模型，避免新增第二份情绪真源。评价绑定来源事件、目标与人物，保留解释及版本；消费新结果修订，同一经历重放不重复累积。情绪不由无关会话活跃度机械升降。

关系理解来自相关反馈，不能拿消息次数累加亲密度；沉默只表示截至某时未观察到回应，并区分采集健康及发送证据。一次负面事件不升级为长期关系断言。目标达成/受阻与自我反应分开，推断可撤销。

复用低频反思形成有证据、可更正的方法经验；不把日记作为独立新证据，也不追加每条消息一个分类模型。成本沿用现有预算，不新增未经测量的固定调用链。

验收：改变相关目标/经历会合理改变关注、选择与表达；只改无关会话活动不应改变；纠正依据后后续选择会变化；重放100次不重复累计。先确定性/替身测试，再进入 H 的同模型对照，不以情绪词增多证明有效。

### H：40场景语义对照、盲评、消融与成本验收（所有阶段的总门槛）

建立原方案要求的首版40场景固定对照集：群回应、私聊承诺、反馈未知、记忆纠错、身份与范围、长时间无消息；每场景含仅改变一个因素的反事实版本。保存输入、授权、证据、工具返回、预期禁止行为与评分准则。

同模型、同工具结果、尽可能同随机条件比较旧/新；随机模型多次重复，报告波动。盲评归因、完成判断、是否打扰、记忆越界及情绪依据，不只评文风。分别消融有效记忆、目标和评价；没有贡献的模块不能凭名称保留。

报告每轮调用、token/费用、延迟及失败率，关键场景不能退步；新增错误逐条归因。可先写离线评测器和替身数据，真实模型评测需确认可用预算和授权，不能未经要求大批调用。

### I：受控影子、发布与最终交接（最后执行）

先选用户许可的会话，只观察/影子，不发消息、不改生产关系或销承诺。核对真实配置、持久化路径、身份绑定、旧作业退出和回滚预案。真实生产迁移、开关启用、服务重启与外发不是普通“继续”的自动延伸，必须把具体执行清单、备份与验证结果准备好，再获得适用的明确授权。

发布门槛：结构性不变量通过；语义总体改进且关键场景不退；新增错误已归因；成本/延迟相对旧版有报告；失败与恢复有证据。不能以发送更多或对方回复更多作为成功指标。观察所需等待时间不能用聊天轮数替代。

最终交付：每阶段已完成/部分/未完成清单、可复现命令、实际结果、迁移/回滚记录、已知限制及需要用户介入事项。只有证据满足门槛才宣布方案完成。

## 四、每批结束给用户的固定交付

用短段落写：完成了哪一块；解决什么反例；实际测试数量与结果；未通过/未执行的检查；生产是否变更；接下来最值得做的一块。不要把重叠测试数相加，不把代码存在当验收通过。

目前粗估还需15–25个较大工作轮次：代码与隔离收口约10–15轮，语义、影子和发布约5–10轮。这是范围估计，不是每包固定一轮或已获生产授权；新缺陷可能改变区间。优先把完整闭环一次做完，不以堆守卫和细碎回合充当推进。
