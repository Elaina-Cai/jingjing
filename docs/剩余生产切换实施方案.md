## 一、旧事实与信念切换

1. **刷新证据并确定审核范围。** 先从实际运行配置确认源库，使用 scripts/audit_legacy_memory.py，参数为 --db data/yinyue_meta.db --source-id production-meta。使用 --review-template 生成待审清单，存入 .test_tmp。只让证据能证明原文、平台、账号、会话及可见范围的记录进入审核。生产迁移授权和逐条事实确认是不同的输入，清单上的待审状态不得当作批准。缺归属或缺证据的记录原地留存，禁止猜测账号或扩大可见范围。
2. **在生产副本演练。** 使用 SQLite 在线备份 API 生成一致副本，保留对应的源逻辑 ID。用 --check-review 核对审核清单与源快照。scripts/import_legacy_beliefs.py 先 dry-run，再对隔离目标使用 --apply，按 sources、review、target 的实际 CLI 参数执行，其中来源参数为 --source / --source-id。运行 scripts/drill_legacy_cutover.py --workdir <空的隔离目录> 验证切换与回退，再用 scripts/verify_legacy_import.py 核对审核覆盖、导入完整性和读取绑定。涉及子进程的 pytest 明确传入隔离 --basetemp，环境设置参见旧交接。
3. **接通正式生产路径。** 现有 core/memory/legacy_import.py 和相关 CLI 有隔离目标守卫。保持守卫，先查生产事实读写的真实入口、读路由绑定与写入保护，复用已有审核、导入和验证逻辑，为经确认的生产路径提供显式操作入口。生产入口需要锁定确定的源、目标、审核摘要和受影响范围，支持重跑和中途失败；现有隔离演练通过只能证明隔离路径。旧库可能服务会话、角色或其他存储，不得将整表停写当成记忆切换。
4. **生产操作顺序。** 备份核验 → 暂停受影响范围的旧写入 → 再核源指纹及审核清单 → 导入并核对数量、来源及完整性 → 确认旧写入保护生效 → 切换真实读路径及写入归属 → 恢复服务并复查。对已知批准样本检查正确账号可读、跨平台或错账号/会话不可见；验证新写入唯一落点、重启后绑定仍生效。无确认样本或读写归属无法验证时，记录所缺证据，保持现有绑定。
5. **回退及验收。** 提前演练切换后新增或撤销的事实如何保留。回退时先停相关写入、核对并交接切换后增量，再还回旧读写归属，保留新库和审计。记录审核、迁移、暂缓数量，目标校验结果、隔离验证、新旧写入权及回退位置。通过这组检查才能宣布完成。没有迁入的旧记录按审核状态留存。

## 二、影子功能转正

1. **核对实际开关。** 以 core/features.py 的注册项、实际调用点、启动链和运行时取值为准。盘点每项对应功能、观察时行为、正式时行为、加载配置的服务和最近证据。优先查 YINYUE_FEATURE_OUTPUT_GATE=shadow，入口为 core/speech/outbound.py，判定在 core/speech/guards.py。配置中的 YINYUE_FEATURE_GROUP_SOCIAL_GATE=shadow 此前未找到消费者，需复查当前分支、入口和替代功能，证实退役或找回消费者后再处理。YINYUE_FEATURE_CONVERSATION_SHADOW 和 YINYUE_SAY_MATRIX_SHADOW 等名称含 SHADOW 的开关也查调用点，独立对照探针按其实际用途处置。
2. **接通配置加载。** run.py 有 .env 加载，loop/run.py 此前仅对目标唤醒有定向读取。核实 scripts/supervisor.py 及子进程的入口和环境继承，同时核对是否有继承值覆盖 .env。若差异属实，在实际使用的服务接通该开关，沿用现有配置约定并验证重启后仍然有效。只输出待核对的开关和有效值，避免导出完整环境。
3. **切前验证。** 隔离运行相关测试和实际出站入口的替身发送，覆盖正常私聊和群聊原样通过、群聊字数只观察、结构化名单在 on + enforce 下改为拒绝文本、shadow 下只记录、拦截项和观察项作用域独立。确认所有在用的发送入口都按预期取值。新发现的影子功能逐项验证其正式态特有的效果及失败边界。
4. **分项切换及回退。** 先备份现行配置，保存基线读数。出站闸门切到 on 后按运行手册重启需要加载变更的服务，观察重启后的有效值、首批正常发送回执和守卫审计。对合成的拦截场景使用替身；确需真实验证时范围限已授权的微信 Elaina 会话，避免发送名单样本。遇正常消息误拦、发送异常或有效值不一致，恢复该项原配置，重载并复查回执。其余有实际消费者的开关一项一项重复；历史残项记录对应证据及处置结果。
5. **验收记录。** 每项记录配置值、运行时值、哪个进程消费、正式行为的验证证据和恢复方法。分别标明已经生效、仍待验证和已退役的项。配置文件中的 on 只能证明配置已写入。
