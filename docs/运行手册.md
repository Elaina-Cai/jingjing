## 1. 环境与解释器

| 事实 | 值 / 位置 |
|---|---|
| 生产解释器 | `.venv\Scripts\python.exe`（Python 3.14.0） |
| 测试解释器 | `.venv_it\Scripts\python.exe`（Python 3.14.0）——**所有测试/检查器用它** |
| 环境变量 | `.env`（当前 123 行 `YINYUE_` 前缀），由 `core/env.py::load_yinyue_env_defaults` 在**进程启动时读一次** |
| 改 .env 之后 | **必须重启**，否则读到的还是旧值（这是最常见的"改了没生效"） |
| 临时目录 | 宿主 TEMP 不可用；生产在启动早期把 TEMP/TMP 钉到 `logs\tmp`，测试用 `tests/_tempdirs.py` 的 `temp_base` |

**纪律**：测试与检查器一律 `.venv_it`；生产进程一律 `.venv`。混用会得到互相矛盾的读数（历史上踩过：`.venv` 没装 sentence-transformers）。

## 4. 起停服务

服务 = autostart / 监管器 / 调度器 / AI 引擎整栈。AI 引擎硬活口是
`127.0.0.1:39871`。旧 `restart_service.ps1` 只看 8972，不适用于当前整栈；
计划任务名仍为 `yinyue_scheduler`。

```powershell
# 1) 先看当前监听和受管进程，不动任何东西
.\.venv_iso\Scripts\python.exe .\scripts\restart_stack.py --dry-run

# 2) 真重启（总闸 → 等自退 → 超时才清 → 起监管器 → 等 39871）
.\.venv_iso\Scripts\python.exe .\scripts\restart_stack.py --grace 30 --reason manual_restart
```

`restart_stack.py` 的顺序（**不要手工简化**）：

1. 列出持有 `:39871` 的引擎 pid 和受管进程；
2. 写 `all.stop`、`scheduler.stop`、`loop.stop`；
3. 给整栈 30 秒自行退场，只有超时才记录并清理；
4. 清掉四个停止哨兵；
5. 启动监管器，等 `:39871` 重新监听；
6. 核对 `logs\loop_heartbeat.json` 与 `logs\loop_engine.json`。

历史上的“重启假成功”都出自旧进程还在、新实例却被单实例门拒绝。不要先删哨兵，也不要手工叠第二个监管器。

**验活三条**（缺一条都不算起来）：

| 判据 | 位置 |
|---|---|
| 调度器在跑且 pid 与心跳一致 | `logs\loop_heartbeat.json` 的 `pid` / `uptime_ms` / `main_loop_ticks` |
| AI 引擎在跑 | `logs\loop_engine.json` 的 `pid` / `ticks`，且 `:39871` LISTENING |
| 启动里程碑出现 | `logs\yinyue.log` 里的 `scheduler_running`、`migration_done`、`flag_*` |

网页面板若另行启用，再验 `GET http://127.0.0.1:8972/accounts`；该端口不是当前 AI 引擎的活口。

**历史消息元数据维护**（只补缺失平台号/发送者/引用，不覆盖已有值）：

```powershell
.\.venv\Scripts\python.exe .\scripts\backfill_inbound_metadata.py --limit-per-account 5000 --max-rounds 100
.\.venv\Scripts\python.exe .\scripts\verify_evidence_chain.py
```

先在 world.db 副本或隔离环境验证；生产执行时保持服务空闲。脚本幂等，
第二轮 `updated=0` 表示源库里也没有更多可补元数据。

**卡死时的取证**：单次任务超过 `YINYUE_JOB_TIMEOUT_SECONDS`（默认 180s；`run_sync_pipeline*` 为 360s）会落 `logs\job_stack_<ts>.txt`；超 `YINYUE_JOB_STUCK_RESTART_SECONDS`（默认 900s）会 `os._exit(3)` 让 autostart 重启。`logs\faulthandler.log` 会随运行增长（曾到 119 MB），重启时轮转。

**看门狗**：`logs\watchdog.stop` 存在 ⇒ autostart 的看门狗循环不启动。停服务排障时先放这个文件，避免「刚停就被拉起来」。

## 8. 常见故障速查

| 现象 | 真因 | 处置 |
|---|---|---|
| 改了 `.env` 没生效 | 环境变量只在进程启动时读一次 | `scripts\restart_stack.py` |
| 重启后旧进程还在 / 新引擎没监听 | 旧进程仍持有单实例或 39871 | 重跑 `restart_stack.py`，看它列出的 survivors |
| 服务不响应停止信号 | 主循环被同步轮钉住，哨兵只在循环顶部检查 | `restart_stack.py`；看 `logs\job_stack_*.txt` 定位栈 |
| `sqlite3.OperationalError: unable to open database file` | 宿主 TEMP 不可写（只有需要临时文件的 INSERT 会踩） | 已在启动早期钉 `logs\tmp`；复现时先查临时目录是否可写 |
| 日志里 `embedding_failed` 但功能看着正常 | 曾静默回零向量（＝没查） | 已于 `llm/embedding.py` 加本地回退 + 熔断；查 `embedding_degraded` 计数 |
| 无头截图后在仓库根出现 `edge_cdp_*` | 临时 profile 目录 | 已 gitignore；可直接删 |
| 单跑绿、全量红 | 并发/临时目录 flaky | `--filter` 单跑确认，再查是否动了共享目录 |
| 贴图文字与文档不一致 | 文档改了没重渲染，或反之 | 跑 `check_3d_textures.py`，按提示改生成脚本后重渲染 |
| 文档坐标与图不一致 | 只手改了文档 | 跑 `check_docs_consistency.py`，按「图→文档→检查器→测试」顺序改 |

## 9. 写文件与命令行的编码纪律（本机专有，踩过很多次）

- 写含中文的文件：`[System.IO.File]::WriteAllText($p, $c, (New-Object System.Text.UTF8Encoding($false)))`（无 BOM）。`Set-Content -Encoding utf8NoBOM` 在 PS 5.1 不支持；`-Encoding ASCII` 会把中文压成 `?`。
- PowerShell 命令行里**不要**出现中文弯引号 `“ ”`、emoji、反引号 —— 会让整条命令**静默 `exit 1`**（没有任何输出）。用 `「」` 代替弯引号；emoji 在 Python 源码里写 `\U0001F600` 转义。
- 长脚本不要塞进一条 here-string：分段落盘（`[IO.File]::AppendAllText`），每段写完先 `py_compile`。
- 控制台里中文/表格会错位，**以写进文件的内容为准**；需要判断渲染效果时用像素统计，不靠肉眼。
