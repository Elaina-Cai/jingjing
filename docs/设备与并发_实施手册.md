### 第 1 步：租约 `core/execution/gui/lease.py`

**新增**：`core/execution/gui/lease.py`、`tests/test_device_lease.py`
**必须实现的签名**（与 `U-30.interfaces` 逐字一致）：

```python
class UiBusy(RuntimeError):      # .holder -> str
class CapabilityMissing(RuntimeError):   # .reason -> str

def device_lease(resource: str, owner: str, *, ttl: float = 60.0,
                 hard_ttl: float = 120.0, wait_s: float = 8.0) -> "Lease": ...
class Lease:
    def acquire(self) -> None      # 拿不到 -> UiBusy
    def release(self) -> None
    def heartbeat(self) -> None
    def is_expired(self, *, now: float | None = None) -> bool
    def holder(self) -> str
```
**复用**：`pathlib` + `msvcrt.locking(fd, LK_NBLCK, 1)`（Windows 真实互斥）；锁文件放 `data/.locks/<安全名>.lock`，内容 JSON：`{owner, pid, created_at, heartbeat_at}`。
**硬要求**：`hard_ttl` 不可续期（从 `created_at` 起算）；心跳只更新 `heartbeat_at`。
**测试断言（至少 8 条）**：
1. 同进程两线程抢同一资源：一个成功、一个 `UiBusy`；
2. 两个子进程抢同一资源：同上（用 `subprocess` 真起进程）；
3. `ttl` 到 + 心跳停 → 可被接管；
4. `hard_ttl` 到（心跳仍在）→ 不可续，`is_expired()` 为真；
5. 资源名非法（不在白名单）→ `ValueError`；
6. `wait_s` 内拿不到 → `UiBusy`，且 `.holder` 是持有者名；
7. 持锁进程被 kill → 锁自动释放（Windows 行为，断言可再获取）；
8. 释放两次不报错。
**验收**：`.venv_it\Scripts\python.exe -X utf8 -u tests/test_device_lease.py` → `RESULT 0 failed`
**完成判据**：无任何现有文件被修改（`git status` 只多这两个文件）。

**第 5 步·续（2026-10-21，用户批准改语义）**：把「按回车」也纳入同一段租约，并补上脏输入框清理。

- **为什么改**：`fill_message` 单独持锁只覆盖「切会话 → 聚焦 → 填字」，回车那一刻门已经放了。
  别人能在这两百毫秒里切走会话，回车就把我们的话发给了别人。所以 `send_and_verify` 用
  **一次** `with wechat.device_guard(turn_id or "wechat")` 把「填字 + 按回车」包成一整段；
  **落盘回读（15–30 秒）仍在门外**——持锁等平台会堵住所有人的手。
- **必须处理的副作用**：文件锁**不可重入**。`device_guard` 加线程内深度计数
  `_guard_depth()`：已经在门里就直接 `yield None`（不再拿一次锁，否则自己把自己挡住）。
- **脏输入框**：`_fill_message` 聚焦成功后先 `message_box_text()` 读一眼。读到残留 →
  `clear_message_box()`（Ctrl+A + Delete + **回读确认**）；清不掉就 `GuiError("blocked")`，
  **一个回车都不按**（上一轮超时留下的半句话，回车就会当成我们的正文发出去）。
  每次都 `metrics.bump("dirty_composer_cleared", chat=…, verified=…)`。
- **新增**：`core/execution/wx_chat.py::clear_message_box(window=None) -> bool`。
- **测试**：`tests/test_device_lease_wiring.py` 47 条——含「重入只拿一次锁」「重入只释放一次」
  「脏框先清后贴」「清不掉不贴」「回读时锁已放」「回执是 sent」。
- **开关**：`.env` 写 `YINYUE_FEATURE_DEVICE_LEASE=shadow`（只记「本可以拿到手」的日志，不改行为）；
  日志没有误报再改 `on`。

**改 `on` 之前必须先跑**：`python -X utf8 -m scripts.lease_probe`（15 条断言，约 15 秒；
`--case mutex|ttl|hard|parallel|state`，`--lock-dir` 换目录）。2026-10-21 首次跑通的结论：

1. **互斥成立**：另一进程持 `input` 时，本进程等满 `wait_s` 抛 `UiBusy` 且 `holder` 是对方；
   对方退出后立刻能拿到。
2. **崩溃接管是「立刻」不是「等 TTL」**：进程一死，OS 就释放那个字节区间锁，所以 `ttl`
   只是状态新鲜度与诊断，不是接管开关。
3. **活着的持有者抢不动**：`hard_ttl` 到期也抢不动（同一个区间锁还被它的句柄占着），
   只能在「锁空闲 + 状态过期」时接管。真正的兜底是 `wait_s` + fail-closed + 心跳日志；
   要抢占活着的持有者只能杀进程（kill switch 属另一机制，未做）。
4. **并行成立**：`input` 与 `page:tab2` 可同时持有，同一资源仍互斥。
5. **可观测**：状态文件里有 `owner / pid / created_at / heartbeat_at` 四样，排障先看这四个。
   反复出现 `input_busy` 时：读 `data/.locks/<resource>.json` 的 `pid` → `taskkill /PID <pid>`
   （**没有 kill switch 是刻意的**：杀进行中的进程会把可用性问题换成安全问题）。

## 4. 术语表（读文档时对照）

| 词 | 一句话 |
|---|---|
租约 / lease | 一段时间内"手归谁"的独占凭证，带 TTL 与不可续的 hard_ttl |
代次 / generation | 目标每成功切换一次 +1；动作前后比对，不一致就停手 |
安全点 / safe point | 动作序列里的五个可停点；回车（S4）不可中断 |
世界优先 | 恢复与对账先读屏幕/前台/库，日志只做提示 |
唯一命中 / unique | 元素要么唯一、要么不动；0 个或多于 1 个都算"没找到" |
假活 | 开关是 on，但代码没接上，行为没变 |
三源合并 | UIA > DOM > OCR，坐标统一屏幕绝对坐标 |
截断的配额 | 每会话配额不能突破全局硬顶（100×20 ≫ 60） |
证据分级 | OS 动作留全屏图，CDP 动作留页面图，只读只留指纹 |

## 5. 不可自行更改的十条决定（要改先问人）

1. 租约**不是**安全边界，不许当沙箱用（只防无意绕过）。
2. 不许把"等落盘"放进锁内（26 秒的等待必须异步）。
3. 不许跳过回车前那次 `check()`，哪怕为了快 40ms。
4. `external_send` **永不 grant**，每次都要人确认。
5. `fast` 档**永远不许发消息**。
6. 状态只能走 §6 迁移表，不许自由组合。
7. 任何未实测的数字必须带 `# 假设，未校准` 注释。
8. 动了代码必须同步 `refactor_plan.yaml`（files / interfaces / acceptance）。
9. 不许往树里塞"没人要、没量具、没真机验过"的能力（历史上有过 ADB，做了又撤）。
10. 内部状态码不许出现在聊天文本里（要过降级话术库）。
