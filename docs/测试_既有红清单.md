## pytest 风格用例（2026-10-20 已隔离）

`tests/` 根下的用例是**独立脚本**（`def main() -> bool`，`return False` = 失败），由
`scripts/run_all_tests.py` 跑。有 5 个文件当年是照 pytest 夹具写的（`monkeypatch` /
`capsys`，没有 `main()`）：

`test_actor_identity_normalize` · `test_embedding_local` · `test_intention_tick` ·
`test_memory_tool_visibility` · `test_search_deepseek`

它们在脚本 runner 下的两种下场都不好：
- `.venv_it`（装了 pytest）下：import 成功 → **一条用例都不跑 → exit 0 → 报表 PASS**，假绿；
- `.venv`（没装 pytest）下：`ModuleNotFoundError: No module named 'pytest'`，红得没有信息量。

`pyproject.toml:49` 的 `python_files = ["__no_pytest_collection__*.py"]` 又把它们挡在 pytest 外面
——两头都不跑，等于长期零保护。2026-10-20 统一迁到 `tests/pytest_style/`（含 `conftest.py` 补
`sys.path`），由 `scripts/run_pytest_suite.py` 用 `.venv_it` 显式跑：

```
.\.venv_it\Scripts\python.exe -X utf8 scripts\run_pytest_suite.py [--filter 名字] [-v]
```

`run_all_tests.py` 的 glob 是 `tests/test_*.py`，天然不收子目录，两边互不干扰。

**同一个坑，独立脚本也有两种形态**（2026-10-22 定性）：① pytest 风格文件在脚本 runner 下 import 成功、一条不收集就 exit 0；② 文件写了 `def main()` 但末尾没有 `if __name__ == "__main__": main()` 入口——runner 拿到 exit 0 + 空输出，照样记 PASS。
