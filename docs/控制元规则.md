## 规则

判定层 = `core/routing/`、`core/context/`。它只该处理**通用概念**（谁对谁说、这句话要不要接、
这个簇还开着没有）。两类词不该出现在这里：

- **平台名**：`wechat` / `微信` / `napcat` / `onebot` / `telegram` / `企微` / `qq`
- **产品动作名**：`拍一拍` / `戳一戳` / `表情包` / `贴纸` / `提醒` / `日程` / `待办` /
  `投票` / `接龙` / `红包` / `转账` / `朋友圈`

它们属于 World / 适配层。判定层要区分「拍」和「说话」，应该问 World 的 `kind`，不该认字面。

## 检查器的已知限界（写给下一个看到它报错的人）

`scripts/check_docs_consistency.py --report` 的锚点校验只比两件事：**引用的行号（±2 行）与那一行附近的字面词**。
它**不判语义**——给它加语义匹配等于让它开始猜意思，那样它报的每一条都得重新判真假，工具就白写了。所以：

- 写锚点时，旁证词**优先用常量名 / 符号名**（不会因为改逻辑而腐）：写 `` `core/constants.py:41` 的 `MEMORY_CANDIDATE_TTL_DAYS` `` 能核出来，写成「`:41` 的死常量」就核不出来；
- 报「内容已换」时先自己看一眼那行还在不在，再决定是「改行号」「改旁证词」还是「那句话的事实已经变了」——2026-10-23 就有一条属于第三种（`plan_block` 的消费方被搬走），只改数字反而会把错的事写得更像对的。
