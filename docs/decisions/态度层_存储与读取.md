# 态度层：存哪、怎么取（规格 v0.1）

> **状态（2026-10-20）：本文档记的是 v0.5 数值模型的推导过程**（`valence` / `arousal` / `trust`、基线、半衰期、±0.20 限幅、日上限 3 条）。该数值模型已在 `自我立方体.md` v0.6 撤销，现行口径是「事件清单 + 轻/中/重档位 + 时间窗」与「可核对事实」。**本文只作推导留痕，不作实现依据**；其中「证据行只追加、折叠行、读时派生」这套存储机制仍然有效。

## 0. 一句话

**证据进库（唯一真相）、当前值也进库（派生）、进程里只放缓存**。读的时候按人取一两行，再做一次衰减。

## 1. 本文边界

只回答两件事：**存到哪**、**怎么取**。

明确**不涉及**：

- 谁有资格写、写入口放哪个模块、要不要开关；
- 谁读、读出来怎么影响说话/语气/生成；
- 态度维度的最终集合（本文只用一个最小集合举例）；
- 衰减参数怎么定（只定「读时算」这个机制，不定数值）。

## 2. 三层模型

| 层 | 放哪 | 存什么 | 能不能丢 |
|---|---|---|---|
| **证据** | 库（事件流，append-only） | 每一次让态度发生变化的小事 | 不能丢，重建全靠它 |
| **当前值** | 库（一张小表，每人每维一行） | 折叠后的当前值 + 时间 + 衰减参数 | **能重算**，删了也不怕 |
| **缓存** | 进程内存 | 上面那行的拷贝 + 算好的衰减值 | 随便丢，丢了只是慢一点 |

三条理由（为什么不是别的形状）：

1. **只放内存不行**：重启即失忆——「她昨天对你的态度」第二天归零，这是能直接看见的退化；多进程各算一份必然漂移；没有历史值可查，出问题无从复现。
2. **每次从事件全量算不行**：证据是持续产生的，事件无限长，全量扫会随历史线性变慢。所以要物化一行，读时只做衰减。
3. **只读库不缓存是可以的**：缓存只是为了省重复读，**去掉它系统依然正确**——这一点必须成立，否则缓存就成了设计的一部分。

## 3. 证据层（真相）

一条证据的最小结构：

```
attitude_evidence = {
  who:         person_id,          # 态度指向谁
  dim:         str,                # 哪一维（最小集合见 4.3）
  delta:       float,              # 这次变化量（可正可负）
  basis:       {event_id, start, end, quote<=200},   # 原文位置，必须能回指
  observer:    "名@版本",           # 谁判的（规则/模型/人）
  at:          timestamp,          # 事件时间
}
```

纪律：

- **只增不改**，不做归并、不做覆盖、不写「当前值」（当前值是折叠产物，不是证据）。
- **允许 0 条**：一轮没有值得记的态度变化，就什么都不写；**不许写一条 `delta=0` 的占位**（那会把「没证据」伪装成「有证据但没变化」）。
- `basis` 必须能指回原文（`content[start:end] == 原话`），否则这条证据在复核时无从判断。

## 4. 当前值层（派生）

### 4.1 表

```sql
CREATE TABLE person_attitude (
  person_id        TEXT    NOT NULL,
  dim              TEXT    NOT NULL,
  value            REAL    NOT NULL,   -- 未衰减的原始折叠值
  baseline         REAL    NOT NULL,   -- 该维的中性值（衰减回归的目标）
  decay_k          REAL    NOT NULL,   -- 每小时衰减系数
  updated_at       TEXT    NOT NULL,   -- 最后一次证据的时间
  last_evidence_id INTEGER NOT NULL,   -- 最后折叠进来的证据
  PRIMARY KEY (person_id, dim)
);
```

- **一行一维**，不做 `json` 大块：可加索引、可直接比较、迁移时不必解包。
- **主键是 `(person_id, dim)`**，不含 `chat_id`——态度是「对这个人的立场」，跟她在哪个群无关。若将来要表达「群里/私聊表现不同」，那是**读时的修饰项**，不是多一行。
- `baseline` 与 `decay_k` 放在行里（而不是读时从配置查）：让「这一行是什么时候、按什么参数折叠的」自解释；改参数只影响之后写入的行。

### 4.2 读

```
v_eff(person, dim, now) = baseline + (value - baseline) * exp(-decay_k * hours(now - updated_at))
```

只做三次算术，不需要扫事件流。**没有行 ⇒ 未知**，返回 `unknown`，**不要返回 `baseline`**：`unknown`（没观测过）和「观测过、正好回到中性」是两件事，混掉之后所有弃权率都测不准。

### 4.3 最小维度集合（示例，可改）

| dim | baseline | 含义 |
|---|---|---|
| `valence` | 0.0 | 喜恶/耐心（负=不耐烦） |
| `trust` | 0.5 | 相信程度 |
| `note` | — | 自由文本，不参与衰减，仅作人可读的注 |

维度**不要一开始就穷举**：等某类证据反复出现再加一维，加的时候只新增行、不改旧行。

### 5.5 心境与态度：同一份事件流的两种投影（不并表、不互相污染）

```

--------------------------------------
```

> 情绪是同一套存储机制、不同的键与半衰期，见 `docs/decisions/情绪层_存储与读取.md`（一张图看全部）。

这三行来自**两张表**：`mood` 在会话维度（主键含 `chat_id`），`person_attitude` 在人维度（主键 `person_id, dim`）。两张表之间没有外键、也不在同一个读函数里折叠——串不串由读的人决定，不由存储决定。

（2026-10-23 起）变的只是**读的范围**：默认跨会话，给了 `chat_id` 才收窄到那一个会话
（`core/context/emotion.py:454 models_for_reading` / `:474 mood_across_chats` /

会话，不是全历史；进程重启后没被读到过的会话不在取数范围内。

## 6. 有没有必要「用的时候拿」

有必要，而且是最省的选择。三个数：

- **量级**：现在 `person_entities` 是 118 个；按 3 维算不到 400 行、几十 KB，整表常驻内存都放得下。
- **读代价**：按主键取 2–3 行 ≈ **0.2–0.5 ms**，再加一次 `exp` 乘法；对 2–4 秒的回合完全无感。
- **写入频率**：远低于读（大部分回合没有任何一条证据）。

所以「读时取 + 算衰减」是常数时间，不需要预热、不需要后台重算。

2026-10-23 起，「用的时候拿」不再等于「预先塞进 prompt」：态度由 `get_stance_cards(person_id=…)`
与 `read_emotion(person_id=…)` 拉取；先前「每人 ≤3 条事实进自我读数」的注入形态已退役（`0b64198`）。

## 7. 缓存（可选的实现细节）

- 位置：进程内字典，键 `(person_id, dim)`，值 = 行 + 算好的 `v_eff` + 失效时间。
- 失效：TTL 60 秒；或写入时把该人的所有维一起失效（同一人通常一起读）。
- 纪律：**缓存必须有「关掉也能跑对」的开关**（构造参数或配置），否则就是第二真相。
- 不做跨进程共享缓存（那等于又造一份状态）。

## 8. 一致性纪律

`person_attitude` 是**派生值**，任何时候都应该能由事件流重算出来并逐行对上：

1. 从 `attitude_evidence` 全量重放 ⇒ 得到一张期望表；
2. 与库里的 `person_attitude` 逐行比较 `value / updated_at / last_evidence_id`；
3. 不一致就是 bug（不是「以哪边为准」的选择题）。

做不到这一点，它就变成第二真相：态度和记忆/窗口打架时，谁对谁错说不清。

## 9. 不放进库的东西

- 渲染好的句子、拼进 prompt 的片段；
- 按人算出来的「语气档位」「称呼选择」等展示物；
- 语义摘要（「她觉得你有点烦」这种自然语言结论）——要存就存成证据 + 数值，句子每次现生成。

理由：展示物会随文案改动全部失效，且无法复核。

## 10. 边界与退化

- **没观测过**（无行）⇒ `unknown`，不是 0、不是 baseline。
- **观测过又很久没动** ⇒ 靠衰减回到 baseline，行仍保留（不知道 ≠ 归零）。
- **同一人被合并/改 id**（实体收敛会改 `person_id`）⇒ 该表需要跟着迁移；这里只登记这个事实，迁移方式另行设计。
- **关系事实**（称呼、身份、欠人情）不属于这一层：那是「她和他之间的事实」，进事实层，不进态度层。
