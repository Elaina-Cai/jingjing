# 感知层 ①

> 依据：**只有** `output/3d/viewer_css.html` 里那块横向薄片 `t_perceive.png`（板面文字：`感知层 ①` / `(eventize) · 幂等 · 失败留痕`）以及它与上下两块的管子。
> 四问先答：**图上是哪块** = 横着挂的薄片，位于「外部世界」与「账本·事件流」之间（图上那个「岔点」只是接线，不是一块板、也不是一个模块 —— 见 §1 与 `账本·事件流.md` §6）；**进来什么** = 外部世界里的发生；**出去什么** = 一条事件进账本、一条失败留痕；**职责** = 把发生变成事件，只此一件。

## 2. 进来的是什么

外部世界里的**一次发生**，四种来源（这四种分类是描述外部世界的口径，不是这一层的动作）：

| 来源 | 例子 | 形态特点 |
|---|---|---|
| 消息 | 群里一句话、一张图、一个文件 | 有说者、有时间、有原文 |
| 系统事件 | 拍一拍、撤回、入退群、公告、通话 | 常常只有结构化字段，没有正文 |
| 网页抓取 | `fetch(url)` 回来的正文 | 没有平台编号，只有 URL 与抓取时刻 |
| 附件引用 | 一条消息里的文件/图片引用 | 正文在别处，消息里只有指针 |

这四种的共同点，也是这一层唯一能依赖的东西：**它们都是已经发生的、无法被我们改变的事实**。

## 3. 出去的是什么

**只有两样。**

| 出路 | 形状 | 谁收 |
|---|---|---|
| 一条事件 | 同一形状（时间 / 会话 / 说者 / 内容 / 出处 / 与别的发生的关系），且原文一字不改 | 账本 |
| 一条失败留痕 | 哪一次发生、卡在哪一步、为什么、能复现的最小信息 | 运维与量具 |

没有第三样：这里**不产出总结、不产出标签、不产出判断、不产出「这条重不重要」**。

## 4. 职责：板面上那三个词，逐字兑现

### 4.1 eventize（事件化）

把软件各自的形状**翻译成同一种形状**，好让下游只认一种。只做三件事：

1. **取字段**：时间、会话、说者、内容、出处、关系（引用了谁 / 撤回了谁 / 针对谁）；
2. **定身份**：给这次发生一个稳定的身份证（见 4.2）；
3. **落形状**：填成同一张表的一行，字段缺失就留空，**不猜**。

判据：翻译前后**信息不得增加，也不得减少**。多出来的（这条像问句、这个人是主人）一律不许加；少掉的（正文被截断、表情被丢掉）一律算失败。

### 4.2 幂等

**同一次发生，只允许交出去一次。**

| 情况 | 做法 |
|---|---|
| 外部世界给了原生身份证（消息编号之类） | 用它当身份证；同号再来 = 同一次发生 |
| 外部世界没给（网页抓取、部分系统事件） | 由这一层生成**稳定指纹**：同一内容、同一来源，两次得到的指纹必须相同 |
| 软件重复推送（重连补拉、脚本重跑） | 命中身份证 -> 计为重复，不新建行 |
| 内容相同但确实是两次发生（同一句话说了两遍） | 只要有不同的原生身份证，就是两次发生 |

为什么必须在这里做：**下游一旦去重，就说明这一层漏了**；而下游去重的代价是它得看懂内容，那正是这一层不做的事。

### 4.3 失败留痕

**读不到、解析不了、指纹算不出、写不进去 —— 四种失败，一种都不许静默。**

| 要素 | 要求 |
|---|---|
| 哪一次 | 来源指针（会话 + 时间 + 原生编号 / URL） |
| 卡在哪 | 阶段：取 / 译 / 定身份 / 落行 |
| 为什么 | 一句可读原因 + 原始错误摘要（<=2KB） |
| 能复现 | 足以重跑的最小输入（不是整条原始负载） |
| 给谁看 | 运维（修）与量具（对账） |

**不变量**：进来的次数 = 出账本的 + 判为重复的 + 失败的。**差额必须为 0**；不为 0 就是这一层在吞东西。

## 5. 为什么它必须薄

| 如果它变厚（开始读历史/做判断） | 后果 |
|---|---|
| 有了状态（我记得上次谁在回谁） | 就不能重放；同样输入两次跑出不同结果，对账失效 |
| 开始判断（这条不重要，丢掉） | 丢掉的东西**永远无法证明不该丢**；下游所有「她不知道发生过」都追不回来 |
| 开始补全（这个人应该是 XX） | 原文被污染；以后所有引用都对不上 |

所以它的大小是**一个函数 + 一张身份证规则 + 一张失败表**，没有缓存、没有上下文、没有记忆。

## 4.5 什么能改变它（写入路径）

感知层是**闸门**：它自己不留状态，所以「它变了」只有一种含义——**外面又来了一条事件**。

| 能改变它的 | 谁 | 形式 | 改不动它的（禁止） |
|---|---|---|---|
| 平台来了新消息/系统事件 | 平台客户端、本地库同步 | 追加一条事件行（幂等） | 人手工插入一条「没发生过的消息」 |
| 补录历史 | 对账/补录流程（代码） | 追加，带补录标记，共用同一套入库序号 | 插到中间另起序号、改已有行的顺序 |
| 撤回/编辑 | 平台事件 | **新追加一行**（原行保留） | 改掉原行、删掉原行 |

三条规则：

1. **只追加**：任何「更正」都是新事件，历史不改；
2. **失败必须留痕**：落不进来的事件要有一条失败记录，禁止静默丢弃（否则就是「她永远不知道那句话」）；
3. **幂等**：同一条平台事件重复到达，只落一次。

## 6. 意义（它错了会怎样）

它是「世界」与「我们的账本」之间**唯一的翻译层**：

- **吞掉一句** -> 她永远不知道这件事发生过，而且没人知道她不知道；
- **改写一句** -> 以后每一次引用、撤回、对账都会错位，且错得看不出来；
- **重复一句** -> 她会把同一件事当两件事，或者对同一句话回两次。

一句话：**这一层不产生任何价值，但它决定了后面所有价值是否可信。**

## 7. 边界（它明确不管什么）

| 不管 | 归谁 |
|---|---|
| 谁在回谁、这个人是哪个身份 | 账本不判；判断只在判板，依据由账本给 |
| 这条重不重要、要不要看 | 判板 |
| 怎么排序、怎么分组、怎么渲染成一屏 | 世界面 |
| 存多久、怎么删、怎么归档 | 账本 |
| 附件正文 / 图片描述 / 语音转写 | 旁注（由我们这一侧的后台处理器去读它的字节产出，挂在这一层的输出上，但不改写它） |
| 平台怎么调、发什么 | 出口与软件·适配器 |

## 8. 量具

| 指标 | 口径 |
|---|---|
| 进来 | 外部世界声明发生了多少 |
| 出账本 | 实际落了多少行 |
| 重复 | 命中身份证多少次 |
| 失败 | 四种失败各多少次（按阶段分组） |
| **不变量** | 进 = 出 + 重 + 失，差额为 0 |

另加一条质量数：**原文保真** —— 随机抽 N 行，原文片段与软件侧原话**逐字节相同**（含空格、零宽字符、表情）。

## 9. 不做清单

- 不打标签、不分类、不判断重要性与情感；
- 不合并同一人的多条消息（那是世界面的事）；
- 不生成摘要、不翻译、不做错别字纠正；
- 不决定保留期、不做归档；
- 不在本层丢弃任何东西（除身份证重复）；
- 不直连判、记忆、自我、工具包、出口。

## 10. 已定（原「未定」四条，2026-10-19 拍）

| # | 项 | 结论 |
|---|---|---|
| 1 | 网页抓取的稳定指纹 | 键 = `sys:<url>#<抓取时刻（微秒）>`；正文 `sha256` 只作**字段**、不进键。同页抓两次 = 两次发生（同两条消息）；重试幂等靠 `pull_id`，不靠时间或摘要；摘要进键会把「页面更新」误判成同一次 |
| 2 | 编辑 / 撤回算不算新发生 | **算新发生**：追加 `kind=edit` / `kind=revoke` 一行，指向用 `ref_external_msg_id`。微信撤回实测拿不到 `newmsgid`（169 条 `revokemsg`，0 条带），退化为 `ref_local_hint`（同会话 + 同发送者 + ≤120 秒 + 候选唯一 → `inferred`），否则 `unknown` —— 错误方向是「少看一条」而不是「多说一句」 |
| 3 | 失败留痕保留多久 | **永久，但只留元数据**（平台 / 会话 / 尝试 / 错误码 / 时刻），不存原始负载；90 天后转归档表。失败是「缺口」的账，删了没法对账，但可以瘦身 |
| 4 | 跨软件同一事件 | **算两次发生**（微信、QQ 各来一次 = 两次观察，说者与场合不同）；另加 `content_sha256` 字段，便于事后关联、去重展示 |

## 10.1 什么**不**归这一层：屏幕、剪贴板、前台窗口

这一层只处理「**外部发生的事**」（有人在某个会话里说了什么、平台发生了什么）。前台窗口标题、
屏幕画面、剪贴板内容都不属于"发生"——它们是我方这一侧的观察，同一秒可以变十次，也没有
外部消息号。它们归 `core/senses/`（`世界窗口.md` §12.1 的「第二投影」，总闸 `SENSORY`），
**不进 `terminal_events`**：账本仍然只记"谁在什么时候说了什么"。
