# 账本 · 事件流（唯一真相）

> 依据：`output/3d/viewer_css.html` 里 `(0, -600, 0)` 的板子（贴图 `t_ledger.png`），以及从留痕条 `(0, -415, 1000)` 垂下来的两条虚线（`每回合写一行` / `只记事实`）。
> 四问先答：**图上是哪块** = 判板正下方那块横板（两块立方体正中间）；**进来什么** = ①落屏吐出的一行行事件（外部发来的、她自己发出去的、系统事件、摄取回来的网页原文）；**出去什么** = 只读的两种视图（窗口后缀 / 记忆全量），以及可回放的重建结果；**职责** = 记住「发生过什么」，别的都不管。

## 1. 图上位置

- 板子：`(0, -600, 0)`，`700 × 200`，中心正对原点，左右两个立方体（自我 `-950`、工具包 `950`）夹着它。
- 两条从留痕条下来的虚线：**每回合写一行**（判 → 账本）、**只记事实**（不许写"她觉得"）。
- 三根实线从板子往上走：**翻最近 40 条** → 世界窗口；**按词 / 意思翻** → 记忆立方体；这两条是**读**。
- 账本**没有**指向判的箭头：判不直接读账本，只读窗口后缀与检索结果。

## 2. 什么是「事件」

**一行 = 一次外部发生的、不可再分的事实。** 判断标准只有三条：

1. **有外部来源**（某个人、某个平台、某个网页），不是她自己的想法；
2. **不可再分**（一条消息就是一条；附件正文是它的一部分，不是新行）；
3. **发生了**（有发生时间与抓取时间，不写"可能会"）。

字段（以现表 `terminal_events` 为准，此处只列语义）：

| 字段 | 含义 | 缺了会怎样 |
|---|---|---|
| 平台 / 账号 / 会话 / 会话类型 | 这条从哪来、归谁 | 无法隔离，跨会话串味 |
| `external_msg_id` | 平台的原生消息号 | 无法幂等，重复入账 |
| 本地 `sequence` | 会话内单调递增序号 | 无法稳定排序（同秒多条） |
| 发送者（人 id + 显示名快照） | 谁说的 | 无法归属，改名后历史错乱 |
| 发生时间 / 抓取时间 | 何时发生 vs 何时入库 | 无法做时间推理 |
| 类型（消息/引用/拍一拍/系统/撤回…） | 怎么发生的 | 渲染不出系统行 |
| 正文 + 字位置（start/end） | 原话与可定位片段 | 无法"指回原文" |
| 引用/父事件 | 回的是哪条 | 无法重建对话线程 |
| 附件指针（媒体行 id） | 图片/文件在哪 | 无法按需读 |

**不写进去的**：她的情绪、态度、判断、留痕、摘要、标签、向量。这些是**视图或旁注**，不是事实。

## 3. 一行怎么产生（落屏 = eventize）

```
外部世界 → ①落屏（无状态：只换格式、幂等、失败留痕）→ 账本（写一次，唯一入口）
```

四条硬规则：

1. **唯一入口**：只有落屏能写事件行。任何其它模块要"补一条"，只能调用落屏。
2. **幂等**：唯一键 =（平台, 账号, 会话, `external_msg_id`）；重复写入是 no-op，只加一个计数。
3. **失败留痕**：解析失败、抽取失败、入库失败都要落一条 `ingest_failed`（带原因），**不许静默丢**。
4. **两个时钟**：`occurred_at`（平台给的）与 `ingested_at`（我们写入的）都存；排序用 `sequence`，不用墙钟。

## 4. 谁写、谁读

| 角色 | 是谁 | 权限 |
|---|---|---|
| 写者一 | ① 落屏（收消息、发送回执、系统事件） | **唯一写事件行的通道** |
| 写者二 | 摄取（网页抓回来的原文，作为外部来源的一种） | 同样是「事件」，走同一个落屏接口 |
| 旁路 | 「记」写的留痕行 | **不进账本**，进旁路表（§11） |
| 读者 | 世界窗口（取后缀）、记忆检索（取候选） | 只读 |
| 读者 | 对账 / 备份 / 审计脚本 | 只读 |
| 非读者 | 判 | 不直接读账本（只读渲染后的窗口与检索结果） |

## 5. 写进去以后还能不能改

**不能。** 账本是 append-only：

- 撤回 → **追加**一条 `revoke` 事件（指向被撤回的 `external_msg_id`），原行保留；
- 编辑 → 追加 `edit` 事件（带新正文与旧正文 hash），原行保留；
- 删除（合规）→ 追加 `tombstone` 事件 + 只对正文做不可逆擦除，**保留定位信息**（谁/何时/哪条）。

读的时候**按时间折叠出"当前状态"**（最新状态视图），所以"改"只发生在视图里，不发生在表里。

## 6. 同一张表，两种视图

| 视图 | 取什么 | 给谁 | 预算 |
|---|---|---|---|
| **后缀（窗口）** | 本会话最近 N 条 / 最近 2 小时 | 世界窗口 → 判 | 40 条 / 3600 字符（超出逐出，不压缩） |
| **全量（记忆）** | 该会话全部事件，按词 / 意思翻 | 记忆检索 → 判 | 先候选 ≤2 条，每条带出处 |

**关键纪律**：两个视图都不许"改写原文再给模型"。窗口顶格就**逐出**（丢掉最旧的），不做摘要、不做压缩；要更早的东西，只能**去翻**。
### 6.1 两份投影：不是分流节点，是两种格式

图上在感知层与账本之间画了一个**「岔点」**（`addSpine(300, 850)` 的接线处）。它**不是一个模块**，2026-10-21 明确：那只是为了图好看画的分叉，**实现上不建"分流节点"**。

真实机制是：**事件流只存一份，读的时候投影成两份各自对味的格式**（§6 那张表就是这两份契约）。不复制、不双写、不分流。

| 投影 | 取什么 | 给谁 | 形状要求（对味的部分） |
|---|---|---|---|
| **窗口格式** | 本会话最近 40 条 / 2 小时 / 3600 字符 | 世界窗口 | **有序、有界、可直接排版**：时间 + 显示名 + 正文 + 引用块 + 系统行；超出逐出；不跨会话拼接 |
| **记忆格式** | 该会话全量 + 检索命中 | 记忆立方体（原文板） | **可寻址、可回原文**：`sequence` / `external_msg_id` / 会话 / 说者 / `occurred_at` / 原文与字段哈希；命中后取原文行（±6 行上下文） |

- 两份都由**账本既有的字段**算出来，不需要为谁多存一份；
- 两份都**不许改写原文**（窗口逐出不压缩；检索命中直接给原文行，不拿"最像的"顶，§7）；
- 谁要第二份格式，就在这里加一行投影定义，**不许在账本里加一个分支节点**去搬数据。

> 为什么写这一节：文档与图会被人当成"要写一个分流组件"来实现；图上那个叉号只是接线点，代码里没有对应物。

## 7. 三种读法，别混

1. **按序读（后缀）**：`ORDER BY sequence DESC LIMIT 40`——看"刚刚发生了什么"；
2. **按内容翻（检索）**：关键词 / FTS / 向量 / 结构，命中后**取原文行**（±6 行上下文）——看"以前有没有提过"；
3. **按定位取（引用）**：拿 `external_msg_id` 或 `sequence` 直接取那一行——看"他说的到底是哪句"。

三种读法都必须**回到原文行**，不许拿"最像的"顶。

## 8. 幂等与顺序

- **幂等键**：（平台, 账号, 会话, `external_msg_id`）唯一；重复 = no-op + `duplicate_skipped` 计数。
- **顺序**：`sequence` 由落屏在写入时按会话分配（单调 +1），**不用墙钟排序**（同一秒多条、时钟回拨都不怕）。
- **重放安全**：同一个原始包重放两次，结果必须完全一致（行数、内容 hash、sequence 都不变）。
- **乱序到达**：允许（平台会补发），`sequence` 按写入顺序，`occurred_at` 保留真实时间；窗口渲染用 `sequence`，时间推理用 `occurred_at`。

## 9. 存储与索引

- **落地**：`data/yinyue_meta.db`（sqlite，WAL）里的 `terminal_events`；附件/媒体在 `message_media`；对话边在 `utterance_edges`。
- **必需索引**：`(chat_id, sequence)`、`(chat_id, occurred_at)`、唯一键 `(platform, bot_account_id, chat_id, external_msg_id)`。
- **容量估算**：现库 1.8 万行量级；按每天 ~1 千行算，一年 ~36 万行 ≈ 数百 MB，sqlite 完全够。
- **冷热**：查询只走索引；全表扫描只允许出现在对账与备份里。

## 10. 备份、迁移、回放

| 事项 | 规则 |
|---|---|
| 备份 | 每日一次 `sqlite3 backup()`（WAL 下**不能**直接复制文件）；备份后 `PRAGMA integrity_check` |
| 备份的加密 | 本机备份**暂不加密**；一旦要离机（云 / 移动盘 / 共享）必须先加密（见 §18 第 2 条） |
| 迁移 | **只 ADD COLUMN**（禁止改名/改类型）；旧库必须先探测列存在（`PRAGMA table_info`）再写；回滚 SQL 写进迁移 docstring |
| 回放 | 给定时间区间 + 会话，能重放出「当时窗口长什么样」；回放是纯函数（同一后缀 → 同一渲染） |
| 修数 | 只能追加事件修正，禁止 UPDATE 旧行；修数脚本必须带备份 + dry-run + 二次确认 |

**回放的三条前提**（缺一条就回放不了）：

1. 输入唯一（同一时刻的窗口只由账本决定，不掺缓存）；
2. 渲染是纯函数（不读当前时间以外的外部状态）；
3. 行里自带渲染所需的一切（显示名存**快照**，不 join 当前昵称表）。

## 11. 什么东西**不**进账本

| 东西 | 放哪 | 为什么 |
|---|---|---|
| 情绪事件 / 态度事实 | 自我立方体的证据表 | 是"她的读数"，不是外部发生的事 |
| 每回合留痕（reading/decision/basis） | 旁路表 `turn_trace` | 可丢可重建，不该污染真相 |
| 判断结论、标签、摘要 | 不落库（或只落旁路） | 写时定性不可逆（2026-09-22 事故） |
| 向量 / FTS 索引 | 索引表 / 文件 | 属于索引层，可删可重建 |
| 抓回来的网页正文 | 记忆立方体的外部半边（同构事件） | 是事实，但**不是"群里的发生"**，单独标 `provenance=web` |
| 附件字节 | 文件系统 + `message_media` | 账本只存指针 |

## 12. 缺行与对账（不许静默）

- **对账**：按会话取「平台应有区间」与「本地 sequence 区间」比对，发现缺口就记 `event_gap`（起始、结束、缺失条数）；
- **补录**：缺口通过重新拉取补齐，补齐后 `event_gap` 标 `resolved`；
- **不可补**：平台已不支持拉取的，标 `unrecoverable` 并保留缺口行——**宁可留疤，不许假装完整**；
- **入库失败**：单条失败重试（退避），仍失败则落 `ingest_failed`（带平台/会话/原因），并在下一轮对账时重试。

## 13. 大小与预算

- 单行正文均值 ~40 字（≈120 字节 UTF-8），加元数据约 **300–800 字节/行**；
- 窗口渲染：40 条 → 约 3,600 字符（顶格就逐出）；
- 检索：候选 ≤2 条、每条 ±6 行上下文（≈600 字符）；
- 查询目标：按索引取后缀 **p90 < 20ms**；按内容翻 **p90 < 300ms**。

## 14. 边界（账本明确不管）

- 不判断"要不要说"、不判断"对谁说"——那是判；
- 不写时分类、不打标签、不做知识图谱（类目是读时的透镜）；
- 不做摘要、不做压缩、不改写原文；
- 不做业务规则（限流、静默、冷却都在判/投）；
- 不管别的会话（每个会话一个后缀视图，跨会话只能显式检索）。

## 15. 意义

- **唯一真相**：所有下游（窗口、记忆、对账、审计、回放）都从这一份推导，没有第二份"事实"；
- **可回放**：同一后缀必然渲染出同一屏，出了错能复现；
- **可审计**：每条结论都能指回某一行某一段字；
- **可重建**：索引与视图删了能重建，账本本身不动。

## 16. 量具

1. 每日新增行数 / 会话（分布，异常骤降要报警）；
2. 幂等命中数（`duplicate_skipped`）——正常应远小于新增；
3. **缺口数**（`event_gap` 未解决数）——目标 0；
4. 入库失败率（`ingest_failed` ÷ 总入站）——目标 < 0.1%；
5. 后缀查询延迟 p50 / p90；
6. 回放一致率（同一后缀重放 100 次，渲染 hash 必须全同）；
7. 附件抽取成功率（按类型分）。

## 17. 不做

- 不做写时分类 / 写时摘要（历史证明会翻车）；
- 不做「最像的顶」——查不到就返回空，让判弃权；
- 不做 UPDATE 旧行（合规擦除除外）；
- 不做跨会话混读（同一会话内才拼上下文）。

## 18. 已定（原「未定」五条，2026-10-19 拍）

| # | 项 | 结论 | 理由 |
|---|---|---|---|
| 1 | 保留期 | **永久**，正文不删、不建归档库，全部留在主库；冷热只在**查询层**做（按时间 + 索引过滤）。触发条件：单库 >2 GB 再谈归档 | 账本是唯一真相，删了就不可重放；体量小——主群 7 天 11.6 万字，全年约 12 MB，十年约 120 MB |

| 3 | 跨平台 id 归一 | **不在账本层做**。账本只存 `(platform, account, chat, external_msg_id)` 原始标识 + 可空的 `person_id` 投影；归一由身份层（`person_entities`）负责 | 账本是事实层，归一属推断层；把推断写进事实层会重演 2026-09-22 事故 |
| 4 | 编辑 / 撤回历史 | **不新建存储**，只提供视图：默认读折叠成当前状态；需要时按 `external_msg_id` 展开全部修订（落成 `ledger history --external-id X`） | 撤回 / 编辑本来就是追加事件，数据已经在 |
| 5 | 附件字节 | **本地盘** `data/media/<platform>/<account>/<chat>/<yyyymm>/`，文件名用 `sha256`；磁盘剩余 <5 GB 时停止拉取并记 `media_skipped_disk` | 量级小（媒体表日级十几行），对象存储是过度设计；水位闸防上次 2.87 GB 那种事故 |
