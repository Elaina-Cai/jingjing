# 记忆立方体（① 原文板 / ② 索引板 / ③ 常驻板 + 候选区）

> 依据：`output/3d/viewer_css.html` 里右侧那个线框立方体（三块板 `t_mem_a/b/c.png` + 外挂纸片 `候选区·未转正`），管子 `search_memory(q,k≤2)`（判 ← 立方体）与 `remember(0..3)`（判 → 立方体，虚线）。
> 四问先答：**图上是哪块** = 右侧立方体；**进来什么** = 账本投影（原文）+ 摄取（附件正文/网页/梗）+ 人写的常驻 + 判写的候选；**出去什么** = ≤2 条带出处的原文行 / 一行常驻读数；**职责** = 让「翻原文」成为一个动作，而不是一次猜。

## 1. 图上位置

```
             ┌──────────── 记忆立方体 ────────────┐
  账本投影 ──>│ ① 原文板   ② 索引板   ③ 常驻板        │
  摄取     ──>│  (可寻址)   (可丢可建)  (少而稳)       │
             └───────┬────────────────────────────┘
                     │ search_memory(q, k<=2)
                     ▼
                 判 / 投 / 记   <──── remember(0..3)  （虚线，写候选区）
                     │
                     └──> 候选区纸片（未转正）
```

- 立方体：`makeWireCube(MEM_X=780, MEM_Y=-320)`；三块板 z 依次 `-3.3 / 0 / +3.3`（原文 / 索引 / 常驻），候选纸片在 `(1160, 0)` 处 `rotateZ(-6deg)`。

| 与谁相连 | 方向 | 说明 |
|---|---|---|
| 账本·事件流 | 只进（投影） | ① 原文板就是账本的视图，不另存一份 |
| 摄取（附件/网页/梗） | 只进 | 正文进账本，再投影到 ① |
| 判 | 出（`search_memory`）/ 进（`remember`） | 出≤2 条；进 0~3 条候选 |
| 世界面 / 自我 / 工具包 / 出口 | **不相连** | 图上没有管子 |

## 2. 一个必须先定的判断：① 不是第二个库

图上立方体画在右侧、与账本分开，容易被理解成「另一份存储」。**不是。**

| 如果 ① 另存一份 | 后果 |
|---|---|
| 两个写入口 | 同一句话有两份原文，先后不一致时无法裁决 |
| 两份副本 | 撤回/删除要传播两次，漏一次就永远不一致 |
| 无法对账 | 「她看到的那条」和「账本里那条」可能不是同一条 |

所以：**① 原文板 = 账本的投影视图**（同一张表，换一个取法）。这一份在 `账本·事件流.md` §6.1 里叫**『记忆格式』投影**：可寻址、可回原文（`sequence` / `external_msg_id` / 会话 / 说者 / `occurred_at` / 原文哈希），与给世界面的『窗口格式』是同一份数据的两种取法，**不另存、不分流**。立方体的意义不是「再存一份」，而是「**换一个视角去取**」——账本按会话取后缀（世界面），记忆按词/意思/时间跨会话取（这里）。

② 是**派生**：可从 ① 全量重建，随时可丢。
③ 是**唯一真写**：条数极少（图上是 12 / 200），只有人能改。

## 3. 三块板各是什么

| 板 | 板上写的 | 含义 | 谁写 | 丢了会怎样 |
|---|---|---|---|---|
| ① 原文板 | 时间·会话·人·原文·字位置·来源；「改动只能追加：改口/撤回都成新行」 | 所有她说过的、别人说过的、抓回来的原话 | 账本（唯一写者） | 永久失忆 |
| ② 索引板 | 倒排 / 向量 / 结构 / 身份 / 旁注 -> 命中行号 | 怎么找到 ① 里的某一行 | 索引器（自动） | 只是变慢 |
| ③ 常驻板 | 称呼 / 承诺 / 偏好 / 事实，每条带「依据·写入方式·复核日」 | 「是不是」这类必须立刻知道的事 | **只有人** | 说话失去分寸 |

③ 的页脚印着 `预算 12/200 条 · 候选 7 条（未转正）`：**常驻有上限**，候选**不算记住**。

## 4. 职责：让「翻」成为一个动作（翻的是原文行）

### 4.0 一句话定义

**翻 = 按需取原文行。** 翻回来的每一条都是「谁 · 什么时候 · 在哪个会话 · 说了什么 · 字在哪 · 来源」，不是事实、不是摘要、不是标签。常驻的称呼/承诺/偏好**不是翻来的**，是直接读的一行。

### 4.1 六原语（唯一取数方式）

| 原语 | 一句话 | 典型问法 |
|---|---|---|
| `search(q)` | 词法 + 向量融合 | 「某市那个银行的事」 |
| `near(vec)` | 纯向量近邻 | 「类似上次那种情况」 |
| `read(id, ±N)` | 读这条 + 上下文 | 「上面那句到底是什么」 |
| `list(filter)` | 按时间/人/类型框范围 | 「昨天下午P6说的」 |
| `open(attachment)` | 读附件正文 | 「那份课表里第几周」 |
| `fetch(url)` | 抓网页（结果落成新原文行） | 「这个链接讲的什么」 |

三条纪律：

1. **返回形状统一**：每条都带 `event_id` + 原文片段 + 时间 + 说者 + 来源 + 字位置——判不需要为不同来源写不同分支；
2. **喂给判的 ≤2 条**：多的在代码侧截断并标注被截；
3. **翻不到就说没翻到**：返回空，不许拿「最像的那条」顶替。

### 4.2 什么时候翻（这条规则属于判，但上限属于这里）

| 谁定 | 定什么 |
|---|---|
| 判（依据世界面） | 这一回合有没有解析不出的指代（`unresolved`）；有才翻 |
| 这里 | 一次最多 2 条；翻不到就返回空；不许扩词、不许改写查询 |

### 4.3 候选区（纸片，未转正）

| 项 | 值 |
|---|---|
| 谁写 | 判每回合 0~3 条（`remember`） |
| 算不算记住 | **不算** |
| 过期 | 7 天丢掉 |
| 转正三扇门 | 人批准 / 她明说「记下来」/ 同一件事在原文出现 ≥3 次且一致 |
| 只记三类 | 会被再次指代的名词、未兑现的承诺、被纠正过的事实 |

### 4.4 推送的是索引，不是正文（2026-10-23，`082c346`）

推正文有两个代价：一是**推了就占满窗口**（条数上限变成了窗口上限）；二是**她到底看没看过那条**
在日志里无从判断。改成推索引之后：「要不要看」还给她，日志里有 `read_memory` 这一行可查；
正文一句都不丢，随索引落进 `extra["memory_index"]`（key / memory_id / content / occurred_at /
speaker / source_event_ids / preview），只进留痕、不进 prompt。

两个口径容易写反，记在这里：**key 是每回合重新编号的**（`m1` / `m2` 只在这一轮的索引里有效，
跨回合要重新查，别当成稳定 id）；退路是 `YINYUE_MEMORY_INDEX=off`，回到整段正文注入。

## 4.5 什么能改变它（写入路径）

| 板 | 什么能改变它 | 谁 | 改的形式 | 改不动它的（明令禁止） |
|---|---|---|---|---|
| ① 原文板 | 账本多一行 | **落屏闸门（代码）** | 追加（只增不改）；撤回/改口/补录都成**新行** | 人改旧行、判或模型直接写原文、渲染层补字 |
| ② 索引板 | 原文板变了 / 有人手工重建 | 索引器（代码） | 全量重建或增量；整层可删 | 人手工编辑索引内容（只能删/重建） |
| ③ 常驻板 | 人加/改/删一条 | **只有人** | 直接改（带依据·写入方式·复核日） | 判或模型直接写；情绪/人设反推 |
| 候选区（纸片） | 判每回合写 0~3 条 | 判（模型） | 追加，7 天过期；**不算记住** | 直接进 ③（必须过三扇门） |

### 四条容易搞错的规则

**1. 记忆只追加，从不改写。**

| 场景 | 正确做法 | 错误做法 |
|---|---|---|
| 她说错了、要改口 | 追加一条新原文「说错了，是第 9 周」 | 改掉上一条的行 |
| 用户撤回了一条消息 | 原行保留 + 追加「（已撤回）」 | 删掉原行 |
| 补录历史消息 | 追加，带 `补录标记` 与**同一套入库序号** | 插到中间、另起一套序号 |

**2. 读不会改变任何板。** 检索、`read(id, ±N)`、`open(attachment)` 全是只读；唯一允许变的是「这条被用过几次 / 最后一次用是什么时候」——那是**旁注**，不改原文行。

**3. 常驻只能靠人改，或靠三扇门转正。** 判写的东西停在候选区，7 天不动就丢；转正必须满足其一：人批准 / 她明说「记下来」/ 同一件事在原文出现 ≥3 次且一致。

**4. 删除是受控的，不是随手 DROP。**

| 删什么 | 允许吗 | 怎么做 |
|---|---|---|
| 原文行 | 只能人主动删（用户要求） | 受控入口 + 逻辑删除 + 必留审计；引用处显示「已删除」；物理清除只在归档期后 |
| 索引 | 允许 | 直接丢，重建即可 |
| 常驻一条 | 允许 | 人删，留审计 |
| 候选一条 | 不用删 | 7 天自然过期 |

### 谁能审计

每条原文行都带时间、会话、说者、字位置、来源；每次检索结果都能回到具体某一行。**「她说的这句话是从哪来的」永远要有答案**——答不上来，就说明有人在改写记忆。

## 5. 进来的是什么 / 出去的是什么

| | 进来 | 出去 |
|---|---|---|
| ① 原文板 | 账本投影；摄取（附件正文 / 网页正文 / 梗）经账本写入 | 原文行 |
| ② 索引板 | ① 的全量 | 命中行号与分数（只给 ① 用来排序） |
| ③ 常驻板 | 人（`memory add/edit/rm`） | 一行读数（称呼/承诺/偏好/事实） |
| 候选区 | `remember(0..3)` | 过三扇门后进 ③ |
| 对判 | — | 推送 `[事件记忆·索引]` ≤6 条（key + 时间 + 说者 + 36 字开头）；正文按 key 用 `read_memory(keys="m1,m3")` 取，单次 ≤4000 字 |

## 6. 大小

| 组成 | 体量 | 为什么这么大 |
|---|---|---|
| ① 原文板 | 0 额外存储 | 是账本的视图 |
| ② 索引板 | 可整层删；重建成本分钟级 | 全部是派生数据 |
| ③ 常驻板 | ≤200 条 / ≤4k token | 少而稳，人才改得动 |
| 候选区 | ≤7 天 · 每天最多几十条 | 漏斗，不是仓库 |
| 推送索引 | ≤6 条 / 每条 ≤36 字开头 | 索引不占窗口，正文按需取 |

**没有**：事实表、情节表、关系图、摘要库、第二个向量服务。

## 7. 边界（它明确不管什么）

| 不管 | 归谁 |
|---|---|
| 该不该翻、翻几次 | 判（用 `unresolved` 判定） |
| 存多久、怎么删 | 账本 |
| 谁在回谁 | 账本给平台事实；推断不在这里 |
| 这一屏显示什么 | 世界面 |
| 情绪/态度/人设 | 自我立方体 |
| 怎么发出去 | 出口 |

## 8. 意义

没有它，她只有「这一屏」——一旦被问到屏外的事，只有两个选择：编，或说不知道（而她往往选择编）。

有了它，她能说出两句话里的一句：

- 「我翻到了：22:15 P5问的那个文件是 `课表_第8周.xlsx`」
- 「我这儿没翻到。」

这两句都比编造好。**记忆的价值不在于「知道很多」，而在于「知道自己不知道」。**

## 9. 量具

| 指标 | 口径 |
|---|---|
| 命中率 | `hit@1 / hit@3`（人工标注题集，代码直取为基线） |
| 翻不到率 | `search_miss / 翻次数`（高说明窗口或索引有问题） |
| 该翻没翻 | 人工判「该查却没查」的回合占比（≤10%） |
| 误翻率 | 翻了但没用上的回合占比（只观测） |
| 候选转正率 | 7 天内转正 / 候选总数（低说明记的没用） |
| 常驻膨胀 | 条数与 token 双口径（200 条 / 4k） |
| 重建一致率 | ② 重建后同一查询结果逐条相同（100%） |

## 10. 不做

- 不建第二份原文、不建事实/情节/关系表；
- 不做写时分类（梗、承诺、事实只是 `来源` 不同，不是不同类型）；
- 不自动扩词、不改写查询；
- 不把全量历史塞进提示词；
- 不用「最像的那条」顶替没翻到；
- 不起第二个数据库/向量服务；
- 不让判直接写 ③（只能写候选区）。

## 11. 已定（原「未定」五条，2026-10-19 拍）

| # | 项 | 结论 |
|---|---|---|
| 1 | ② 向量索引放哪 | **进程内**：npz 文件 + numpy 暴力余弦（实测 1.1 万行毫秒级；`core/memory/local_embed.py` 已上线）。不引独立向量服务 |
| 2 | 网页（`fetch` 结果）是否进常规检索 | **不进**。只作为显式目标 `search_memory(scope="external")`，或本回合临时材料；理由：网页会稀释内部原文排序，且不可验证、易过期 |
| 3 | 群外梗是否进常规检索 | **不进**。只作风格素材（判想玩梗时显式搜一次）。实测 2111 条梗库与群内话题零交集，常规召回只加噪 |
| 4 | ③ 上限按条数还是 token | **token 先到先限**（单项 ≤120 token、总 ≤400），条数上限 ≤6 只作兜底。token 才是真预算，一条长文能顶六条短句 |
| 5 | 候选区「≥3 次一致」怎么判 | **同 `(kind, key)` 归一化后相同 + 值语义等价**，且必须来自**不同外部消息号**——同一条消息重复触发不算 3 次，否则一次复读就凑满转正条件 |
