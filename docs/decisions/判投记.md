# 判 / 投 / 记（唯一有模型的地方）

> 本文只写**语义与边界**：输出结构/字段名以 `判投记_契约.md` 为准，重复定义视为 bug。

> 依据：`output/3d/viewer_css.html` 中央那块 560×560 的板（贴图 `t_llm.png`），以及紧挨着它的四样东西——下方 **留痕条**（`t_trace.png`）、再下方 **账本板**（`t_ledger.png`）、右侧 **出口**（`t_exit.png`）与 **软件·适配器**（`t_soft.png`）、右下 **工具包**（含 `t_toolbox.png`）。
> 四问先答：**图上是哪块** = 中央板；**进来什么** = 三面读数 + 两个可空槽位 + 工具清单；**出去什么** = 契约产物（§3）+ 判决行（每回合）/ 完整留痕（仅开口）；**职责** = 全系统唯一的决策点。
> 细则：`判投记_契约.md`（输入输出契约、五问、量具）。本文只管**边界与语义**。

## 1. 图上位置

```
                              ┌────────── 判 / 投 / 记 ──────────┐
  read_screen()  ───────────> │ 唯一有模型的地方                 │
  get_state()    ───────────> │ 读三面 → 交结构                  │ ──投──> 出口 ──投递──> 软件·适配器
  search_memory() ──────────> │                                  │
  run_tool()     ───────────> │                                  │ ──记──> 候选区 / 自我（只由后果）
                              └───────────────┬──────────────────┘
                                              │ 每回合一行
                                              ▼
                                        留痕条 → 账本
```

| 与谁相连 | 方向 | 说明 |
|---|---|---|
| 世界面 | 进（`read_screen`） | 这一屏原文，必填 |
| 自我立方体 | 进（`get_state`） | 情绪事件清单 / 态度事实 / 人设约束（读数，必填） |
| 记忆立方体 | 双向 | 进 = ≤2 条原文（可空）；出 = `remember` 0~3 条 |
| 工具包 | 进（`run_tool`） | 只取料：搜网/读附件/看图；执行永远在代码侧 |
| 出口 | 出（`投`） | 说与做都从这里出去，它只放行不判断 |
| 账本 | 出（留痕一行） | 只增不改，可重放 |

## 2. 板上写的三段（输入 / 产出 / 纪律）

```
输入  看  世界面：这一屏原文 + 谁在回谁
      查  自我：情绪 / 态度 / 人设约束（只读）
      翻  记忆：解析不出才翻，≤2 条带出处；翻不到就说不记得
      用  工具：只取料（搜网 / 读附件 / 看图），每回合 ≤2 次
      办  在手的事：办到哪一步 / 在等什么（≤3 条，每条 ≤60 字；没有就空着）
产出  reading   先复述（这一屏在说什么、谁对谁说）
      decision  接 / 不接 / 只反问 / 弃权
      deliver   说与做，0~2 条（kind 由出口注册表决定）
      memory    0~3 条便签（进候选区，不算记住）
      plan      一件事的下一步（≤1 次；花钱 / 不可逆要先拿批准）
纪律  指不回原文就弃权
      沉默只留判决，不留全文
      说与做都是投递
      不写原文、不改旧行、不打分类标签
```

## 3. 产出结构与一致性（字段定义见 `判投记_契约.md` §2，这里只写语义）

| 段 | 类型 | 何时出现 | 说明 |
|---|---|---|---|
| `decision` | 枚举 | 每回合 | `respond` / `ask` / `silent` / `abstain` |
| `deliver` | 列表 0~2 | respond / ask 必须非空 | `{kind, text?, file?, target?, basis}`；`kind` 由出口注册表决定 |
| `basis` | 列表 | respond / ask 必填 | 指回这一屏的行号 / 记忆 id / 工具 id |
| `reading` | 文本 | 仅 respond / ask | 先复述再判断；复述内容必须能在这一屏里找到 |
| `open_loop` | 对象 | 有未结事时（≤1） | `{want, have, missing, next, due?}`；`missing` 用自然语言 |
| `memory` | 列表 0~3 | 可空 | 便签，进候选区 |
| `plan` | 对象 | 在办一件事时（≤1） | `{job_id?, goal, steps[], awaiting}`；**不是执行**，发出去仍经出口且需批准 |

`gap` 不再是字段：缺什么由**工具调用**表达（见 §4）。

一致性由代码校验，模型不能自圆其说：

| 规则 | 违反即拒 |
|---|---|
| `respond` / `ask` ⇒ `deliver` 非空 | 是 |
| `silent` / `abstain` ⇒ `deliver` 必须为空 | 是 |
| `say` 每轮最多 1 条；`say` 伴随动作时 ≤40 字且不带自己的 @ | 是 |
| `deliver` 里出现未注册的 `kind` | 是（回答「这件事我现在做不到」） |

## 4. 有界：预取 + 最多一次回补

| 预算 | 上限 | 为什么 |
|---|---|---|
| 模型调用 | 2 次（首次 + 一次回补） | 我们没有测试可验证；多一轮只是多一次盲猜 |
| 记忆取用 | ≤2 条 | 多了会挤掉答得对的内容（实测注入多塞使 exact 83.3% → 66.7%） |
| 工具调用 | ≤2 次 | 只取料，不做多步探索 |
| 回合时长 | 秒级 | 聊天是秒级的，社交成本比正确率更硬 |

顺序：代码先算「解析不出的指代」→ 非空就预取 1~2 条 → 一次调用出这套结构 → 只有模型确实调了检索工具且仍为空，才允许回补一次。

## 4.5 什么能改变它（写入路径）

**判板本身没有状态**：每回合重算一次，回合结束什么都不留（除那一行留痕）。所以「它变了」只有四种原因：

| 能改变它的 | 谁 | 形式 |
|---|---|---|
| 这一屏变了 | 世界面 | 输入不同 → 读数不同 |
| 自我读数变了 | 自我立方体 | 上一行、上一句都可能不同 |
| 工具清单/契约版本变了 | 人（配置） | 能请求的动作集合变化 |
| 模型与参数变了 | 人（选型） | 温度/模型/思考档 |

**改不动它的**：

| 禁止 | 为什么 |
|---|---|
| 跨回合「记住」上一轮的判断 | 它是无状态的；要记住只能写进留痕或候选区，不能塞进模型上下文当事实 |
| 模型自己改契约 | 输出格式由代码校验，不由模型声明 |
| 模型自评「有把握」 | 不可判定；只认 `basis`（能不能指回原文） |
| 用上一轮的读数当这一轮的输入 | 自我读数每轮重新取，不吃缓存 |

### 4.5.1 判能改变什么，不能改变什么

| 判能改变 | 怎么改 | 谁真正落笔 |
|---|---|---|
| 出口的投递（说 / 发图 / 发文件 / 提醒） | `deliver` 0~2 条 | 出口 + 软件适配器（**代码**） |
| 候选区便签 | `memory` 0~3 条 | 记忆立方体（**代码**写入） |
| 这一回合的留痕 | 判决行 / 完整留痕 | **代码**写进账本旁注（只增不改） |

| 判**不能**改变 | 为什么 |
|---|---|
| 账本原文、索引 | 只追加，写者是落屏闸门 |
| 常驻记忆 | 只有人能改；判只能写候选区 |
| 人设 | 只有人能改 |
| **情绪 / 态度本身** | 判只能提「一条事件」或「一条事实」，必须带 basis；代码校验后追加，**没有数值可改**（见 `自我立方体.md` §4.5–§4.6） |
| 世界面 | 是渲染结果，不是判写的 |

一句话：**判只产「决定」，代码负责落笔。** 它没有 setter，只有输出。

**它提议的事件长什么样**（代码只校验四件事：有 basis、维度合法、同(消息,维度)没记过、档位合法）：

```json
{"about": "P5", "fact": "说项目做完了，实际没有", "weight": "中", "basis": ["e5012"]}
{"what": "被说人机", "about": "P5", "weight": "中", "basis": ["e5180"]}
```

档位只有 `轻 / 中 / 重`（判据见 `自我立方体.md` §4.6.1）；读数由代码现算，不写回。

## 5. 判的五问（不是分类器）

| 问 | 不通过的结果 |
|---|---|
| 有人在等我吗 | `silent` |
| 话题连着吗 | `silent` |
| 我有具体一句可说吗 | `silent`（说什么都像人机，就别开口） |
| 我能不能参与（需要身体/身份/权限吗） | `silent` |
| 代价值得吗（吵到别人 / 打断正事） | `silent` |

五问不是五个 if 判断，是模型读原文后自己回答的问题；代码只校验输出形状与 `basis` 可指回。

## 6. 弃权（abstain）

| 情形 | 输出 |
|---|---|
| 解析不出指的是什么 | `abstain`；同轮最多调一次检索，仍空就放弃；不写 `gap` 字段，缺什么由那次调用表达 |
| 需要的能力没注册 | `abstain` + 「这件事我现在做不到」 |
| 判断不了该不该接 | `abstain`（不是猜一个） |

目标区间：弃权率 **5%~15%**。低于 5% 说明它在硬答；高于 15% 说明输入太差。

## 7. 投（说与做都是投递）

| kind | 例 | 谁执行 |
|---|---|---|
| `say` | 一句话（可带 @） | 出口 → 软件适配器 |
| `sticker` | 发个表情包 | 同上 |
| `file` | 发文件 | 同上 |
| `reminder` | 定时提醒 | 同上（到点再由代码触发） |

三条硬规矩：

1. **能做什么由出口注册表决定**，模型只能从清单里选；清单外的请求一律拒绝并说明；
2. **同轮 ≤2 条**，`say` 最多 1 条；
3. **say + 动作** 时 `say` 是伴随语（≤40 字、不带自己的 @），且必须指向同一件事。

## 8. 记（只写候选区）

| 项 | 规则 |
|---|---|
| 数量 | 0~3 条，**允许 0 条** |
| 写哪 | 记忆立方体的候选区（不是常驻板） |
| 只记三类 | 会被再次指代的名词 / 未兑现的承诺 / 被纠正过的事实 |
| 不算记住 | 7 天不动就丢；转正需过三扇门 |

## 9. 进来什么 / 出去什么

| | 进来 | 出去 |
|---|---|---|
| 必填 | 世界面（这一屏）、自我读数 | — |
| 可空 | 记忆索引 ≤6 条、工具结果、工具清单、情绪 / 态度读数（工具拉取） | — |
| 产物 | — | 契约产物（§3）+ 判决行（每回合）+ 完整留痕（仅开口/动手） |
| 副作用 | — | 投递（出口）、候选便签（记忆） |

## 10. 大小（进提示词的预算）

| 段 | 预算 |
|---|---|
| 世界面 | ≤3600 字符（约 1500 token） |
| 自我读数 | ≤200 字 |
| 记忆索引 | ≤6 条（每条 36 字开头）；正文只在 `read_memory` 时进（单次 ≤4000 字） |
| 工具清单 | ≤6 个 schema，约 250~350 token |
| 工具轮 | ≤ 1024 字（`YINYUE_TOOL_LOOP_BUDGET_CHARS` 可调，下限 200） |
| 输出契约 | 固定约 300 token |

**超了怎么办**：把**早前**轮压成 `[早前工具轮·摘要]`（「调了什么 → 拿到什么（含关键参数）」+
「细节已压掉，要用就按参数再查一次」），**最近一轮永远原样留着**。理由是直接删她不知道自己
查过什么，会原地重查——宁可留一句查过什么，也不让她原地重查。

## 11. 边界（明确不管）

| 不管 | 归谁 |
|---|---|
| 存原文 | 账本 |
| 这一屏显示什么 | 世界面 |
| 检索怎么排序 | 记忆立方体 |
| 怎么发出去、重试、回执 | 出口 / 软件适配器 |
| 人设写什么 | 人（人设层） |
| 情绪/态度怎么变 | 事件追加 + 读时现算（时间窗 + 排序，不算数值） |

## 12. 意义

全系统只有这一块板里有模型。它的意义有两面：

| 面 | 含义 |
|---|---|
| 权力 | 只有它决定「说不说、说什么、做什么」 |
| 责任 | 每一句都能指回原文；指不回就弃权——这是没有测试可跑时唯一的质量保证 |

反面：把它降级成分类器（先打标签再按标签走），判断力就没了；前面所有量具都验证过这一点。

## 13. 量具

| 指标 | 目标 |
|---|---|
| `basis` 覆盖率（有依据的输出占比） | ≥90% |
| 弃权率 | 5%~15% |
| 该翻没翻 | ≤10% |
| 无依据断言 | ≤5% |
| 重复开口（同一件事连说两遍） | ≤10% |
| @ 命中率（点的人对不对） | ≥90% |
| `reading` 与人工标注一致率 | ≥80%（每 50 条抽一次） |

## 14. 不做

- 不做分类器（不先打标签再走分支）；
- 不让模型自评把握；
- 不让模型写原文、改旧行；
- 不让模型直接写常驻记忆；
- 不给自由工具循环（≤2 次、预取优先）；
- 不省掉**判决行**；但沉默回合不写完整留痕（只留判决）。
- 不设 `gap` 分类字段（缺什么由工具调用表达）。

## 15. 未定

1. 留痕保留多久（永久 / 90 天 / 抽样永久）；
2. 一次回补是否保留（现在设计为保留，但可关）；
3. 弃权要不要显式说一句（「我这儿没搞明白」vs 直接沉默）；
4. 五问里「代价值得」能不能读限流器读数（会引入代码状态进模型）；
5. `deliver` 的 `target` 与出口注册表的匹配失败时，是弃权还是降级为 `say`。
