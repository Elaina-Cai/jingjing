# 人设层：存储与读取

> **状态（2026-10-20）：本文档描述的是规范层（版本化、不随经历变、只有人能改），与 `自我立方体.md` 的「人设铭牌」一致，仍为实现依据。**

> 同体例：`情绪层_存储与读取.md`（会话状态）、`态度层_存储与读取.md`（人物状态）。三篇都是「口吻的原料」，不是口吻本身（见 §5）。

## §0 一句话

人设是**主人通过 WebUI 声明的规范**，不是从行为里统计出来的状态：存成不可变版本，绑定层可按版本钉住，读侧只读「选中的那一版」，不衰减、不进证据层。

## §1 边界（五条）

1. **是规范不是状态**。不会被最近三句话改写，不衰减；它给的是上下界与禁忌，不是每句的模板。
2. **写者只有一个：主人**（WebUI 编辑，或 `configs/speech_seed/persona_yinyue.json` 种子）。系统可以提议，发布权在主人。
3. **版本不可变**。改动产生新版本，旧版本留着，回退不改内容只改指针。
4. **一轮只读一份**。选定哪个 `version` 就用哪个，同一轮不混版本。
5. **关系惯用法不属于人设**。「叫她什么、哪些梗能复用」跟具体一个人绑定，属关系史（`person_notes` 一类）。

一句话读法：**编辑器改草稿行 → 保存即快照成不可变版本 → 绑定（或默认 latest）选出这一版 → 读侧只认这一版。** 眼下这条链的活口是「唯一绑定没 pin」，所以 latest 就是线上。

## §4 四处缺口（都有上面的真数据作证）

1. **保存即发布，没有草稿与审核闸**。51 个版本里 39 次是 `reimport_speech_seed` 批量重导入；UI 一保存也立刻出新版本。因为唯一绑定没 pin，**任何一次保存/重导入都立刻成为线上人设**。
2. **版本之间没有 diff 与原因**。只有 `created_by`（标记）与 `created_at`；`personas.created_at` 还是 NULL。答不出「v3 比 v2 差在哪、为什么改」。
3. **没有「全局默认版本」这一表达**。默认吃 latest ⇒ 改一个字全体迁移。要么给默认版本一个显式指针，要么强制显式 pin。
4. **关系惯用法挤在全局规范里**。`voice.address` 现在写的是「称主人为『主人』（仅私聊）；群里对任何人用『你』或名字」——把「按会话分叉的称呼」塞进了全局字段；真正按人绑定的称呼（叫她什么）应在关系史。

## §5 三篇合起来是不是「口吻」

不是口吻本身，是**口吻的原料**；产物是一段可读的约束，不是一张分类表。

- 三篇分别回答：她此刻的心情（情绪，会话级）、她对这个人的态度（态度，人物级）、她是谁且不许怎样（人设，全局规范）。
- 合起来的产物只有一样：**一段口吻约束**（温度、长度、耐心、主动度、解释倾向、称呼、禁忌），随 prompt 注入。（2026-10-23 起：随 prompt 注入的只有人设这一层；另两层的读数改成按需拉取，见 `自我立方体.md` §7。）
- 其余四项（这一句要干什么 / 场合 / 关系细节 / 语音还是文字）**不需要再建模**：生成器手里的既有上下文已经包含——回复意图、窗口里的在场人与公开度、关系笔记、工具选择。把它们写进公式只会误导成「还要再建四层」。
- 一句话：`口吻约束 = compose(情绪, 态度, 人设)`，然后交给生成器。不要为口吻建枚举表（穷举路线在本项目已证伪两次：召回题型闸门、指代通道）。
