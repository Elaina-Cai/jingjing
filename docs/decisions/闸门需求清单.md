# 闸门需求清单（重新设计前置，R0）

> 目的：删闸门之前，先把「每个闸门当年到底在防哪一起事故」翻成需求。
> 闸门可以删，需求不会消失——需求消失才会。删之前先回答：这条需求由谁接。

## 0. 四个承载位

| 位 | 含义 | 判据 |
|---|---|---|
| **模型** | prompt 里给足事实，让它自己判 | 这是"读语义"，代码只能猜 |
| **代码** | 确定性事实 / 物理边界 | 这里没有语义，只有"是不是、能不能" |
| **审计** | 只记账、不拦、不改 | 需要量具观测，但拦了会误杀 |
| **删** | 需求本身不成立 | 当年防的事已被别处解决，或压根不是问题 |

标注：**V**=有否决权（能让她不说话/不发送）　**R**=改写文本　**A**=只审计

## 4. 五起事故地图（重新设计的红线）

这五条是"删了会重演"的部分，不是"删了会变笨"的部分：

1. **她停止回答**（位置门/b4 的由来）——"宁可少拦，不可误杀"是当年定的红线。任何新设计都不能出现"整晚不说话"。
2. **把自己说成第三方**（2026-09-24）＋**反方向的误认领**（2026-09-30）——双向都会错，所以它必须是确定性代码，不能只靠 prompt。
3. **@错人连续复发**（2026-10-01 19:30）——根治方向是"理解层给结论、出口只渲染"（R14），不是"出口再猜一次"（R13）。
4. **复读机刷屏**（批D）——零 token 前置闸，成本意义大于语义意义。
5. **否定翻转**——判据自承没有语义主语，属于该交模型的一类。
