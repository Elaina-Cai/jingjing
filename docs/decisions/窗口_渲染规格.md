# 窗口（工作记忆 / 情景缓冲）渲染规格 v0.2

状态：设计定稿（2026-10-18）。只定「她这侧看到的一屏长什么样」，不定下游怎么用；未落码、未改动任何现有渲染路径。

v0.2 = v0.1 全量保留 + 穷举补齐（引用、媒体、钱、通话、群务、异常、未知类型）。凡是能出现在一屏里的东西，这里必须查得到写法；查不到的，写进「11. 未定项」，不许临场发明。

## 0. 一句话

窗口 = 某个会话（群或私聊）最近的一段对话，按平台自己的样子排好、放进有界预算里，只呈现事实与平台会显示的东西；任何判断、摘要、推断都不进这一层。

## 1. 边界（铁律）

1. 可见性判据：把同一份平台原始数据交给平台自己的界面，用户能看到什么，窗口就显示什么。需要解析、推断、只有本系统知道的东西，一律不进窗口。
2. 渲染器是哑的：取字段 -> 排版。不做匹配、不做解析、不做推断、不读 now()、不访问网络。
3. 可重建：窗口 = f(事件流后缀)，纯函数；同一输入重放必须逐字相同。
4. 有界：预算满了从最早处逐出（滑出窗口不等于销毁，事件流里仍在）。

### 四处已裁决的口径（2026-10-18 用户拍板）

| # | 事项 | 结论 |
|---|---|---|
| 1 | 超长正文 | 不折叠，完整显示（窗口可以被一段长文占满，不截断） |
| 2 | 过期/已清理的媒体 | 显示 [图片：已过期]，其余类型同构，不假装还在 |
| 3 | 语音转文字 | 平台给就显示：[语音 n″｜转文字：…] |
| 4 | 匿名 / 机器人 / 群名片 | 平台显示什么就写什么（匿名写 匿名，机器人写平台给的名字），不写出真实 id |

## 2. 单位与生命周期

- 窗口属会话，不属人：(platform, account_id, chat_id) 一个窗口；群成员不各占窗口。
- 潜在窗口数 = Σ(平台 × 会话数)；只有「热」会话常驻内存，温/冷按需重建。
- 生命周期：事件落库 -> append 到窗口 -> 渲染 -> 预算逐出；重启从事件流重放，结果逐字相同。

## 3. 行模型（一行 = 一个事件）

| 字段 | 含义 | 说明 |
|---|---|---|
| time | 事件时间 | 渲染成 HH:MM；跨天另起分隔行 |
| actor_display | 显示名快照 | 渲染时写死的那个名字；改名/改群名片不改写历史行 |
| actor_role | self / other / system | self 渲染成 我（微信）/ 你（QQ） |
| kind | 事件类型 | message / pat / recall / join / leave / kick / notice / card / money / call / flash / signin / homework / vote / chain / file / deleted / unknown |
| body | 正文 | 原样，含 emoji；不含任何拼装出来的判断 |
| quote | 引用块 | 只有平台给了引用才有；at_body（我们自己解析的）不进窗口 |
| media | 媒体占位 | 类型 + 描述（来自标注层）；过期走 该类型+已过期 |
| money | 红包/转账/群收款 | 见 4.6 |
| system | 系统事件 | 撤回/轻拍/群务/钱财流水/通话结束 |

三条硬约束：

1. 一行只对应一个事件；一条消息里同时有正文、媒体、引用时，仍是**一行**（内部按 4.3/4.5 的顺序拼）。
2. `actor_role=self` 时名字列写 **我**（微信）/**你**（QQ），不写她自己的昵称。
3. 任何字段缺失都不许「补一句自然语言」解释；缺就空着（见 4.12）。

## 4. 渲染规则

### 4.1 每行骨架

    HH:MM  <名字，10 列宽>  <正文>

- 列宽按「东亚宽字符算 2 列」计算（emoji、中文都算 2 列）；名字超 10 列时占满并右补空格，不截断。
- 续行缩进对齐正文列（1 + 5 + 2 + 10 列 = 正文从第 19 列起）。
- 自己发的消息与别人同格式（平台不给「我」加框，我们也不加）。
- 正文里的 emoji 属文字，原样保留。

### 4.2 系统行

以两个点起头，名字位置放事件主体，不占「说话人」语义：

    08:24  ..李湛    撤回了一条消息
    08:22  ..P5    拍了拍 我
    08:27  ..系统    「P5」邀请「阿澈」加入了群聊
    12:01  ..系统    P5 领取了 P5 的红包

规则：`..` 后面紧跟的那个名字是**事件主体**（撤回的人 / 拍的人 / 被移出的人 / 系统），不是这条消息的作者；所以它不进 `actor_display` 的语义，也不用「我」替换（自己就是 `..我` / `..你`）。

### 4.3 引用块（基本形状）

形状统一 `┃ 被引者：被引内容`，位置分平台：

- 微信：正文**下方**，单起一行
- QQ：正文**上方**，与正文同属一条气泡

```
08:31  李湛      这个谁写的
                  ┃ Elaina：[图片]
```

- 被引内容过长：以 `……` 截断（这是引用块内部的必要截断，不是第 1 节那条「正文不折叠」）。
- 被引内容含换行：引用块内保留换行，续行缩进到被引内容的正文列（相对 `┃ ` 再缩进 2 列）：

```
08:32  P5      我不同意这个结论
                  ┃ 李湛：今天的实验数据我重新跑了一遍，
                    把 batch 调成 12 之后……
```

- 引用一条系统行/拍一拍/通话记录：平台本身不提供这种引用，窗口**不造**（见 4.4.5）。
- 引用块里的媒体只落占位（`[图片]` / `[表情包]` / `[视频 00:07]`），不带描述、不带过期状态（完整穷举见 4.4）。

### 4.4 引用（穷举）

#### 4.4.1 什么算「能引用的」

- 判据：**平台客户端允许长按/右键「引用」的对象**，才是可引用对象。
- 窗口只承认平台自己给的引用字段（微信 `quote_reply`／QQ `qmsg`）；没有这个字段就**不造**引用。
- 一条消息的**任何内容类型**都可以被引用（文字/图片/表情包/语音/视频/文件/链接/位置/名片/小程序/直播/聊天记录/接龙/投票/作业/红包/转账/群收款/闪照/匿名/机器人）。
- **不可引用**：系统行（撤回提示、拍一拍、入退群、被移出、群主/管理员变更、群公告、群名片修改、签到、作业上传提示、群文件上传提示、闪照销毁提示、跨天分隔行）、通话记录、跨天分隔、窗口分隔。

#### 4.4.3 引用自身坏掉的形态（穷举）

| 情形 | 写法 |
|---|---|
| 引用字段在，但被引内容取不到（跨库/已被清理） | `该消息已不可见` |
| 被引者没有显示名（陌生人/未同步） | 被引者写 `未知成员` |
| 被引者显示名超长（>10 列） | 不截断名字，整行按宽度折行 |
| 被引内容只有空白字符 | `该消息为空` |
| 同一条被引消息被多人引用 | 各自独立显示，不合并、不写「被引用 3 次」 |
| 跨平台引用（微信数据里出现 QQ 引用，或反之） | `该消息已不可见`，并记一条异常（数据错误，不猜） |

#### 4.4.4 引用块的排版细则

- 起点：`┃` 起于正文列（第 19 列）；该条消息正文为空时，引用块仍从正文列起。
- 微信：引用块在正文**下方**，紧贴下一行，不插空行。
- QQ：引用块在正文**上方**，与正文同属一条气泡，正文另起一行的正文列。
- 被引内容单行超过 60 列 → 截断 + `……`；多行最多 3 行，第 4 行起 `……`。
- 被引内容里的媒体按 4.4.2 的「引用块显示」列写（**不带**描述、**带**过期/销毁状态）。
- 引用块只出现一次，不重复；正文里再出现同样的 @ 或引用文字，按正文原样显示。

#### 4.4.5 不允许的引用（写下来防复发）

1. `at_body`（我们从正文里 grep 出的 @）→ 不进引用块，它属标注层 `parsed_at_body`。
2. `inferred_target`（我们推断「在回谁」）→ 绝不写成 `┃`。
3. 系统行 / 拍一拍 / 通话记录 / 群公告 / 签到 / 跨天分隔 → 平台不提供引用，不造。
4. 跨平台引用 → 不存在，按 4.4.3 处理。
5. 「引用副本」只能来自平台字段；**不许**因为我们「知道上一条是什么」就补一个引用块。

### 4.5 媒体占位（穷举，含退化态）

| 类型 | 正常 | 退化 |
|---|---|---|
| 图片 | `[图片：<标注层描述>]` | 无描述 `[图片]`；已过期 `[图片：已过期]`；加载失败 `[图片：加载失败]`；发送失败 `[图片：已过期] [!发送失败]` 不出现，改为行尾 `[!发送失败]` |
| 表情包 | `[表情包：<主题/情绪>]` | 无描述 `[表情包]`；已过期 `[表情包：已过期]`；已下架 `[表情包：已下架]` |
| 语音 | `[语音 7″]` | 无时长 `[语音]`；有转写 `[语音 7″｜转文字：…]`；转写失败 `[语音 7″｜转文字失败]` |
| 视频 | `[视频 00:12]` | 无时长 `[视频]`；已过期 `[视频：已过期]` |
| 文件 | `[文件：计组实验报告模板.docx  38.2 KB]` | 只有名字 `[文件：计组实验报告模板.docx]`；已过期 `[文件：已过期]`；缺名字 `[文件]` |
| 闪照（QQ） | `[闪照 · 阅后即焚]` | 已销毁 `[闪照：已销毁]`（随后一行 `..系统 闪照已销毁`） |
| 位置共享 | `[位置共享：正在共享 · 3 人]` | 已结束 `[位置共享：已结束]` |

规则：

- 图片/表情包的描述来自**标注层**（异步、每张一次、按内容哈希去重、版本化），不是平台字段；它不改 `content`、不动偏移，窗口只是把它显示出来。
- 正文里的 emoji 属文字，原样保留；`[表情包：…]` 才是表情包。
- 描述里出现换行 → 压成空格；描述超过 40 列 → 截断 `……`（媒体占位是一行，不折行）。
- 媒体占位永远是**一行**：`[图片：…]` 不折行，正文才折行。

### 4.6 钱（穷举）

**红包**：一行卡片 + 逐条领取流水（群）/ 无流水（私聊）。

    12:01  P5      [红包] 恭喜发财，大吉大利 · 8 个 / 共 20.00 元 · 已领完
    12:01  ..系统    P5 领取了 P5 的红包
    12:02  ..系统    P5 的红包被领完，李湛 手气最佳 12.40 元
    12:03  ..系统    红包已过期，5.00 元已退回

红包状态：`待领取`（不写，卡片本身就是待领取）/ `已领完` / `已过期，n 元已退回` / `已取消`。

**转账**：点对点；群内写 `→ 收款人`，私聊不写。

    12:05  鲸鲸      [转账 30.00 元 → 李湛 · 待收款 · 备注：上次的饭钱]
    12:06  ..系统    李湛 已收款
    12:07  鲸鲸      [转账 5.00 元 → P5 · 已退还]
    12:08  鲸鲸      [转账 5.00 元 → P5 · 已过期，已退回]

转账状态：`待收款` / `已收款` / `已退还` / `已过期，已退回` / `已取消`；备注长在卡片里，不单独成行。

**群收款**：

    12:09  P5      [群收款] AA 聚餐 · 6 人 / 共 300.00 元 · 已收 4 人
    12:10  ..系统    Elaina 支付了 50.00 元
    12:11  ..系统    群收款已结束，已收 300.00 元

群收款状态：`进行中（已收 n 人）` / `已结束，已收 m 元` / `已过期，已退回` / `已取消`。

    [屏幕共享 12:03 · 已结束]          [聊天记录：3 条 · 「计组作业到底交不交」]
    [群接龙] 周五聚餐报名 · 7 人已接龙  [投票] 周末去哪 · 12 人已投 · 剩余 2 天

### 4.8 通话（穷举）

    [语音通话 03:12 · 已结束]   [语音通话 · 未接听]   [语音通话 · 对方已取消]
    [视频通话 · 对方忙线]       [视频通话 · 已拒接]   [语音通话 · 通话中断]
    [语音通话 · 3 人 · 已结束]                       （群通话）

规则：通话只有在**结束时**落一行；进行中的通话不作为窗口行（平台在聊天流里也不显示"正在通话"）。

### 4.9 时间与分隔

- 每行带 `HH:MM`（24 小时制，本地时区）。
- 跨天插一行 `..系统 —— 2026-10-17 ——`。
- 同一天内不重复显示日期；同一分钟内的多条仍各带 `HH:MM`（平台如此）。
- 时间来自事件行（`occurred_at`），不读 now()。

### 4.10 撤回（原位替换）

- 那一行**原位**变成 `..我` / `..你` / `..名字` `撤回了一条消息`；原文不再出现在窗口里。
- 事件流里原文仍在（可追溯、可审计），窗口不显示。
- 被撤回的是媒体/卡片/钱：整行替换，不保留占位。
- 别人引用了被撤回的消息 → 引用块写 `该消息已撤回`（见 4.4.2 #39）。

### 4.11 异常与退化（穷举）

    09:06  鲸鲸      我马上到 [!发送失败]
    22:15  ..系统    消息已发出，但被对方拒收了

| 情形 | 写法 |
|---|---|
| 发送失败 | 行尾 `[!发送失败]`（正文/媒体都加在行尾） |
| 被对方拒收 | 单独一行 `..系统 消息已发出，但被对方拒收了` |
| 平台侧已删除 | 整行 `该消息已删除`（保留时间与作者列） |
| 未知消息类型 | `[未知内容]`（不猜、不加解释） |
| 系统行取不到主体名 | 主体写 `未知成员` |
| 媒体加载失败 | `[图片：加载失败]`（同构：视频/文件） |
| 引用内容取不到 | `该消息已不可见`（见 4.4.3） |

### 4.12 空正文 / 纯媒体 / 纯 emoji

- 只有媒体：只放占位，不加「（无正文）」这类解释——那是自然语言，不是平台内容。
- 纯 emoji：按正文原样显示（它属于文字）。
- 纯空白：`该消息为空`。
- 纯 @：`@李湛`，不补别的字。

## 7. 预算与逐出

三条同时约束（先到先逐）：

1. 条数：默认 40 条（DEFAULT_FULL）。
2. 时间：默认 2 小时；跨度过大时只保留近段，长尾靠引用副本，而不是无限扩窗。
3. 字符：渲染后字符上限，默认 3600（与现有 DEFAULT_BUDGET 一致）。

逐出只影响「看不看得见」，不影响事件流；被逐出的行仍可按需再取（例如用户追问「上面那句」）。引用块里的被引内容算在**当前行**的预算里，不额外占历史（所以引用副本能跨出窗口）。

## 8. 重建

窗口 = render(事件流后缀)，五步纯函数：

1. 取该会话可见类型的后缀，按 (occurred_at, sequence) 排序、按预算裁剪。
2. 补引用边（utterance_edges，只认平台给的 quote/qmsg；at_body 属标注层，不进窗口）。
3. 补媒体占位与描述（message_media + 标注层）。
4. 取显示名快照；必须来自事件行——靠名册现查会把改名后的名字涂到历史上。
5. 排版。

三前提：输入唯一（只吃事件流 + 标注层）、渲染纯函数、行内自带渲染所需的一切。

## 9. 不做清单（写下来防复发）

- 不判「在跟谁说」、不判「该不该开口」、不判语气/意图/噪声。
- 不做摘要、不压缩正文（第 1 节裁决 1）、不把推断写成「回 X」。
- 不读 now()、不访问网络、不查名册补名字。
- 不因为「下游要用」而往窗口里加字段。
- 不造引用、不猜未知类型、不给空正文加解释性文字、不合并「被引用 N 次」。

## 10. 未定项

- 温/冷窗口的缓存与回收策略（内存 vs 磁盘）。
- 标注层（图片/表情包描述）的 generation 字段与失效规则。
- 跨平台同一人（微信/QQ 同一个人）在窗口里是否统一显示名：不统一（平台显示什么就写什么），但下游实体层可合并。
- QQ 匿名消息被引用时，平台是否给「匿名」这个显示名（待实测核对）。
- 群通话超过 2 人时的平台原话（`3 人通话` / `语音通话 · 3 人`）待核对。
- 媒体「加载失败」的平台原话（微信实际显示可能是「图片已失效」）待核对。
