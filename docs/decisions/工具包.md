# 工具包（能力池 / 手）

> 依据：`output/3d/viewer_css.html` 里 `(950, 600)` 的线框立方体 + 清单板（贴图 `t_toolbox.png`），以及 `run_tool` 那条管子。
> 四问先答：**图上是哪块** = 判板右后方的立方体；**进来什么** = 判的一次调用（族 + 目标 + 参数 + 一句目的）；**出去什么** = 一段带来源与时间的文本（或「状态 + 证据」）；**职责** = 拿「本来不在这一屏里」的信息，或改变外部状态。

> **扩展声明（硬约定）**：加一个工具 = §7 表里加一行（另加一条注册声明 + 一个执行函数 + 一行量具 + 一个失败分支测试）。**本文档不因加工具而新增章节**，全文上限约 250 行；超了就说明该合并，或该拆出一个新族。

## 1. 图上位置

- 立方体：`makeWireCube(950, 600)`，与自我立方体 `(-950, 600)` 左右对称，中间夹着原点 `O`。
- 清单板：贴图 `t_toolbox.png`，挂在立方体上（板上写的三组就是 §7 的表）。
- 管子：`run_tool`（判 → 工具包）、`web_search`（工具包 → 外部世界竖板 `(1500, -600, 0)`）。
- **虚线 `read_screen / get_state / search_memory` 不是工具调用**：它们是判取三面读数的专用通道，由代码预取（见 §7 A 类）。

## 2. 契约层：三个动词，四个 effects

**这是本文档唯一不随工具变化的部分。** 所有工具都只是某个动词的一个实例。

| 动词 | 做什么 | 契约 | 是否要证据 |
|---|---|---|---|
| `observe` | 拿回信息（只读） | `observe(target, what, params) -> {content, source, at, truncated}` | 要 `source` |
| `act` | 改变外部状态 | `act(target, action, params) -> {status, evidence, reversible}` | 要 `evidence`（截图/日志/回执号） |
| `schedule` | 把动作推迟 | `schedule(when, what, params) -> {task_id, next_fire_at}` | 要 `task_id` |

四个 `effects`（风险类别，决定放行条件）：

| effects | 含义 | 例子 |
|---|---|---|
| `read` | 只读，无副作用 | 读附件、搜网、看图、读屏幕 |
| `write_local` | 改本机文件/数据库 | 写文件、改配置 |
| `ui_control` | 操作界面（点/填/拖） | 点按钮、填表、浏览器自动化 |
| `external_send` | 对外发东西 | 发消息、发邮件 —— **永不经工具包，只走出口** |

**「操作别的软件」不是新动词**：它是 `act` + `ui_control`（或 `act` + `write_local`）。

## 3. 注册协议（七个字段）

```yaml
family:    observe | act | schedule
effects:   read | write_local | ui_control | external_send
args:      参数 schema（声明式，模型只能填，不能造）
returns:   返回 schema
perms:     允许谁调 / target 白名单
limits:    超时、每回合次数
idempotent: 能否安全重放
owner:     谁维护、出问题找谁
```

- **模型不能发明工具名或参数**：不在注册表里的调用直接 `blocked(reason=unknown_tool)`；
- 注册表默认 `disabled`，由人启用（见 §6）；
- 没有 `args` schema 的工具不许上线（否则模型输入不可校验）。

## 4. 策略矩阵（effects × 放行）

| effects | 放行条件 | 默认档 |
|---|---|---|
| `read` | 有 `source`、命中超时/配额限制即拒 | **enabled** |
| `write_local` | 路径白名单；首次上线先 shadow | shadow |
| `ui_control` | 前台可见 + 每回合 ≤1 次 + 必须回证据 | shadow |

### 4.1 前台可见怎么判（`ui_control`）

三条**同时成立**才算「前台可见」：

1. **进程在前台**：目标窗口属于当前前台窗口的进程（`GetForegroundWindow` → `GetWindowThreadProcessId`，与目标 hwnd 的 pid 相同）；浏览器后台标签不算；
2. **标题匹配**：目标窗口标题包含注册项声明的 `window_title` 子串（大小写不敏感）；匹配不上就 `ui_blocked`，不许「猜一个窗口点下去」；
3. **截图可验**：动作前后各截一张，目标区域必须有 ≥100 个非背景像素的变化；截图落 `data/evidence/<turn_id>_<n>.png`，路径写进回执。

另外三条硬规矩：

- **每回合 ≤1 次**；同一轮失败过一次，本轮不再试；
- **shadow 期只判定不执行**，只记 `ui_would_run{target, action, checks}`；启用需人工 + 应用白名单（按进程名）；
- **抢焦点要认**：执行前若前台不是允许碰的窗口，返回 `status:"needs_focus"` 给判，由判决定要不要抢（**默认不抢**）。
| `external_send` | 一律拒绝（走出口注册表） | blocked |

这样即使将来冒出 20 个没见过的工具，**风险类别只有四类，策略不用重写**。

## 5. 注入与上限：系统 N 个，本轮 ≤6 个

| 概念 | 含义 |
|---|---|
| 注册工具总数 | 不设上限（可以几十个） |
| **本轮注入 prompt 的工具** | **≤6 个**，每个 schema 约 40–60 token |
| 注入策略 | 默认 3 个 `observe` + 1–2 个已启用的 `act` |
| 开启一个族 | **由人**在会话级别开，不由模型自己开 |
| 参数个数 | >4 个就拆成两个语义清晰的动作，不继续加 |

**「上限 6」约束的是注入视图，不是系统能力**。这是这份设计能扩展的前提。

**两句实话（2026-10-23 核）**：

- 封顶的只有**提示词清单**：`core/tools/registry.py::TOOL_IN_PROMPT_MAX = 6`，渲染在
  `core/tools/prompt.py::render_tool_block`，超了**整行丢弃、绝不截半行**；注册总数不设上限。
  这条规则的来由是 2026-10-21 的真机教训（`send_plan` 因注册顺序排第 7 被截掉）。
- 给模型的 **function schemas 目前不封顶**：`agents/conversational.py:2828-2833` 是全量
  `llm.chat_tools(tools=tool_schemas, …)`。所以一回合的真实 token 成本由 schemas 决定，
  不是那 ≤6 行清单；量具「注入超限次数（清单 >6）」量的是清单，不是 schemas。

### 5.1 谁把清单接进 prompt（实现补注）

`ToolRegistry.select_for_prompt(limit=6)` 只回答「该给哪 6 个」；把 schema 变成文字的是
`core/tools/prompt.py`：

| 项 | 值 |
|---|---|
| 抬头 / 收尾 | `[本轮可用的工具]` / 「工具名 + 一句要什么；一回合最多两件；失败就说没查到，不许编」 |
| 每个工具 | 一行 `- name(参数) → 返回什么`，**单行 ≤120 字**（≈60 token） |
| 整段 | **≤700 字**（≈350 token）；放不下就**整行丢弃**，绝不截半行 |
| 参数 | ≤4 个；超了渲染成 `…`（与 §5「>4 个就拆」同口径） |
| 空 | 没有启用的工具 / 没有注册表 → **空串**，不注入空块 |

开关 `TOOL_PACKAGE_PROMPT`（三态，默认 `off`）：`off` 既有提示词逐字不变；`shadow` 只记一行
`tool_prompt_shadow chars=… lines=…`；`on` 才追加。为什么必须能退回——现在工具是模型自己编名字，
换成清单会改变行为，这属于**行为改动**，不是渲染改动（`agents/conversational.py::_tool_specs_block`）。

## 6. 上线流程（防她乱来）

```
写实现 → 注册声明（默认 disabled）
  → shadow：只记录「如果调用了会怎样」，不执行
    → 人工试用（指定会话 / 指定 target）
      → 启用（进入注入池）
```

先例：微信发送就是这条路（dry-run → 白名单 → 真发）。

1. **提示词清单 ≤6 个**（`core/tools/registry.py::TOOL_IN_PROMPT_MAX = 6`，渲染在 `core/tools/prompt.py::render_tool_block`，超了整行丢弃）；注册总数不设上限。要加工具先问「它该不该进清单」——降级进 A 类预取不占名额；
2. 参数 **>4 个**就拆成两个语义清晰的动作，不继续堆；
3. `external_send` 一律不进这张表（走出口注册表）；
4. 每个工具必须有一条**失败分支测试**（上表失败码至少覆盖一个）；
5. 表里加行的同时，§15 量具里加一行、变更记录加一行。

## 8. 三条纪律

1. **工具只「取回来 / 做掉」，不判断要不要说**——判断在判板；
2. 每条返回必须带 `source` 与 `at`，缺一个即视为失败（不能当证据用）；
3. 工具**不写原文、不改账本**；它的产物落在附件表或临时缓存里，可丢可重建。

## 9. 输入从哪来 / 输出到哪去

**输入三条**

| 来源 | 内容 |
|---|---|
| 判的一次调用 | 族（observe/act/schedule）+ 目标 + 参数 + 一句目的 |
| A 类预取 | 代码在组 prompt 时已经放进去的三条读数（工具本身看不到） |
| 策略层 | 本回合次数上限、超时、target 白名单、effects 放行档 |

**输出四条**

| 去处 | 内容 |
|---|---|
| 回判（同一回合的下一轮） | 一段文本（≤600 字，超出标 `truncated`） |
| 附件/抓取缓存 | 正文抽取结果、PDF 转出的文件行（不占 prompt） |
| 状态 + 证据（仅 `act`） | `status` + 截图/日志/回执号 |
| 留痕 | 失败码与耗时（**只记事实，不写编造内容**） |

路径：判 → `run_tool` → 工具包 →（observe）外部世界 / 附件 → 回判；（act）本机或界面 → 证据回判。
**归属**：工具产物不进账本——账本只记「事件」，抓取/附件内容在独立表，可丢可重建。

## 10. 有界

- 每回合 **≤2 次**工具调用（含失败）；
- 一件事（job）的**任务累计 ≤12 次**（跨回合累加，见 `办_在手的事.md` §9）；回合上限与任务上限同时生效；
- 超时：`observe` 8 秒 / `act` 20 秒（超时即返回 `timeout`，最多重试 1 次）；
- 注入清单（**提示词清单**）**≤6 个**工具；给模型的 function schemas 目前不封顶（`agents/conversational.py:2828`），所以「≤6」不能拿来估 token；
- 同一 URL / 同一附件同回合不重复取（去重键：规范化 URL / 附件 id）；
- 进 prompt 的工具返回合计 **≤600 字**。

## 11. 失败与「没查到」不是一回事

| 情况 | 返回 | 判该怎么用 |
|---|---|---|
| 网络失败 / 超时 | `error=timeout` | 可以说「现在查不了」，**不许**编内容 |
| 查到了但为空 | `ok, results=[]` | 说「没搜到」，**不许**拿最像的顶 |
| 部分失败 | `ok, partial=true` + 失败原因 | 用到的部分标来源，并说明缺口 |

## 12. 大小与预算

- 提示词清单（≤6 行）≈ **300 token**；**function schemas 全量给，不在这 300 里**——估成本要按注册面算；
- 单次返回进 prompt ≤600 字；
- 工具轮总预算 **1024 字**（`YINYUE_TOOL_LOOP_BUDGET_CHARS` 可调，下限 200）：超了把**早前**轮压成
  `[早前工具轮·摘要]`（调了什么 → 拿到什么，含关键参数），**最近一轮永远原样**——理由是
  「宁可留一句查过什么，也不让她原地重查」。旧 `_trim_tool_messages`（24000 字）降为兜底；
- 每回合最多 2 次 → 最坏 1,200 字 ≈ 600 token；
- 任务累计上限 12 次 → 单件事最坏 7,200 字 ≈ 3,600 token，摊到多个回合，不在一回合里付；
- 工具产物落库不占 prompt；附件正文只在被 `read_attachment` 时才进。

## 13. 边界（明确不管）

- 不管「要不要说」——那是判板；
- 不管「怎么说」——那是出口与生成；
- 不管记忆写入——只取回，写入由「记」负责；
- 不做主动轮询——没有判的调用就没有工具动作；
- 不做多步规划——一次调用一个动作，要串行就分多轮（仍受 ≤2 次限制）；
- 不管凭据管理——密钥在 `.env` / 凭据表里，工具只按名字引用。

## 14. 意义

- 让她能「去查」而不是「凭印象说」：**可指回的来源是唯一硬防编造手段**；
- 把「这屏里没有的东西」变成可达：搜网 / 抓取 / 读附件 / 看图，覆盖四类外部信息；
- effects 分级让将来「操作电脑软件」能接进来而不用重写策略。

## 15. 量具

1. 每回合工具调用次数分布（p50 / p90；**>2 的比例必须为 0**）；
2. 空结果率（`ok` 且为空 ÷ 总调用）；
3. 失败码分布（`timeout` / `http_4xx` / `not_extractable` / `rate_limited`）；
4. 结果被引用率（判的 `basis` 里引用了工具结果的回合占比）；
5. **编造率**（引用了工具结果但内容不在返回里）——目标 0；
6. `act` 类证据缺失率——必须 0；
7. 注入超限次数（清单 >6 个）——必须 0；
8. 平均耗时（`observe` / `act` 分开统计，p90 对齐 §10 超时）。

## 16. 不做

- 不做工具市场 / 插件热加载——先注册再上线；
- 不做「模型自己写脚本并执行」——远期另议，必须有沙箱 + 人工启用；
- 不做「自动重试到成功」——最多 1 次；
- 不做工具结果进账本。

| 5 | 多工具能否并行 | **保持串行**（≤2 次）。并行会让预算、回执、失败归因同时变复杂，而延迟差对聊天场景不关键 |

## 17.1 装填：谁把工具接上（实现补注）

契约（七字段 / 四 effects / 三动词）和实现（`agents/tools/*.py`，异步、面向模型）不是一种形状，
中间必须有一层**装填**，否则「在手的事」永远停在 `no_executor`。这一层是 `core/tools/builtin.py`：

| 工具 | family | effects | 谁提供实现 | 默认 |
|---|---|---|---|---|
| `web_search` | web | read | 旧 `WebSearchTool`（独立线程跑协程 + 硬超时） | 启用 |
| `fetch_url` | web | read | 旧 `FetchUrlTool` | 启用 |
| `gui_snapshot` | gui | read | `core/execution/gui/cdp.py::CdpReader`（只读，一次点击都没有；`GUI_CHANNEL` 关着时返回 `ui_blocked`） | 启用 |
| `get_current_time` | system | read | 本地 `datetime.now()` | 启用 |
| `write_note` | file | write_local | 本地写 `data/workspace/notes/` | 登记，**能否动手另有闸** |

三条必须说清的事：

1. **`enable()` 只解决「可见」，不解决「可动手」**。写工具在启动时装上（否则一件事没有手），
   但写步要跑起来必须先过 job 层那道闸：`advance()` 里 `allow_effects` 只放 `read`，
   写步停在 `need_approval`，等私聊本人一句「可以」落一行 `Approval` 才解冻。
2. **`external_send` 一个都不许登记**。`ToolRegistry.enable()` 见到它就返回
   `external_send_via_exit`——想对别人说话只有出口注册表一条路（R3）。
3. **同步桥不许把异常冒上去**：协程扔进独立线程跑（本进程可能已经在事件循环里），
   超时转成 `status="timeout"` 的 `ToolResult`。「查不了」与「没查到」仍然是两件事。

量具（E3 起算）：`unknown_tool` 次数（判点了不存在的工具）、`not_enabled` 次数（装了没开）、
写工具的 `no_change` 比例（见 `办_在手的事.md` §17.2）。

## 17.2 声明式工具：加一个能力 = 加一个文件（实现补注）

`configs/tools/*.yaml` 里的每一个文件，就是一条 `ToolSpec`。代码在 `core/tools/declarative.py`，
总闸是 `DECLARED_TOOLS`（三态，默认 `off`）。

**一个文件长什么样**（`configs/tools/example.yaml` 是唯一模板）：

```yaml
name: demo_weather           # 工具名，也是 prompt 里那个名字
family: web                  # 与手写工具同一个分类字段
effects: [read]              # 只许 read / write_local；external_send、ui_control 一律拒
args:                        # 参数名 → 类型（同 ToolSpec.args）
  city: str
returns: 该城市未来一天的天气摘要（纯文本）
allow_hosts: [example.com]   # 主机白名单；URL 的 host 必须在名单里（子域算命中）
limits:
  timeout_s: 5               # >10 会被拒
  max_chars: 800             # >4000 会被拒
http:
  method: GET                # 只许 GET；POST/PUT/PATCH/DELETE 会被拒
  url: https://example.com/weather?city={city}   # 占位符个数有上限
enabled: false               # 由人改 true
```

**三条纪律**

1. **两道闸同时成立才启用**：文件里写 `enabled: true`，**并且**调用点 `bind_declared(enable=True)`。
   默认 `enable=False`，所以「把 yaml 丢进目录」本身不会启用任何东西。
2. **加载失败只留痕、不阻断**：坏文件打 `declared_tool_rejected file=… reason=…`，
   `bootstrap()` 永远能起来。理由：一个写错的 YAML 不该让整个常驻进程死了。
3. **permission 不在文件里写**：`effects` 就是权限；`external_send` 与 `ui_control` 连写都会在解析时被拒——
   那两类动作只能走出口注册表与 `core/execution/gui/`。

**它解决什么**：以前「加一个只会 GET 的查询类工具」要改 `core/tools/builtin.py`、跑一遍门禁；
现在是加一个 yaml。「能力面」的横向扩展成本从「一次提交」降到「一个文件」。

**它不解决什么**：不会写代码的工具做不了（要逻辑、要分页、要多步），也不会放开写动作与外部发送。
量具：声明被拒率、声明工具的失败码分布、以及一条硬指标——**「声明与实现不符」事故 0 次**。

## 17.3 MCP：把外部服务器当成只读工具源（实现补注）

外部 MCP 服务器（自己会 spawn 子进程）能声明一堆工具。我们只拿它当**只读**用：
`core/execution/mcp.py` 把 `tools/list` 的每一项登记成 `effects={read}` 的 `ToolSpec`，
写动作与外部发送永远不经过 MCP（那两类只能走出口注册表与 `core/execution/gui/`）。

配置在 `configs/mcp/*.yaml`（模板 `example.yaml`），一台上限三项：

| 字段 | 含义 |
|---|---|
| `command` | 参数数组，`shell=False`；写 `&&` 不会被解释 |
| `timeout_s` | 每次请求上限（默认 8 秒，与 `DEFAULT_TIMEOUT_S` 对齐） |
| `allow_tools` / `deny_tools` | fnmatch 模式；**deny 永远优先**，命中的连登记都不登记 |
| `enabled` | 文件里写 true **且** 调用点 `bind_servers(enable=True)` 才启用；登记后仍需 `registry.enable()` |

**失败三分类（不许混）**：进程起不来 / 协议错 → `McpError`，handler 给 `status="timeout"`（查不了）；
对方 `isError: true` → `status="failed"`（调用了，对方说不行）；正文为空 → `no_result`（调用了，没有东西）。
为此 §6 的失败码新增一个封闭值 `failed`。

**有界**：服务器 ≤3 台、每台 ≤20 个工具、正文 ≤4000 字、每次请求 ≤8 秒、`stderr` 直接丢掉
（否则服务器写满管道会把它自己卡死）。

**它不解决什么**：不替服务器做鉴权、不管它内部干什么、也不许它写我们的账本——它只是一个「读」的来源。

## 17.4 回合内工具调用闭环：请求在判、执行在代码、结果进下一轮（实现补注）

前面几节讲的是「工具怎么被登记、怎么被放行」。这一节讲**谁去调它**——在这之前，
`check_call(` 只出现在 `core/tools/registry.py` 里，工具清单能进 prompt 了，
但没有任何代码去解析判说的「用 web_search」并真的调一次。这一节补的就是这一步。

**形状**（`core/tools/turnloop.py`，总闸 `TOOL_LOOP` 三态默认 off）：

| 步骤 | 做什么 | 不许做什么 |
|---|---|---|
| 解析 | 从判决载荷取 `tools`：每条 `{name, purpose, args?}`，最多 2 条；缺 `purpose` / `purpose` >20 字 / `args` 不是映射 → **整条丢掉** | 不猜名字、不补默认参数 |
| 执行 | 逐个 `registry.observe(target="", what=purpose, params={tool, turn_id, **args})`；参数多出来就是 `bad_args`，未注册就是 `unknown_tool` | 不自己调 `check_call`（`observe` 内部只记一次账），不并发 |
| 结果 | 排成 `[工具结果]` 块（单条正文 ≤600 字、整块 ≤1200 字、**放不下整行丢弃**），存进「下一轮信箱」 | 不回流到本轮、不改写判的 `decision` |
| 留痕 | `core/terminal/turn_trace.py::record_full_detail(detail={"tools": [{name,status,purpose}]})`——**只写完整留痕，不写判决行**（判决行每回合一行是量具分母） | 不在 `TOOL_TRACE=off` 时写 |

**为什么是「下一轮」而不是「回合内多轮」**：判无状态 + 一回合一次模型点（R2），
工具结果回来时本轮已经定稿。做成回合内循环就等于给判加了一个隐式状态机。
所以宁可慢一回合：这一轮说「我去查」，下一轮带着结果说话。

**量具**：调用次数 >2 的比例恒 0（代码截断）/ 未注册工具率 / `bad_args` 率 /
结果被引用率（下一条 `deliver.basis` 里出现工具 id）/ 编造率 0（结果为空时必须说没查到）。

**已知边界**：信箱是**进程内单格**（`_PENDING`，按会话存一块，取一次即消失；没有 `chat_id`
时用最近一次判决的会话兜底）。重启即丢——它服务的是「下一轮」，不是「永久记忆」；
要永久就写完整留痕，那一份在盘上。

## 17.5 清单要写「什么时候用它」，失败要写「下一步」

模型下一轮唯一读得到的是两段文字：**工具清单**与**上一次的工具结果**。这两段写得像
数据库字段，它就只能猜；写得像人话，它就能改。

### 一、清单行加 `purpose`

`ToolSpec.purpose`（一句"什么时候用它"，≤40 字）由 `core/tools/prompt.py::render_spec_line`
追加在行尾：

```
- send_plan(target, text) → 开出来的那件事（停在等主人批准，一个字节都没发） ｜要真办事（发消息/动手）时用：开一件事等主人批准
```

为什么不是"把 returns 写长一点"：`returns` 回答"给我什么"，`purpose` 回答"**我什么时候该想起它**"。
10-21 真机里她说"我没有往群里发消息的工具"，缺的正是后者。

### 二、失败行附「下一步」

`core/tools/registry.py::NEXT_STEP_HINTS`（码 → 一句话）由 `core/tools/turnloop.py::
render_results` 在**失败行**追加：

```
- gui_click(点一下): no_target（下一步：先确认目标名字对不对（用 gui_state 看一眼当前是什么），再换 target 重试）
```

四条纪律：

1. **只在失败时附**：成功行加提示会把注意力从结果挪到建议上；
2. **说动作不说码**：`no_target` 只是索引，模型需要的是"换 target 重试"；
3. **不认识的码不编**（`hint_for` 返空串）——编出来的建议比没有建议更糟；
4. **提示要短**：一行里已经有一个状态码，再加三十字就挤爆（`RESULTS_BLOCK_MAX_CHARS`）。

钉住：`tests/test_tool_purpose_and_hints.py`（10 个规格都有 purpose 且 ≤40 字、清单行带
`｜`、失败行有「下一步」而成功行没有、`ok`/空码/未知码不给提示）。
