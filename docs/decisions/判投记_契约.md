# 判 / 投 / 记 · 契约（v0.9）

> 本文是**唯一事实源**：输出结构、字段名、留痕字段、量具阈值只在这里定义一次。块文档 `判投记.md` 只写语义与边界。

> 状态：设计稿（2026-10-19）。只做设计，不实现。
> 这一块是整个系统里**唯一有模型的地方**；其它框都是可数、可重算、可对账的。

## 0. 一句话

读三面（世界 / 自我 / 查询结果）→ 先复述 → 决定开不开口 → 投（说与做都是投递，不补 @）→ 记（0~3 条）。
**每条结论都要能指回原文；指不到就弃权。**

## 1. 输入（六样，前两样必填；后四样默认空 / 默认给）

| # | 输入 | 是否必填 | 形状 | 预算 |
|---|---|---|---|---|
| 1 | 世界面 | **必填** | 这一屏的渲染文本（平台会显示的东西 + 旁注） | 40 条 / 2 小时 / 3600 字 |
| 2 | 自我 | **必填** | 人设约束（**全量**，三层里唯一进 prompt 的）/ 情绪与态度**不预注入**，改由工具拉（`read_emotion` / `get_stance_cards`，2026-10-23 `0b64198`） | ≤ 200 字（人设部分） |
| 3 | 查询结果 | **可空（默认空）** | 推送侧给的是**索引**（≤6 条 key，`[事件记忆·索引]`）；正文按 key 用 `read_memory` 取，带出处 | ≤ 6 条索引 / 单次正文 ≤4000 字 |
| 4 | 工具结果 | **可空（默认空）** | 搜网 / 读附件 / 再检索，带出处 | ≤ 2 次 |
| 5 | 限流读数 | **默认给**（不是可空） | 一行事实：「本群最近一次我发言在 40 秒前」「本回合被点名」「本空间私聊无限制」 | ≤ 40 字 |
| 6 | 在手的事读数 | **可空（默认空）** | 每件一行：`job_id · 目标 · 到第几步 · 在等什么`，带「已问过 / 已确认」清单 | ≤ 3 条 / 每条 ≤ 60 字 |

槽位 3/4 填不填，只有一个判据（**由代码算，不靠模型自评**）：

```
unresolved = 这一屏里出现的指代/符号 − 屏内能解析到的对象
unresolved 为空  → 不查（0 条）
unresolved 非空  → 只查这几样，≤ 2 条
```

- **默认不查**：`≤ 2 条` 是上限不是预期；预期是 0 条。
- 若发现「大多数回合都要查」，那是世界面太小/太旧（先修窗口），不是该多查。实测反例：往注入里多塞条目会把本来答对的挤出去（端到端 exact 83.3% → 66.7%）。
- 工具清单（schema）随 prompt 一起给，但**只给「能请求什么」，执行永远在代码侧**；模型请求、代码执行、结果再回灌。

**关于第 6 样（在手的事读数）**：只有存在 `job` 时才给，且只给**授权通道里**的那几件；它是判唯一的跨回合连续性（判无状态）。读数里必须带「已问过 / 已确认」，否则会重复提问（量具：重复提问率 ≤10%）。细则见 `办_在手的事.md`。

**关于第 5 样（限流读数）**：冷却/频率**不进出口**（出口拦 = 她想好的话被掐掉且她不知道）。代码只报事实，判自己决定要不要说。这样「她节制」是她的判断，而不是系统的静默丢弃。

不进来：全量账本、索引内部结构、别的会话、任何「推断出的关系」。

## 2. 输出契约（三必填 + 三条件；不设 `gap` 字段）

必填（每回合都要显式给，沉默/弃权也不例外，允许给空）：

```
decision: respond | ask | silent | abstain
deliver:  [{ kind, text?, file?, target?, basis: [行号 / 记忆 id / 工具 id] }]   0~2 条
basis:    [行号 / 记忆 id / 工具 id]   支撑 decision 的依据
```

条件（按 `decision` 决定出不出现）：

```
reading:   一句复述——这一屏在发生什么、谁可能在等谁       仅 respond / ask
open_loop: { want, have, missing, next, due? }             仅当有未结事，≤1 条
memory:    [{ slot, subject, content, quote }]  0~3 条          可空
plan:      { job_id?, goal, steps: [{n, action, effects, safe_point}], awaiting }
           仅当她在办一件事（推进或新开），≤1 次
tools:     [{ name, purpose, args? }]  0~2 条              可空
```


- **`tools` 是「请求」，不是「结果」**：模型只写「要哪个工具、为什么（`purpose` ≤20 字）」，
  执行永远在代码侧（`core/tools/turnloop.py`），一回合最多两条、含失败；结果**不进本轮**——
  判无状态、一回合只有一次模型点（R2），所以工具结果进**下一轮**提示词与完整留痕的 `tools`
  字段（`判投记_契约.md` §8.1）。`purpose` 必填是因为「该查没查」拿它当分母。
- **`plan` 不是执行**：它只写「下一步要做什么、什么时候必须停下来等人」；真正发出去必须经出口，且花钱 / 不可逆 / 涉隐私的步骤必须带 `approval`（谁、何时、批了哪个 `action_hash`、哪个通道）。
- **不设 `gap` 字段**：缺什么由**工具调用**表达（调 `search_memory` / `fetch_url` / `read_attachment` 就是缺口），不另造一套缺口分类。
- `reading` 不是给人看的散文，是**自查**：写不出复述，说明没看懂，直接 `abstain`。
- `decision` 只是一个词，**不允许**输出"半接半不接"；`respond / ask` ⇒ `deliver` 非空，`silent / abstain` ⇒ `deliver` 必须为空（代码校验，模型不能自圆其说）。
- `basis` 里每一项都必须能在本次输入里找到；找不到的项要删掉，删完为空则 `abstain`。
- `memory` 允许 0 条；**禁止**为了"有输出"而记。
- **两段纪律，缺一不可**：判侧 `quote` 必须是窗口里 ≥4 字的原话、逐字照抄，抄不准就别提这一条；落地侧 `core/routing/memory_notes.py:47 quote_evidence()` 拿这句话去窗口行里逐字比对，命中才换成真实 `event_id`，一条都不中就整条丢弃（只记 `unverified` 进 `memory_notes_staged` / `memory_notes_shadow` 日志）。
- 所以：**判说了便签 ≠ 一定进候选区**。

## 3. 判的五问（不是分类器）

1. 有人在等我吗（被 @ / 被点名 / 刚有人问完没人接）
2. 话题连着吗（这一屏在聊的事，我插得上吗）
3. 我有具体一句可说吗（不是"嗯""确实"这种填充）
4. 我能参与吗（线下事、要身体、要付钱 → 不能）
5. 代价值得吗（她刚连发过 / 别人正在互聊 / 说了会被当 AI）

**五问必须由模型读原文后自己答，不许做成查表或阈值。**
答不上来就 `abstain`（弃权）——弃权不是失败，是正确输出之一。

## 4. 弃权（abstain）与"不知道"

| 情形 | 正确输出 |
|---|---|
| 指代解不出（「那个」没有先行词） | 先查（≤2 条，见 §1 的 unresolved 判据）；查不到 → `abstain`，或说「没翻到」 |
| 情绪/态度读数缺失 | **整行不写**（新口径没有「中性值」可假设；宁缺勿造） |
| 自我冲突（想接 vs 人设禁止） | 人设优先，记一条日志 |
| 两个解读都成立 | 选依据更多的一个；分不出 → `abstain` |

不许自评"有把握"——**有依据可判定，有把握不可判定**。只要求写 `basis`。

## 5. 投（说与做都是投递）

`deliver` 是**开放列表**：`kind` 是字符串标识，能用哪些由**出口注册表**决定；模型只能从注册表给它的清单里选，写了未注册的 `kind` 一律拒（并回答"这件事我现在做不到"），**不许编造能力**。

| kind | 形态 | 副作用 | 闸门 |
|---|---|---|---|
| `say` | 文本（含 @） | 低 | 频率 |
| `sticker` | 表情包 | 低 | 白名单 |
| `file` | 文件 | 中 | 大小 / 类型 |
| `reminder` | 定时提醒 | 中 | — |
| …（日历 / 邮件 / 浏览器等按需注册） | | | 按注册表声明 |

同轮规则：

- 最多 **2 条**，其中 `say` 最多 **1 条**（两条文本会自相矛盾）；
- `say + 动作` 时，`say` 是**伴随语**（≤40 字），不带自己的 @，@ 由动作的 `target` 统一定；
- `say` 与动作**必须指向同一件事**，不一致要拦；
- 结果按条回写 `result: [{ok, reason?}]`，一条成功不等于全成功。

其它纪律：

- **不补 @**：只有"明确只对一个人说"时才 @；多人/不确定 → 不 @。
- 说过的内容不再用元陈述重复（禁止「这个我刚说过啦」这类模板）。
- 长度与温度由人设 + 态度算出，不由"回复意图"标签决定。
- 引用原文时贴出处（第几行），不改写对方原话。

## 6. 记

只记三类：

1. **未来会被指代的名词**（人、物、事、别名）
2. **未兑现的承诺**（"我明天提醒你"）
3. **被纠正过的事实**（"不是 A，是 B"，并记纠正者）

写入的是**候选区**（`memory_proposals`，`status=pending`），不是常驻；**当前只有一扇门**：人批准（`core/quality/memory_proposals.py:563 approve() → core.context.person_notes.upsert_note`）。原设计的「候选区 TTL 7 天」与「她明说记住 / 同条 ≥3 次」两条门**未落地**——`core/constants.py:41 MEMORY_CANDIDATE_TTL_DAYS = 7` 是死常量（全仓零引用），`REPEAT_MIN_OCCURRENCES = 3`（`:51`）是提案侧判 `habit` 的门槛，不是转正闸。

### 6.1 未结事（open loop）

「记」里最容易被漏掉的一类：**开了头但没结束的事**（等回复、等文件、答应了要提醒）。

```
open_loop: { want, have, missing, next, due? }
```

- 只记**当前仍然有效**的；同时不超过 **3 条**，超了先关最旧的。
- `missing` 必须是一句自然语言（"还差他确认时间"），**不许**写成分类标签（`file` / `person`）。
- 关闭只有两种：目标达成（追加 `closed` + 证据行号）或过期（`due` 到了且无进展）。
- 读的时候按 `due` 升序，最多带 2 条进提示词，不带全文。

## 7. 两条回路

| 回路 | 触发 | 回写到 |
|---|---|---|
| 短环 | 说完之后，有无人接、有无被 @、有无负向词 | 追加一条事实/事件（`自我立方体.md` §4.6.3）→ 影响开口阈值 |
| 长环 | 记的条目被再次翻到 / 被证伪 | 记忆候选区转正或作废 |

**后果用行为信号判，不用 LLM 判**（有无后续入站、有无 @ 她、有无"人机/别说了"类词）。

## 8. 量具（每条约束配一个数）

| 约束 | 指标 | 目标 |
|---|---|---|
| 结论要能指回 | basis 覆盖率 | ≥ 90% |
| 该弃权就弃权 | 弃权率 | 5~15% |
| 该查就查 | 该翻没翻率（有未解符号却未查） | ≤ 10% |
| 不编 | 无依据断言率 | ≤ 5% |
| 不重复 | 重复开口率（同话题 10 分钟内二次开口） | ≤ 10% |
| @ 要对 | @ 命中率（@ 的人确实是该回的人） | ≥ 90% |

### 8.1 留痕（两行制：判决行每回合一行 / 完整留痕只在开口·动手时）

**为什么分两种**：统计（开口率、弃权率）需要每回合都有；复查（她当时有没有看懂）只在真开口的回合才有意义。合成一张会让沉默回合塞满空字段，拆成两张又不会丢数。

| 行 | 何时写 | 字段 |
|---|---|---|
| **判决行** | 每回合（含 silent / abstain） | `turn_id` / `chat_id` / `ts` / `decision` / `basis`（可空） |
| **完整留痕** | 仅 `respond` / `ask` 或确有投递 | 下表全部字段 |

四条落地口径（v0.7，**已实现**：`core/terminal/turn_trace.py` + 迁移 63 + `scripts/report_turn_trace.py`）：

- **回合边界**：每条入站消息 + 每次群触发；`silent` / `abstain` 也写判决行；写入点是 decision 定稿后的**唯一收口**（`core/routing/turn_decision.py:80` 有 8 个 silent 出口，不许各写一遍）。
- **`basis` 格式**：可空 JSON 数组，元素 `<来源>#<行号>`（`w#3` / `m#2`）；为空**仅允许** silent / abstain；`basis_count` 只在报表里派生。
- **幂等**：每个 `turn_id` 一行（主键即 `UNIQUE(turn_id)`），重复写为 no-op。
- **三档语义**：off 不写 / shadow 写行并带 `mode` 列、不参与决策与出口 / on 写行并进验收报表；record 失败只 log，不抛、不回滚、不阻断。

完整留痕（append-only、只增不改）：

| 字段 | 例子 | 用途 |
|---|---|---|

> 留痕里的字段与模型输出的字段**不是同一套形状**：模型给 `MemoryNote`（slot/subject/content/quote），留痕只记条数（`memory_notes`）。
| `turn_id` / `chat_id` / `ts` | `t-17902` / `5793…` / `22:15:03` | 定位 |
| `reading` | 「P5问课表文件叫什么，鲸鲸刚答过第 8 周」 | 看懂没看懂（人工可判） |
| `decision` | `respond` / `ask` / `silent` / `abstain` | 判决留痕 |
| `deliver` | `[{kind: 'file', target: 'P5', basis: ['w#12']}]` | 说/做分别是什么（**内容不在这里**：文本看 `speech_ref`，动作结果看 `result`） |
| `result` | `[{ok: true}, {ok: false, reason: 'file too large'}]` | 投递回执（逐条） |
| `basis` | `["w#3", "m#2"]` = 世界面第 3 行 / 记忆第 2 条 | 断言可指回 |
| `speech_ref` | 账本行号（`sequence`），指向「她发出去的那条消息」 | **文本只在账本**，这里只存引用 |
| `speech_excerpt` | 可选，≤200 字审计副本，**必须标「以账本为准」** | 人工快速对照用，不作为事实来源 |
| `trimmed` | 被删掉的、指不回依据的句子 | 无依据断言率的分母 |
| `tools` | `[{name:"search_memory", q:"某市 银行", k:2}]` | 该翻没翻 |
| `memory_notes` | `2` | 写回审计（只记条数，不落便签正文） |
| `open_loop` | `{want:"…", have:"…", missing:"…", next:"…", due:"…"}` | 未结事的产生与关闭 |

五条纪律：

1. 留痕**只增不改**（与账本同一纪律）；
2. 留痕里**不存**生成的散文摘要（派生物，可重建）；
3. 留痕必须能由账本**重放**重建（同输入 → 同 reading / decision）；对不上就是第二真相；
4. **留痕不复制消息全文**：她说了什么，文本只在账本（`speech_ref` 指过去取）；留痕只存引用与判断。
   - 允许存 `speech_excerpt`（≤200 字）作为人工审计副本，但**必须标注「以账本为准」**；
   - 两者不一致时以账本为准，并记 `trace_ledger_mismatch` 告警（说明有人绕过同一写口写了两份）。
5. **沉默不写完整留痕**，但判决行必须写：没有判决行，开口率/弃权率就算不出来（这是不许省的唯一一行）。

用它加一个量具：

| 约束 | 指标 | 目标 |
|---|---|---|
| 真的看懂了 | `reading` 与人工标注的一致率 | ≥ 80%（每 50 条抽一次） |

## 9. 不做

- 不做"该不该查"的分类器（触发＝这句有未解符号）
- 不做"他在想什么"的推断层
- 不让模型自评把握、不给"半接半不接"
- 不把记忆全量常驻、不把索引给模型看
- 不在"投"这一层改判断（投只负责把判断变成字或动作）
- 不做任意软件操作：`shell.run` / 鼠标键盘 / 装软件永远不进注册表
- 管理型动作（加人 / 踢人 / 改备注 / 改群名）不属于"投递"，单列通道，现在不做

## 9.5 量具口径（两个数不是一回事）

| 名称 | 定义 | 分母 |
|---|---|---|
| 开口率 | (respond + ask) / 全部判决行 | 全部判决行 |
| 弃权率 | abstain / 全部判决行 | 全部判决行 |
| 沉默率 | silent / 全部判决行 | 全部判决行 |
| **覆盖率** | 有 basis 的开口回合 / 开口回合 | 开口回合 |
| **指回率** | 人工抽 50 条里 basis 能定位回原文行的比例 | 抽样 50 条 |

报表必须打印用的是哪个口径；两个数不许混用。
